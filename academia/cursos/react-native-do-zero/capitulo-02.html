A primeira interface própria

O aplicativo ganha sua própria interface

No capítulo anterior, o projeto deixou de ser apenas o exemplo original do Snack. A imagem da Santa Filomena Água & Gás já está no componente IdentidadeEmpresa, e o nome da empresa aparece na tela.

Candidato à aprovação pedagógica — etapas ainda serão testadas no Snack

ObservarAlterarCompararConsolidar
Retome sem repetir

1. Onde paramos

Não precisamos rever todos os códigos do capítulo anterior. Basta lembrar a pequena estrutura que já existe:

App.js components/ └── IdentidadeEmpresa.js assets/ └── santa-filomena.png

O App.js organiza a tela. O componente IdentidadeEmpresa já existe e, neste momento, apresenta a imagem da empresa.

Observe

2. Observe antes de mexer

Olhe a pré-visualização do aplicativo e tente identificar: o fundo, o nome da empresa, a área onde a imagem aparece e os espaços entre esses elementos.

A primeira pergunta é simples

O que podemos mudar primeiro para a tela começar a deixar de parecer o exemplo original?

Vamos começar pelo que envolve toda a interface: o fundo.

Programe e observe

3. Primeira mudança: o fundo

Abra o arquivo App.js. O arquivo inteiro aparece abaixo para você não precisar adivinhar onde está a alteração. Digite ou altere somente a linha destacada.

App.js — arquivo completo no estado atual
import * as React from 'react';
import { Text, View, StyleSheet } from 'react-native';
import Constants from 'expo-constants';
import { Card } from 'react-native-paper';

import IdentidadeEmpresa from './components/IdentidadeEmpresa';

export default function App() {
  return (
    <View style={styles.container}>
      <Text style={styles.paragraph}>
        Santa Filomena Água & Gás
      </Text>

      <Card>
        <IdentidadeEmpresa />
      </Card>
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    justifyContent: 'center',
    paddingTop: Constants.statusBarHeight,
    backgroundColor: '#eef3f7',
    padding: 8,
  },

  paragraph: {
    margin: 24,
    fontSize: 18,
    fontWeight: 'bold',
    textAlign: 'center',
  },
});

Linha que você deve digitar ou alterar nesta etapa

O que observar

A estrutura não mudou. O conteúdo também não. Apenas o fundo passou a ter outra aparência na pré-visualização, que é atualizada automaticamente pelo Snack.

Um estilo pode mudar a aparência de um componente sem mudar aquilo que ele contém.

Construa uma área própria

4. O conteúdo precisa de uma área própria

O fundo mudou, mas o conteúdo ainda está dentro do Card que veio no exemplo. Queremos começar a controlar essa área por conta própria.

Antes de digitar, apague a linha import { Card } from 'react-native-paper';. Depois, substituiremos o Card por uma View nossa.

No quadro abaixo, o arquivo inteiro já aparece no novo estado. Digite ou altere somente as linhas destacadas.

App.js — arquivo completo no novo estado
import * as React from 'react';
import { Text, View, StyleSheet } from 'react-native';
import Constants from 'expo-constants';

import IdentidadeEmpresa from './components/IdentidadeEmpresa';

export default function App() {
  return (
    <View style={styles.container}>
      <Text style={styles.paragraph}>
        Santa Filomena Água & Gás
      </Text>

      <View style={styles.cartao}>
        <IdentidadeEmpresa />
      </View>
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    justifyContent: 'center',
    paddingTop: Constants.statusBarHeight,
    backgroundColor: '#eef3f7',
    padding: 16,
  },

  paragraph: {
    margin: 24,
    fontSize: 18,
    fontWeight: 'bold',
    textAlign: 'center',
  },

  cartao: {
    backgroundColor: '#ffffff',
    borderRadius: 16,
    padding: 20,
  },
});

Linhas que você deve digitar ou ajustar nesta etapa

Observe a pré-visualização. A área branca do conteúdo agora foi construída por nós.

  • backgroundColor define o fundo do cartão;
  • borderRadius arredonda seus cantos;
  • padding cria espaço entre a borda e o conteúdo.

Essas propriedades aparecem porque nossa interface passou a precisar delas — não porque precisamos decorar uma lista.

Esse é o momento

O componente criado no capítulo anterior passa a ter uma função mais clara.

Organize visualmente

6. A identidade precisa de hierarquia visual

Nome e imagem já estão juntos. Agora precisamos organizar melhor essa apresentação: o nome deve ter uma área de destaque e a imagem precisa ocupar um espaço previsível.

Continue em components/IdentidadeEmpresa.js. Neste passo, o espaçamento do título passará a ser controlado pela nova barra superior; por isso, apague marginBottom: 16 do estilo titulo. O quadro abaixo já mostra o estado final. Digite ou ajuste somente as linhas destacadas.

IdentidadeEmpresa.js — arquivo completo no novo estado
import * as React from 'react';
import { View, Text, Image, StyleSheet } from 'react-native';

export default function IdentidadeEmpresa() {
  return (
    <View style={styles.identidade}>
      <View style={styles.barraSuperior}>
        <Text style={styles.titulo}>
          Santa Filomena Água & Gás
        </Text>
      </View>

      <Image
        source={require('../assets/santa-filomena.png')}
        style={styles.imagem}
        resizeMode="contain"
      />
    </View>
  );
}

const styles = StyleSheet.create({
  identidade: {
    alignItems: 'center',
  },

  barraSuperior: {
    width: '100%',
    backgroundColor: '#dbeafe',
    paddingVertical: 12,
    borderRadius: 12,
    marginBottom: 16,
  },

  titulo: {
    fontSize: 24,
    fontWeight: 'bold',
    textAlign: 'center',
  },

  imagem: {
    width: '100%',
    height: 180,
  },
});

Linhas que você deve digitar ou ajustar nesta etapa

Observe a pré-visualização e compare.

  • barraSuperior cria uma área própria para o nome;
  • width e height reservam o espaço da imagem;
  • resizeMode="contain" ajuda a manter a imagem inteira dentro desse espaço.

A estrutura agora pode ser lida assim:

IdentidadeEmpresa ├── barraSuperior │ └── titulo └── imagem

Compreenda o que já usou

12. O que aprendemos

Os conceitos deste capítulo surgiram porque a interface precisou deles:

  • View para criar áreas da interface;
  • Text para apresentar informações;
  • Image para apresentar a imagem;
  • StyleSheet para organizar estilos;
  • backgroundColor, padding e borderRadius para construir a área visual;
  • fontSize, fontWeight e textAlign para criar hierarquia;
  • width, height e resizeMode para controlar a imagem.

Também começamos a perceber que componentes podem reunir partes da interface que pertencem ao mesmo conjunto.

15. O próximo problema já apareceu

O aplicativo agora apresenta a empresa de maneira organizada. Mas um delivery precisa mostrar mais do que quem é a empresa.

Ele precisa apresentar aquilo que a empresa vende.

É dessa necessidade que nascerá o próximo capítulo.

Validação prática antes da aprovação comercial

Roteiro de teste preservado

Antes da edição comercial, o capítulo deve ser percorrido exatamente como um iniciante faria:

  1. confirmar o estado real herdado do Capítulo 1;
  2. alterar somente o fundo e conferir a pré-visualização;
  3. remover Card, criar a View cartao e conferir a pré-visualização;
  4. mover o título para IdentidadeEmpresa.js e conferir a pré-visualização;
  5. criar a hierarquia visual e conferir a pré-visualização;
  6. adicionar descrição e mensagem e conferir a pré-visualização;
  7. realizar o experimento de borderRadius e restaurar 16;
  8. conferir se cada quadro mostra o arquivo completo daquele momento;
  9. conferir se apenas as linhas que devem ser digitadas ou alteradas aparecem destacadas dentro do próprio quadro;
  10. produzir screenshots finais somente depois de o código real estar validado.

Se em qualquer etapa surgir a pergunta “onde exatamente eu mexo?”, a experiência ainda precisa voltar para a próxima espiral MbB.
