Construa e confira

2. O que realmente muda de um produto para outro?

Compare as duas chamadas. A estrutura é a mesma. O que muda são apenas as informações enviadas ao componente:

•nome do produto;

•descrição.

Isso sugere uma mudança de organização: antes de pedir ao aplicativo que repita automaticamente os cartões, precisamos ter um lugar único para guardar as informações dos produtos.

Primeiro organizamos os dados. Depois fazemos a interface usar esses dados.

Construa e confira

3. Uma lista para guardar os produtos

Em JavaScript, uma lista desse tipo pode ser representada por um array. Cada item da lista pode guardar as informações de um produto.

Também vamos dar a cada produto um id. Ele não aparece para o cliente; serve como uma identificação estável dentro do aplicativo.

Construa e confira

4. Leia a estrutura antes de continuar

O trecho novo pode ser lido assim:

produtos→→ é a lista inteira.→[ ... ]→→ indica que estamos guardando vários itens.→{ ... }→→ reúne as informações de um único produto.→id, nome e descricao→→ são informações pertencentes àquele produto.

Não precisamos transformar isso em uma aula abstrata sobre arrays e objetos. Aqui eles apareceram porque o projeto passou a precisar de uma forma organizada de representar vários produtos.

Construa e confira

5. A lista existe, mas ainda não controla a tela

Agora temos duas fontes para as mesmas informações: a lista produtos e as duas chamadas <Produto> escritas manualmente.

Isso cria a próxima necessidade:

Como fazer uma chamada <Produto> para cada item que já está dentro da lista?

É exatamente para esse tipo de situação que vamos usar map.

Construa e confira

6. Para cada produto, crie um Produto

O método map percorre os itens do array. Em nosso caso, para cada item chamado produto, ele produzirá um componente <Produto>.

components/Produtos.js - arquivo completo; substitua as duas chamadas manuais pelo bloco em negrito
import * as React from 'react';
import { View, Text, StyleSheet } from 'react-native';
import Produto from './Produto';

const produtos = [
  {
    id: 1,
    nome: 'Água mineral 20 L',
    descricao: 'Galão retornável de água mineral.',
  },
  {
    id: 2,
    nome: 'Gás 13 kg',
    descricao: 'Botijão residencial de 13 kg.',
  },
];
export default function Produtos() {
  return (
    <View style={styles.areaProdutos}>
      <Text style={styles.tituloSecao}>Produtos</Text>

      {produtos.map((produto) => (
        <Produto
          key={produto.id}
          nome={produto.nome}
          descricao={produto.descricao}
        />
      ))}
    </View>
  );
}
const styles = StyleSheet.create({
  areaProdutos: {
    marginTop: 24,
  },
  tituloSecao: {
    fontSize: 20,
    fontWeight: 'bold',
    marginBottom: 12,
  },
});

Linhas destacadas são as que entram ou mudam nesta etapa

Observe a pré-visualização. O resultado esperado continua sendo dois cartões: Água mineral 20 L e Gás 13 kg.

A diferença está no código: Produtos.js não precisa mais ter uma chamada escrita manualmente para cada item.

produtos.map(...) pode ser lido, neste momento, como: “para cada produto da lista, monte um componente Produto”.

Construa e confira

7. Por que existe key?

Dentro do map aparece uma linha nova:

key={produto.id}

Quando React cria vários componentes a partir de uma lista, ele precisa distinguir um item do outro. Por isso usamos o id estável de cada produto como key.

key não é uma informação mostrada na interface e também não precisa ser enviada como uma prop comum para Produto. Ela ajuda o React a acompanhar cada item da lista.

Construa e confira

10. O que mudou e o que permaneceu

Para o usuário, a tela continua apresentando os mesmos dois produtos. Para o código, porém, aconteceu uma mudança importante:

•os dados dos produtos agora ficam reunidos em uma lista;

•Produto continua responsável pela aparência de um cartão;

•Produtos percorre a lista e cria os cartões necessários;

•adicionar outro produto passa a significar adicionar outro item aos dados, e não copiar um bloco de interface.

Essa é uma evolução interna do sistema. Nem toda melhoria profissional precisa mudar imediatamente aquilo que o usuário vê.

Construa e confira

11. O que aprendemos

Os conceitos entraram porque a repetição criou uma necessidade real:

•array como uma lista de produtos;

•objeto para reunir id, nome e descrição de cada produto;

•map para percorrer a lista e produzir componentes;

•key para identificar cada item de forma estável.

Não precisamos dominar todas as possibilidades de arrays, objetos ou map agora. Precisamos compreender o suficiente para saber por que apareceram neste projeto.

Construa e confira

14. O próximo problema já apareceu

Agora o aplicativo consegue apresentar quantos produtos existirem na lista. Mas, para o cliente, todos eles ainda são apenas informações na tela.

O cliente já consegue ver os produtos. Mas ainda não consegue escolher nenhum deles.

A próxima evolução deverá nascer dessa limitação. Não vamos decidir antecipadamente se isso exigirá botão, estado, quantidade ou outra solução. Primeiro observaremos qual é a menor interação útil para o usuário.
