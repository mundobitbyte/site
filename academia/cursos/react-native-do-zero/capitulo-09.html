Valores do pedido

O pedido calcula seus valores

No capítulo anterior, cada item escolhido passou a carregar uma quantidade. O cliente já consegue dizer, por exemplo, que deseja 3 galões de água e 1 botijão de gás.

Mas ainda falta uma informação básica de qualquer pedido comercial: o aplicativo não mostra quanto custa cada produto nem quanto ficará o conjunto.

O pedido já sabe o que e quanto. Agora precisa saber quanto custa.

Construa e confira

1. Onde paramos

O catálogo possui id, nome e descrição. O estado do pedido guarda id e quantidade. Essa separação continua correta: o preço pertence ao produto; a quantidade pertence à escolha do cliente.

Produto → nome, descrição, preço→Item do pedido → id do produto, quantidade

Essa decisão evita copiar o preço para vários lugares sem necessidade.

Construa e confira

2. O preço precisa existir nos dados do produto

Antes de calcular qualquer coisa, cada produto precisa ter um valor numérico. Usaremos valores fictícios e fáceis de conferir: R$ 20,00 para a água e R$ 100,00 para o gás.

components/Produtos.js - arquivo completo; acrescente somente as linhas em negrito
import * as React from 'react';
import { View, Text, StyleSheet } from 'react-native';
import Produto from './Produto';

const produtos = [
  {
    id: 1,
    nome: 'Água mineral 20 L',
    descricao: 'Galão retornável de água mineral.',
    preco: 20,
  },
  {
    id: 2,
    nome: 'Gás 13 kg',
    descricao: 'Botijão residencial de 13 kg.',
    preco: 100,
  },
];
export default function Produtos() {
  const [itensPedido, setItensPedido] = React.useState([]);

  function alternarProduto(id) {
    const itemExistente = itensPedido.find(
      (item) => item.id === id
    );

    if (itemExistente) {
      const novaLista = itensPedido.filter(
        (item) => item.id !== id
      );
      setItensPedido(novaLista);
    } else {
      setItensPedido([
        ...itensPedido,
        { id: id, quantidade: 1 },
      ]);
    }
  }

  function aumentarQuantidade(id) {
    const novaLista = itensPedido.map((item) => {
      if (item.id === id) {
        return {
          ...item,
          quantidade: item.quantidade + 1,
        };
      }
      return item;
    });
    setItensPedido(novaLista);
  }
  function diminuirQuantidade(id) {
    const novaLista = itensPedido.map((item) => {
      if (item.id === id && item.quantidade > 1) {
        return {
          ...item,
          quantidade: item.quantidade - 1,
        };
      }
      return item;
    });
    setItensPedido(novaLista);
  }

  return (
    <View style={styles.areaProdutos}>
      <Text style={styles.tituloSecao}>Produtos</Text>
      <Text style={styles.resumo}>
        Tipos selecionados: {itensPedido.length}
      </Text>

      {produtos.map((produto) => {
        const itemPedido = itensPedido.find(
          (item) => item.id === produto.id
        );

        return (
          <Produto
            key={produto.id}
            nome={produto.nome}
            descricao={produto.descricao}
            preco={produto.preco}
            selecionado={itemPedido !== undefined}
            quantidade={itemPedido ? itemPedido.quantidade : 0}
            onAlternar={() => alternarProduto(produto.id)}
            onAumentar={() => aumentarQuantidade(produto.id)}
            onDiminuir={() => diminuirQuantidade(produto.id)}
          />
        );
      })}
    </View>
  );
}

const styles = StyleSheet.create({
  areaProdutos: {
    marginTop: 24,
  },
  tituloSecao: {
    fontSize: 20,
    fontWeight: 'bold',
    marginBottom: 12,
  },
  resumo: {
    color: '#374151',
    fontSize: 14,
    marginBottom: 12,
  },
});

4. Preço unitário ainda não responde tudo

Escolha Água mineral 20 L e aumente a quantidade para 3. O cartão mostra preço de R$ 20,00 e quantidade 3, mas o cliente ainda precisa fazer a conta mentalmente.

3 unidades × R$ 20,00 = ?

A interface já possui as duas informações necessárias. Portanto, agora nasce o subtotal de cada item.

Construa e confira

5. Falta o valor do pedido inteiro

Agora cada cartão consegue calcular seu próprio subtotal. Mas, se água e gás estiverem escolhidos ao mesmo tempo, o usuário ainda não vê a soma geral.

Essa é uma responsabilidade da área que conhece todos os itens: Produtos.js.

subtotal pertence ao item
total pertence ao conjunto do pedido

Para transformar vários subtotais em um único valor, usaremos reduce somente agora, porque surgiu uma necessidade de reduzir uma lista a um resultado único.

Construa e confira

6. Teste com valores conhecidos

Use os valores fictícios do capítulo para conferir se o comportamento faz sentido:

1.Selecione Água mineral 20 L e deixe quantidade 2. O subtotal deve ser R$ 40,00.

2.Selecione Gás 13 kg e deixe quantidade 1. O subtotal deve ser R$ 100,00.

3.O total do pedido deve mostrar R$ 140,00.

4.Aumente a água para 3. O subtotal da água deve ir para R$ 60,00 e o total para R$ 160,00.

5.Cancele o gás. O total deve permanecer apenas com R$ 60,00.

6.Cancele também a água. O total deve voltar para R$ 0,00.

O total deve ser consequência do estado atual do pedido, não um número guardado separadamente.

Construa e confira

7. Uma decisão profissional importante

Não criamos um novo useState para totalPedido. O total pode ser calculado a partir de produtos e itensPedido sempre que a interface é atualizada.

Guardar também o total em outro estado criaria mais uma informação que poderia ficar desatualizada em relação às quantidades.

Se um valor pode ser obtido com segurança a partir do estado atual, não precisamos criar outra memória apenas para copiá-lo.

Construa e confira

8. O que mudou para o usuário

•cada produto exibe preço unitário;

•um produto selecionado exibe quantidade e subtotal;

•alterar a quantidade atualiza o subtotal imediatamente;

•a área de produtos mostra o total do pedido;

•cancelar um item retira também sua contribuição do total.

Agora o usuário consegue conferir o efeito financeiro de cada decisão antes de avançar para seus dados pessoais ou endereço.

Construa e confira

9. Experimente para entender

1.Selecione somente a água e altere a quantidade algumas vezes.

2.Observe se subtotal e total variam juntos.

3.Selecione também o gás.

4.Altere somente a quantidade do gás e confira se o subtotal da água permanece igual.

5.Cancele um dos itens e confira se o total é recalculado.

O objetivo é perceber que o preço pertence ao produto, a quantidade pertence ao item escolhido e o total nasce da combinação dessas duas informações.

    </View>
  );

12. O que aprendemos

•dados numéricos podem fazer parte do catálogo de produtos;

•preço e quantidade têm responsabilidades diferentes e não precisam ser duplicados no mesmo estado;

•multiplicação produz o subtotal de um item;

•reduce pode transformar vários itens em um único total;

•um valor derivado não precisa necessariamente de um useState próprio;

•toFixed e replace podem ajudar a apresentar um valor didático com duas casas e vírgula decimal.
