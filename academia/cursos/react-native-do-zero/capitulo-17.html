Identidade nativa

O aplicativo ganha identidade própria

O aplicativo já roda no celular, mas ainda está sendo executado dentro do Expo Go. Antes de gerar uma instalação independente, precisamos preparar a identidade nativa do projeto.

Construa e confira

1. Identidade visual não é apenas a tela

Teste correto do splash

Confirme a tela de abertura em um build de preview ou produção. O Expo Go não é a referência visual definitiva para essa etapa.

•o nome exibido pelo sistema operacional;

•o ícone do aplicativo;

•a imagem e a cor usadas na tela de abertura.

Construa e confira

2. Prepare os arquivos visuais

Para concluir agora sem depender das artes finais, duplique o arquivo quadrado assets/santa-filomena.png duas vezes e renomeie as cópias como:

•assets/icon.png - primeira cópia da imagem quadrada;

•assets/splash-icon.png - segunda cópia da imagem quadrada.

O arquivo santa-filomena.png continua sendo usado dentro da interface. Os novos arquivos pertencem à identidade nativa do aplicativo.

Construa e confira

3. Instale o suporte de splash

Terminal
npx expo install expo-splash-screen
Construa e confira

4. Configure app.json

Substitua o conteúdo de app.json pelo arquivo completo abaixo. Salve antes de continuar.

app.json — arquivo completo nesta etapa
{
  "expo": {
    "name": "Santa Filomena Água & Gás",
    "slug": "santa-filomena-agua-e-gas",
    "version": "1.0.0",
    "orientation": "portrait",
    "icon": "./assets/icon.png",
    "userInterfaceStyle": "light",
    "plugins": [
      [
        "expo-splash-screen",
        {
          "image": "./assets/splash-icon.png",
          "imageWidth": 200,
          "resizeMode": "contain",
          "backgroundColor": "#eef3f7"
        }
      ]
    ]
  }
}

Linhas destacadas são as que entram ou mudam nesta etapa

Construa e confira

5. O que pode e o que não pode ser validado no Expo Go

O nome e parte da configuração podem aparecer durante o desenvolvimento, mas a tela de abertura nativa não deve ser aprovada visualmente apenas pelo Expo Go. A própria documentação do Expo orienta validar o splash em um build de preview ou produção. Por isso, a confirmação definitiva ficará para o próximo capítulo.

Construa e confira

6. Execute novamente e confirme que o código continua funcionando

Terminal
npx expo start

A configuração nativa não pode quebrar o fluxo que já estava funcionando. Percorra pelo menos a tela inicial e a revisão do pedido.

Checkpoint

7. Checkpoint 17 - O projeto possui identidade nativa

•app.json com nome e slug do projeto;

•icon.png e splash-icon.png presentes em assets;

•expo-splash-screen instalado;

•aplicativo continua executando durante o desenvolvimento;

•splash marcado como pendente de confirmação no build instalável.

Construa e confira

8. O próximo problema já apareceu

Ainda dependemos do Expo Go e do servidor de desenvolvimento. Para encerrar este volume, o aplicativo precisa existir como arquivo instalável e abrir sem o computador.

Capítulo 17 concluído

Marque a conclusão somente depois de copiar o código, observar a prévia e realizar os testes indicados.
