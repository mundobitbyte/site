2. Precisamos enxergar o total das escolhas

Antes de mover qualquer estado, vamos criar em Produtos.js uma memória própria para o conjunto das escolhas e mostrar sua quantidade na tela.

Nesse primeiro teste, não conectaremos essa nova memória aos cartões. Isso é intencional: queremos observar exatamente o que acontece quando duas partes do aplicativo guardam informações separadas.

3. Faça o teste que revela o problema

1.Toque em Escolher no cartão de Água mineral 20 L.

2.Observe que o próprio cartão indica Produto selecionado.

3.Agora olhe para o resumo acima dos cartões.

O cartão diz que a água está selecionada, mas o resumo continua em Selecionados: 0.

Não é um erro do React. Existem duas memórias diferentes: uma dentro de Produto e outra dentro de Produtos. Alterar uma não altera automaticamente a outra.

Construa e confira

4. Onde a memória precisa ficar?

Agora a necessidade ficou visível. Se queremos que a área de produtos conheça o conjunto das escolhas, a memória não pode continuar isolada dentro de cada cartão.

ANTES→Produto 1 → guarda sua própria escolha→Produto 2 → guarda sua própria escolha→DEPOIS→Produtos → guarda o conjunto das escolhas→↓→Produto recebe seu estado e avisa quando for tocado

A menor mudança profissional é colocar o estado no componente comum que enxerga todos os produtos. Essa prática é conhecida como elevar o estado (lifting state up), mas o nome só importa depois de entendermos a necessidade.

Construa e confira

5. Produtos passa a guardar as escolhas

Agora faremos a conexão completa. Produtos.js guardará os ids selecionados e decidirá se um toque adiciona ou remove aquele id.

Não tente decorar includes, filter ou os três pontos. Leia a função como uma decisão: se o id já está na lista, removemos; se não está, acrescentamos.

components/Produtos.js - arquivo completo; digite/ajuste somente as linhas em negrito
import * as React from 'react';
import { View, Text, StyleSheet } from 'react-native';
import Produto from './Produto';

const produtos = [
  {
    id: 1,
    nome: 'Água mineral 20 L',
    descricao: 'Galão retornável de água mineral.',
  },
  {
    id: 2,
    nome: 'Gás 13 kg',
    descricao: 'Botijão residencial de 13 kg.',
  },
];
export default function Produtos() {
  const [selecionados, setSelecionados] = React.useState([]);

  function alternarProduto(id) {
    const jaSelecionado = selecionados.includes(id);

    if (jaSelecionado) {
      const novaLista = selecionados.filter(
        (produtoId) => produtoId !== id
      );
      setSelecionados(novaLista);
    } else {
      setSelecionados([...selecionados, id]);
    }
  }
  return (
    <View style={styles.areaProdutos}>
      <Text style={styles.tituloSecao}>Produtos</Text>

      <Text style={styles.resumo}>
        Selecionados: {selecionados.length}
      </Text>

      {produtos.map((produto) => (
        <Produto
          key={produto.id}
          nome={produto.nome}
          descricao={produto.descricao}
          selecionado={selecionados.includes(produto.id)}
          onAlternar={() => alternarProduto(produto.id)}
        />
      ))}
    </View>
  );
}

const styles = StyleSheet.create({
  areaProdutos: {
    marginTop: 24,
  },
  tituloSecao: {
    fontSize: 20,
    fontWeight: 'bold',
    marginBottom: 12,
  },
  resumo: {
    color: '#374151',
    fontSize: 14,
    marginBottom: 12,
  },
});

Linhas destacadas são as que entram ou mudam nesta etapa

A lista selecionados começa vazia. Cada toque chama alternarProduto com o id daquele produto.

•includes verifica se o id já está entre os selecionados;

•filter cria uma nova lista sem o id que deve ser removido;

•...selecionados mantém os ids atuais antes de acrescentar o novo;

•length informa quantos ids existem na lista.

Construa e confira

6. Produto deixa de guardar uma memória isolada

Como Produtos passou a ser o responsável pelo conjunto das escolhas, Produto.js não precisa mais de um useState próprio.

Apague a linha que cria selecionado e setSelecionado. Depois ajuste as referências indicadas em negrito.

Construa e confira

7. Observe o caminho completo

1.Produtos calcula se o id está em selecionados.

2.Esse resultado chega ao cartão pela prop selecionado.

3.O botão mostra Escolher ou Cancelar escolha conforme essa prop.

4.Ao tocar, Produto chama a função recebida em onAlternar.

5.Produtos altera a lista selecionados.

6.A interface é atualizada com o novo estado.

toque → aviso ao componente pai → estado muda → cartões e resumo recebem o novo resultado
Construa e confira

8. Experimente para entender

1.Escolha Água mineral 20 L. O resumo deve passar para Selecionados: 1.

2.Escolha também Gás 13 kg. O resumo deve passar para Selecionados: 2.

3.Cancele somente a água. O resumo deve voltar para Selecionados: 1.

4.Confirme que o gás continua visualmente selecionado.

5.Cancele o gás. O resumo deve voltar para Selecionados: 0.

Agora existe uma única fonte de verdade para as escolhas dessa área. Os cartões continuam independentes visualmente, mas a memória que organiza o conjunto está em Produtos.

Quando várias partes precisam conhecer a mesma informação, é importante pensar onde essa informação deve viver.

Construa e confira

9. O que mudou para o usuário

A mudança técnica é interna, mas o usuário ganhou uma confirmação nova: além de enxergar cada cartão selecionado, agora consegue conferir quantos produtos fazem parte da sua escolha.

•Selecionados: 0 quando não há escolha;

•Selecionados: 1 quando apenas um produto está escolhido;

•Selecionados: 2 quando água e gás estão escolhidos;

•cancelar uma escolha atualiza também o resumo geral.

12. O que aprendemos

•estado local é útil quando somente o próprio componente precisa daquela informação;

•uma informação compartilhada pode precisar subir para um componente comum;

•um array também pode ser usado como estado;

•includes ajuda a saber se um id está presente;

•filter permite criar uma nova lista sem determinado id;

•uma função pode ser enviada por props para que o componente filho avise o pai sobre uma ação;

•o mesmo estado pode alimentar vários pontos da interface, como cartões e resumo.

O termo técnico elevar o estado descreve exatamente o que fizemos: a memória saiu de cada Produto e foi para Produtos porque ali o aplicativo consegue enxergar o conjunto.
