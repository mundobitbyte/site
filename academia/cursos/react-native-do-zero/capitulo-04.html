Ponto de partida

Mas o olhar do desenvolvedor encontra outra coisa: para mostrar dois produtos, repetimos praticamente a mesma estrutura de View e Text duas vezes.

A interface funciona. O problema agora é repetir código para representar coisas que têm a mesma forma.

Construa e confira

Construa e confira

2. O que se repete e o que muda?

Os dois produtos são diferentes, mas a forma usada para apresentá-los é quase idêntica.

•A estrutura se repete: View, nome, descrição e os mesmos estilos.

•O conteúdo muda: nome do produto e descrição.

Essa distinção é importante. Antes de pensar em uma solução, precisamos saber exatamente qual parte é repetida e qual parte varia.

Estrutura igual + informações diferentes. Esse é o problema real deste capítulo.

A primeira tentativa será simples: dar um componente próprio à estrutura de um produto. Ainda não vamos falar de props, listas ou map.

Construa e confira

3. Primeiro, extraia um único produto

Na lista de arquivos do Snack, use o comando de novo arquivo e crie components/Produto.js. Depois, mantenha esse arquivo aberto para digitar o conteúdo da etapa.

Neste primeiro momento, Produto ainda representa somente a Água mineral 20 L. Isso é intencional: primeiro vamos separar a estrutura repetida.

4. Use Produto sem mudar o resultado

Construa e confira

5. Agora tente reutilizar Produto

Se Produto já sabe desenhar um cartão, parece natural tentar usá-lo novamente para o segundo produto.

Substitua o bloco manual do gás por outro <Produto />. Como os estilos do cartão não são mais usados em Produtos.js, eles também podem sair deste arquivo.

Construa e confira

6. A necessidade das props apareceu

Agora existe uma razão concreta para o componente receber informações de fora. É aqui que entra a ideia de props.

Vamos chamar de props o conjunto de informações que um componente recebe quando é utilizado. Neste projeto, Produto precisa receber apenas duas informações por enquanto: nome e descrição.

Produtos.js informa os dados. Produto.js usa esses dados para montar o cartão.

6.1. Faça Produto usar as informações recebidas

components/Produto.js - arquivo completo; altere somente as linhas em negrito
import * as React from 'react';
import { View, Text, StyleSheet } from 'react-native';

export default function Produto(props) {
  return (
    <View style={styles.produto}>
      <Text style={styles.nomeProduto}>
        {props.nome}
      </Text>
      <Text style={styles.descricaoProduto}>
        {props.descricao}
      </Text>
    </View>
  );
}
const styles = StyleSheet.create({
  produto: {
    backgroundColor: '#f8fafc',
    borderRadius: 12,
    padding: 14,
    marginBottom: 12,
  },
  nomeProduto: {
    fontSize: 17,
    fontWeight: 'bold',
  },
  descricaoProduto: {
    fontSize: 14,
    marginTop: 4,
  },
});

Linhas destacadas são as que entram ou mudam nesta etapa

Em function Produto(props), a palavra props representa as informações recebidas pelo componente. Em {props.nome} e {props.descricao}, as chaves permitem usar esses valores dentro do JSX.

Os nomes nome e descricao foram escolhidos por nós porque fazem sentido para este projeto.

Agora Produtos.js pode usar a mesma estrutura duas vezes e enviar conteúdos diferentes para cada uso.

Construa e confira

8. O que mudou para o usuário?

Visualmente, quase nada. E isso é proposital.

O usuário continua vendo dois cartões claros e separados. A melhoria aconteceu principalmente na organização interna do aplicativo.

Nem toda evolução de um sistema precisa mudar a tela. Algumas mudanças tornam o código mais fácil de manter e ampliar.

Construa e confira

9. O que cada componente faz agora

App.js → organiza a tela maior→IdentidadeEmpresa.js → apresenta a empresa→Produtos.js → decide quais produtos aparecem→Produto.js → define como cada produto aparece

Essa divisão não surgiu de uma regra abstrata. Cada arquivo apareceu quando o projeto criou uma necessidade real para ele.

12. O que aprendemos

Os conhecimentos deste capítulo nasceram da repetição encontrada no código:

•uma estrutura repetida pode ganhar um componente próprio;

•um componente pode ser utilizado mais de uma vez;

•props permitem que a mesma estrutura receba informações diferentes;

•Produto.js define a aparência de um produto;

•Produtos.js escolhe quais produtos aparecem e quais dados envia para cada um;

•uma melhoria interna pode preservar exatamente a experiência que já funcionava para o usuário.

Construa e confira

13. O que ainda não precisamos

Mesmo com dois produtos reutilizando Produto.js, ainda não surgiu necessidade de acrescentar:

•array;

•map;

•useState;

•quantidade;

•carrinho;

•navegação;

•backend ou banco de dados.

Esses recursos continuam esperando o momento em que o próprio projeto pedir por eles.

16. O próximo problema já apareceu

Agora não repetimos mais toda a estrutura do cartão. Mas Produtos.js ainda precisa escrever um <Produto> para cada item que queremos mostrar.

Com dois produtos isso é simples. E se a Santa Filomena Água & Gás tiver cinco, dez ou vinte produtos?

Vamos continuar escrevendo uma chamada <Produto> para cada item?

Essa é a próxima limitação. Somente a partir dela fará sentido estudar uma forma de reunir os dados dos produtos e produzir os componentes a partir desses dados.
