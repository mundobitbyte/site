2. O endereço precisa de uma área própria

Poderíamos colocar o endereço dentro de DadosCliente.js. Mas isso misturaria duas responsabilidades que já são diferentes no mundo real: identificar o cliente e localizar a entrega.

Por isso, criaremos um novo componente: components/EnderecoEntrega.js.

Na lista de arquivos do Snack, use o comando de novo arquivo e crie components/EnderecoEntrega.js. Mantenha o arquivo aberto: o primeiro passo será pedir apenas a rua ou avenida.

components/EnderecoEntrega.js - arquivo novo; digite todo o conteúdo em negrito
import * as React from 'react';
import { View, Text, TextInput, StyleSheet } from 'react-native';

export default function EnderecoEntrega() {
  const [endereco, setEndereco] = React.useState('');

  return (
    <View style={styles.areaEndereco}>
      <Text style={styles.tituloSecao}>Endereço de entrega</Text>

      <Text style={styles.rotulo}>Rua ou avenida</Text>

        placeholder="Digite a rua ou avenida"

}

4. Só a rua ainda não entrega um pedido

Imagine que o cliente escreva apenas “Rua das Flores”. A distribuidora ainda teria duas perguntas imediatas: qual número e em qual bairro?

A necessidade real mostrou que um único campo era insuficiente.

Vamos acrescentar Número e Bairro. O número continua como texto, porque endereços podem usar valores como 120A ou S/N.

5. Nem todo endereço cabe em três campos

Alguns clientes moram em apartamento, condomínio, fundos ou precisam deixar uma referência curta. Essa informação pode ajudar, mas nem sempre existe.

Por isso, o complemento será opcional. O usuário poderá preencher quando precisar, sem transformar esse campo em obrigação.

Construa e confira

6. Preencher campos não é o mesmo que validar

Agora existe um endereço visualmente completo, mas o aplicativo ainda aceita que rua, número e bairro fiquem vazios. Para o usuário, precisamos deixar claro se as informações essenciais já foram fornecidas.

Não criaremos outro estado para isso. A situação do endereço pode ser calculada a partir dos valores que já existem.

Construa e confira

7. A própria informação mostra se está completa

components/EnderecoEntrega.js - arquivo completo; digite somente as linhas em negrito
import * as React from 'react';
import { View, Text, TextInput, StyleSheet } from 'react-native';

export default function EnderecoEntrega() {

trim() remove espaços do começo e do fim antes da comparação. Assim, digitar apenas espaços não faz um campo vazio parecer preenchido.

Se algum campo obrigatório estiver vazio: 'Preencha rua ou avenida, número e bairro.'
Se os três estiverem preenchidos: 'Endereço pronto para entrega.'

Construa e confira

8. Experimente para entender

1.Preencha rua ou avenida, número e bairro. Confirme que a mensagem muda para Endereço pronto para entrega.

2.Apague somente o bairro. A mensagem deve voltar a indicar que faltam informações.

3.Digite apenas alguns espaços no bairro. A mensagem deve continuar indicando que o endereço não está completo.

4.Digite o bairro corretamente e deixe Complemento vazio. O endereço deve continuar sendo considerado pronto.

5.Preencha um complemento e confirme que ele é preservado sem alterar a regra dos campos obrigatórios.

A validação ainda é simples, mas já corresponde a uma regra real do domínio: algumas informações são indispensáveis para a entrega; outra é apenas apoio.

Validar não é pedir mais dados. É deixar explícito quais dados realmente precisam existir.

Construa e confira

9. O que mudou para o usuário

•existe uma seção claramente identificada como Endereço de entrega;

•o cliente sabe quais informações precisa fornecer;

•Complemento aparece como opcional, sem criar uma falsa obrigação;

•o aplicativo informa se rua/avenida, número e bairro já estão completos;

•a rolagem permite alcançar toda a interface mesmo com o conteúdo maior.

Construa e confira

12. O que aprendemos

•uma nova responsabilidade pode justificar um novo componente;

•TextInput e estado podem ser reutilizados em novos contextos sem reaprender o conceito;

•campos obrigatórios e opcionais cumprem papéis diferentes para o usuário;

•uma condição pode ser calculada a partir de estados existentes sem criar estado duplicado;

•trim() ajuda a não aceitar apenas espaços como informação válida;

•renderização condicional também pode comunicar o estado de preenchimento de um formulário.

O conhecimento novo surgiu porque o pedido precisava chegar a um lugar real. O formulário não cresceu por catálogo de componentes.

Construa e confira

13. Confira antes de encerrar

•Existe components/EnderecoEntrega.js.

•App.js importa e utiliza EnderecoEntrega.

•Rua ou avenida, número e bairro são obrigatórios para o status de endereço completo.

•Complemento é opcional.

•A mensagem muda conforme o preenchimento dos campos obrigatórios.

•Apenas espaços não fazem o campo ser considerado preenchido.

•DadosCliente.js continua separado do endereço de entrega.

•A pré-visualização continua sendo exibida sem erros.

15. O próximo problema já apareceu
