Construa e confira

2. Uma nova parte da interface precisa nascer

Os dados do cliente não pertencem à identidade da empresa e também não pertencem à lista de produtos. Por isso, vamos criar um componente próprio chamado DadosCliente.js.

IdentidadeEmpresa → quem é a empresa→Produtos → o que o cliente está pedindo→DadosCliente → quem está fazendo o pedido

Começaremos com apenas uma informação: o nome. O campo aparece porque agora existe uma pessoa que precisa se identificar.

components/DadosCliente.js - arquivo novo; digite todo o conteúdo em negrito
import * as React from 'react';
import { View, Text, TextInput, StyleSheet } from 'react-native';

export default function DadosCliente() {
  const [nome, setNome] = React.useState('');

  return (
    <View style={styles.areaCliente}>
      <Text style={styles.tituloSecao}>Dados do cliente</Text>

      <Text style={styles.rotulo}>Nome</Text>
      <TextInput
        style={styles.campo}
        placeholder="Digite seu nome"
        value={nome}
        onChangeText={setNome}
        autoCapitalize="words"
      />
    </View>
  );
}

const styles = StyleSheet.create({
  areaCliente: {
    marginTop: 24,
  },
  tituloSecao: {
    fontSize: 20,
    fontWeight: 'bold',
    marginBottom: 12,
  },
  rotulo: {
    fontSize: 14,
    fontWeight: 'bold',
    marginBottom: 6,
  },
  campo: {
    borderWidth: 1,
    borderColor: '#cbd5e1',
    borderRadius: 10,
    paddingHorizontal: 12,
    paddingVertical: 10,
    fontSize: 16,
    backgroundColor: '#ffffff',
  },
});

Linhas destacadas são as que entram ou mudam nesta etapa

TextInput é o componente que permite ao usuário digitar texto. Mas queremos mais do que mostrar letras na tela: o aplicativo precisa manter o valor digitado disponível para uso posterior. Por isso o nome já nasce ligado a um estado.

•value mostra no campo o valor guardado em nome;

•onChangeText atualiza nome conforme o usuário digita;

•autoCapitalize="words" ajuda a iniciar palavras com letras maiúsculas em teclados compatíveis.

Construa e confira

4. Quando a tela cresce, ela precisa poder rolar

Centralizar uma tela pequena funcionava. Agora o aplicativo reúne identidade, produtos, quantidade, valores e dados do cliente. O conteúdo precisa começar pelo topo e continuar verticalmente.

Vamos usar ScrollView para permitir rolagem e retirar a centralização que perdeu sentido.

App.js - arquivo completo; ajuste somente as linhas em negrito e remova justifyContent/padding antigos conforme o estado mostrado
import * as React from 'react';
import { View, ScrollView, StyleSheet } from 'react-native';
import Constants from 'expo-constants';
import IdentidadeEmpresa from './components/IdentidadeEmpresa';
import Produtos from './components/Produtos';
import DadosCliente from './components/DadosCliente';

}

A estrutura agora pode ser lida assim:

tela → área rolável → cartão → identidade + produtos + dados do cliente

ScrollView não entrou porque “faz parte do React Native”. Entrou porque nosso conteúdo passou a ser maior do que a área visível.

Construa e confira

5. Falta uma forma de contato

Saber o nome é importante, mas ainda não basta para um delivery. Se surgir uma dúvida sobre o pedido ou a entrega, a Santa Filomena Água & Gás precisa conseguir falar com o cliente.

A próxima informação necessária é o telefone.

Vamos acrescentar um segundo estado e um segundo TextInput no mesmo componente.

components/DadosCliente.js - arquivo completo; digite/ajuste somente as linhas em negrito
import * as React from 'react';
import { View, Text, TextInput, StyleSheet } from 'react-native';

O telefone também passa a ser um campo controlado por estado. keyboardType="phone-pad" solicita um teclado numérico apropriado em dispositivos compatíveis; a aparência pode variar entre aparelhos.

Construa e confira

6. O que significa um campo controlado?

Agora os dois TextInput seguem o mesmo caminho:

usuário digita → onChangeText recebe o novo texto → setNome/setTelefone atualiza o estado → value mostra o estado no campo

Isso é diferente de tratar o campo apenas como uma caixa visual. O componente passa a possuir os valores que foram informados.

Construa e confira

7. Experimente para entender

1.Digite um nome no primeiro campo.

2.Digite um telefone no segundo campo.

3.Role a tela para cima e para baixo.

4.Selecione ou cancele um produto e altere sua quantidade.

5.Volte aos dados do cliente e confira se os valores digitados continuam nos campos.

O objetivo é perceber que diferentes partes da interface podem mudar e, ainda assim, DadosCliente preserva seus próprios estados enquanto o componente continuar montado.

A memória agora não existe só nos produtos. Os dados digitados pelo cliente também passaram a fazer parte do estado da interface.

Construa e confira

8. O que mudou para o usuário

O aplicativo já oferecia produtos, quantidades e valores. Agora o cliente também consegue informar duas informações pessoais indispensáveis para o atendimento:

•nome;

•telefone para contato.

A rolagem também deixa a tela utilizável mesmo quando o conteúdo cresce. Nenhuma dessas mudanças foi acrescentada apenas para “ensinar um componente”: elas surgiram porque o pedido real passou a exigir mais informações e mais espaço.

Construa e confira

9. O que ainda não estamos fazendo

•não estamos validando se nome e telefone estão corretos ou completos;

•não estamos aplicando máscara automática ao telefone;

•não estamos pedindo endereço ainda;

•não estamos enviando os dados para servidor ou API;

•não estamos reunindo ainda produtos e cliente em uma tela final de confirmação.

Cada uma dessas necessidades terá seu momento. Colocá-las agora misturaria problemas diferentes.

Construa e confira

12. O que aprendemos

•TextInput permite entrada de texto pelo usuário;

•value e onChangeText ligam um campo ao estado do componente;

•um formulário simples pode usar mais de um estado local;

•ScrollView permite percorrer conteúdo maior que a área visível;

•uma decisão de layout, como retirar a centralização, pode ser adiada até a própria evolução da tela justificar a mudança;

•componentes diferentes podem cuidar de responsabilidades diferentes dentro da mesma tela.

Construa e confira
