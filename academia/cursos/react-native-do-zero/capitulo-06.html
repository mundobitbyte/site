Construa e confira

2. A tela precisa oferecer uma ação

Se queremos que o cliente escolha um produto, o cartão precisa oferecer uma área que responda ao toque. Para isso, entra Pressable.

Mas apenas receber um toque não é suficiente. Depois do toque, o aplicativo precisa lembrar que aquele produto foi escolhido. É essa necessidade que faz surgir um estado dentro do componente.

toque do usuário → mudança de estado → interface mostra o resultado
components/Produto.js - arquivo completo; digite/ajuste somente as linhas em negrito
import * as React from 'react';
import { View, Text, Pressable, StyleSheet } from 'react-native';

export default function Produto(props) {
  const [selecionado, setSelecionado] = React.useState(false);

  return (
    <View style={styles.produto}>
      <Text style={styles.nomeProduto}>
        {props.nome}
      </Text>
      <Text style={styles.descricaoProduto}>
        {props.descricao}
      </Text>
      <Pressable
        style={styles.botaoEscolher}
        onPress={() => setSelecionado(true)}
      >
        <Text style={styles.textoBotao}>Escolher</Text>
      </Pressable>

      {selecionado && (
        <Text style={styles.confirmacao}>
          Produto selecionado.
        </Text>
      )}
    </View>
  );
}

Construa e confira

3. O que acabou de acontecer?

A mudança foi pequena na interface, mas importante no comportamento do aplicativo.

•Pressable cria uma área capaz de responder ao toque.

•onPress indica o que deverá acontecer quando essa área for pressionada.

•React.useState(false) cria uma pequena memória para o componente: no início, o produto não está selecionado.

•setSelecionado(true) altera essa memória quando o cliente toca em Escolher.

•A mensagem “Produto selecionado.” aparece somente quando selecionado estiver verdadeiro.

Estado é informação que pode mudar durante o uso do aplicativo e provocar uma atualização da interface.

Não precisamos estudar todos os usos de estado agora. Aqui ele existe porque o cartão precisa lembrar uma escolha feita pelo usuário.

Construa e confira

4. Experimente a primeira escolha

Toque em Escolher no cartão de Água mineral 20 L. Observe a confirmação. Depois toque em Escolher no cartão de Gás 13 kg.

Cada cartão é uma instância diferente de Produto. Por isso, cada um possui seu próprio estado de seleção.

Um componente reutilizável não compartilha automaticamente a memória de outra instância dele.

Construa e confira

5. E se o cliente escolher por engano?

A primeira interação já funciona, mas apareceu uma limitação real: depois de escolher um produto, ainda não há como desfazer a escolha.

Não precisamos criar outro botão. O mesmo toque pode alternar entre dois estados: não selecionado e selecionado.

Escolher → selecionado→Cancelar escolha → não selecionado

Construa e confira

6. Uma mesma ação, dois resultados possíveis

Agora o componente usa o valor atual de selecionado para decidir o próximo passo.

•!selecionado significa o valor oposto: se estiver falso, passa para verdadeiro; se estiver verdadeiro, volta para falso.

•A expressão selecionado ? 'Cancelar escolha' : 'Escolher' decide qual texto o botão deve mostrar.

•A mensagem de confirmação continua aparecendo somente enquanto o produto estiver selecionado.

O objetivo não é decorar símbolos. É perceber que a interface agora representa o estado real daquela escolha.

9. O que mudou para o usuário

Nos capítulos anteriores, várias melhorias aconteciam principalmente dentro do código. Agora existe uma mudança diretamente perceptível para quem usa o aplicativo:

•cada produto possui uma ação Escolher;

•o aplicativo mostra quando aquele produto está selecionado;

•o cliente pode cancelar a própria escolha;

•uma escolha não altera automaticamente o outro produto.

Isso é suficiente para a tarefa deste capítulo: o usuário finalmente consegue indicar quais produtos deseja considerar.

Construa e confira

10. O que aprendemos

•Pressable como área de interação;

•onPress como reação ao toque;

•estado como memória de uma informação que muda;

•React.useState para guardar essa informação;

•renderização condicional para mostrar uma confirmação;

•alternância entre selecionado e não selecionado.

Esses conceitos apareceram juntos porque a tarefa do usuário exigiu toque, memória e resposta visual. Não foram introduzidos como uma lista de assuntos desconectados.

Construa e confira

11. Confira antes de encerrar

•Os produtos continuam vindo da lista criada no Capítulo 5.

•Produto.js recebe nome e descricao por props.

•Cada cartão possui o botão Escolher.

•Ao tocar, o produto passa a indicar que está selecionado.

•É possível cancelar a escolha usando o mesmo botão.

•Selecionar um produto não altera automaticamente o estado do outro.

•A pré-visualização continua sendo exibida sem erros.

13. O próximo problema já apareceu

Cada cartão consegue lembrar se está selecionado. Mas essa memória está dentro de cada Produto.

Se o aplicativo precisar montar um pedido com tudo o que o cliente escolheu, uma pergunta nova aparece:

Como o restante do aplicativo saberá quais produtos foram selecionados?

A próxima evolução deverá nascer dessa limitação. Não vamos antecipar carrinho, quantidade ou pedido completo antes de observar qual é a menor forma de reunir essas escolhas.
