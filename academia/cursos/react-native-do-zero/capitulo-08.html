A escolha ganha quantidade

Construa e confira

1. Onde paramos

Produtos.js guarda apenas os ids selecionados. Isso informa quais tipos fazem parte da escolha, mas não contém quantidade.

components/Produtos.js - estado herdado do Capítulo 7
import * as React from 'react';
import { View, Text, StyleSheet } from 'react-native';
import Produto from './Produto';

const produtos = [
  {
    id: 1,
    nome: 'Água mineral 20 L',
    descricao: 'Galão retornável de água mineral.',
  },
  {
    id: 2,
    nome: 'Gás 13 kg',
    descricao: 'Botijão residencial de 13 kg.',
  },
];
export default function Produtos() {
  const [selecionados, setSelecionados] = React.useState([]);

  function alternarProduto(id) {
    const jaSelecionado = selecionados.includes(id);

    if (jaSelecionado) {
      const novaLista = selecionados.filter(
        (produtoId) => produtoId !== id
      );
      setSelecionados(novaLista);
    } else {
      setSelecionados([...selecionados, id]);
    }
  }
  return (
    <View style={styles.areaProdutos}>
      <Text style={styles.tituloSecao}>Produtos</Text>

      <Text style={styles.resumo}>
        Selecionados: {selecionados.length}
      </Text>

      {produtos.map((produto) => (
        <Produto
          key={produto.id}
          nome={produto.nome}
          descricao={produto.descricao}
          selecionado={selecionados.includes(produto.id)}
          onAlternar={() => alternarProduto(produto.id)}
        />
      ))}
    </View>
  );
}

Construa e confira

2. A memória atual ficou pequena para o problema

Uma lista como [1, 2] consegue dizer que os produtos 1 e 2 foram escolhidos. Mas não consegue representar 3 galões de água e 2 botijões de gás.

Antes: id
Agora precisamos: id + quantidade

Portanto, não vamos criar um segundo estado separado apenas para quantidades. Isso abriria espaço para duas memórias relacionadas perderem a sincronia. A menor solução profissional é fazer cada item escolhido guardar as duas informações juntas.

Construa e confira

3. Cada escolha passa a ser um item do pedido

Em Produtos.js, trocaremos a lista de ids por uma lista de objetos. Ao escolher um produto, ele entra com quantidade inicial 1.

4. O cartão precisa mostrar a quantidade

Construa e confira

5. O componente que possui a memória altera a quantidade

Produtos.js ganhará duas funções: uma aumenta a quantidade e outra diminui. A quantidade mínima de um produto selecionado será 1. Para retirar o produto do pedido, o cliente continua usando Cancelar escolha.

Isso evita duas ações diferentes produzirem a mesma consequência: o botão “-” ajusta quantidade; Cancelar escolha remove o item.

import * as React from 'react';
import { View, Text, StyleSheet } from 'react-native';
import Produto from './Produto';

const produtos = [
  {
    id: 1,
    nome: 'Água mineral 20 L',
    descricao: 'Galão retornável de água mineral.',
  },
  {
    id: 2,
    nome: 'Gás 13 kg',
    descricao: 'Botijão residencial de 13 kg.',
  },
];
export default function Produtos() {
  const [itensPedido, setItensPedido] = React.useState([]);

  function alternarProduto(id) {
    const itemExistente = itensPedido.find(
      (item) => item.id === id
    );

    if (itemExistente) {
      const novaLista = itensPedido.filter(
        (item) => item.id !== id
      );
      setItensPedido(novaLista);
    } else {
      setItensPedido([
        ...itensPedido,
        { id: id, quantidade: 1 },
      ]);
    }
  }

  function aumentarQuantidade(id) {
    const novaLista = itensPedido.map((item) => {
      if (item.id === id) {
        return {
          ...item,
          quantidade: item.quantidade + 1,
        };
      }
      return item;
    });
    setItensPedido(novaLista);
  }
  function diminuirQuantidade(id) {
    const novaLista = itensPedido.map((item) => {
      if (item.id === id && item.quantidade > 1) {
        return {
          ...item,
          quantidade: item.quantidade - 1,
        };
      }
      return item;
    });
    setItensPedido(novaLista);
  }

  return (
    <View style={styles.areaProdutos}>
      <Text style={styles.tituloSecao}>Produtos</Text>
      <Text style={styles.resumo}>
        Tipos selecionados: {itensPedido.length}
      </Text>

      {produtos.map((produto) => {
        const itemPedido = itensPedido.find(
          (item) => item.id === produto.id
        );

        return (
          <Produto
            key={produto.id}
            nome={produto.nome}
            descricao={produto.descricao}
            selecionado={itemPedido !== undefined}
            quantidade={itemPedido ? itemPedido.quantidade : 0}
            onAlternar={() => alternarProduto(produto.id)}
            onAumentar={() => aumentarQuantidade(produto.id)}
            onDiminuir={() => diminuirQuantidade(produto.id)}
          />
        );
      })}
    </View>
  );
}

Linhas destacadas são as que entram ou mudam nesta etapa

•map percorre os itens para produzir uma nova lista;

•quando o id corresponde, criamos uma nova versão daquele item;

•...item preserva os dados que já existiam;

•quantidade recebe + 1 ou - 1;

•se a quantidade já é 1, diminuir não reduz mais.

Construa e confira

6. Observe o comportamento completo

1.Escolha Água mineral 20 L. A quantidade deve começar em 1.

2.Toque em + duas vezes. A quantidade deve chegar a 3.

3.Toque em - uma vez. A quantidade deve voltar a 2.

4.Continue diminuindo até 1. Um novo toque em - não deve levar a zero.

5.Use Cancelar escolha. O cartão deixa de fazer parte do pedido.

6.Escolha água e gás e atribua quantidades diferentes a cada um.

Produto escolhido = pelo menos 1 unidade.
Cancelar escolha = retirar o produto do pedido.

Construa e confira

7. O que mudou na estrutura do estado

Antes, o estado precisava responder apenas “quais produtos?”. Agora ele responde “quais produtos e quantas unidades de cada um?”.

Antes
[1, 2]
Agora
[{ id: 1, quantidade: 3 }, { id: 2, quantidade: 1 }]

Essa mudança não foi feita para deixar o código mais sofisticado. Foi feita porque o pedido passou a exigir uma informação que a estrutura anterior não conseguia representar.

Construa e confira

8. Experimente para entender

Faça um pequeno teste controlado:

1.Selecione apenas o gás e deixe a quantidade em 1.

2.Aumente para 4.

3.Selecione também a água e deixe em 2.

4.Confirme que alterar a água não muda a quantidade do gás.

5.Cancele o gás e confirme que a água continua com sua quantidade.

O objetivo é verificar que cada item do pedido possui sua própria quantidade dentro da mesma memória compartilhada.

Construa e confira

11. O que aprendemos

•um estado pode guardar objetos, não apenas valores simples;

•dados relacionados podem ficar juntos no mesmo item;

•find localiza um item pelo id;

•map também pode ser usado para atualizar um item sem alterar os demais;

•o spread ...item ajuda a preservar propriedades existentes ao criar uma nova versão;

•uma quantidade selecionada precisa de uma regra mínima clara para o usuário.

Mais importante: mudamos a estrutura do estado somente quando a necessidade do pedido mostrou que guardar apenas ids já não era suficiente.

Construa e confira

12. Confira antes de encerrar

•Escolher um produto inicia sua quantidade em 1.

•O botão + aumenta apenas aquele produto.

•O botão - diminui apenas aquele produto.

•A quantidade não fica abaixo de 1 enquanto o produto está selecionado.

•Cancelar escolha remove o item do pedido.

•Água e gás podem ter quantidades diferentes.

•A pré-visualização continua sem erros.

14. O próximo problema já apareceu

Agora o cliente consegue dizer o que deseja e em que quantidade. Mas ainda falta uma informação indispensável para um pedido comercial:

Quanto custa cada produto e quanto ficará o pedido?

A próxima evolução deve nascer desse ponto: preço, subtotal de cada item e total do pedido. Não vamos antecipar pagamento ou finalização antes de o próprio pedido saber calcular seus valores.
