Projeto local

O aplicativo sai do Snack

Até aqui, o aplicativo foi construído e testado em um ambiente online. Isso foi útil para aprender sem começar pela instalação de ferramentas. Agora surgiu uma necessidade nova: o mesmo projeto precisa existir em uma pasta real do computador.

Não vamos reescrever o aplicativo. Vamos transportar o que já funciona.

Construa e confira

1. Por que sair do Snack agora

•o código já possui vários arquivos e pastas;

•a aplicação já usa navegação e rede;

•os próximos passos exigem configurações que pertencem a um projeto Expo completo;

•para gerar um aplicativo instalável, precisamos de um projeto local.

O Snack não foi um atalho descartável: ele cumpriu sua função pedagógica. A mudança de ambiente acontece somente quando o próprio projeto passou a exigir isso.

Construa e confira

2. O que precisa existir no computador

•Node.js em versão LTS compatível com o Expo SDK usado no projeto;

•um terminal no Windows;

•um editor como o Visual Studio Code;

•conexão com a internet para criar o projeto e instalar dependências.

Neste percurso, o alvo é Expo SDK 57. Use o comando indicado nesta etapa para criar a mesma base e mantenha as versões registradas em package.json.

Construa e confira

3. Crie um projeto Expo mínimo

Abra o PowerShell ou o terminal do VS Code na pasta em que deseja criar o projeto e execute:

Terminal
npx create-expo-app@latest santa-filomena-app --template blank@57

Depois entre na pasta criada:

Terminal
cd santa-filomena-app

O template blank é proposital: ele cria a base mínima e mantém App.js como ponto de entrada, combinando com a arquitetura que construímos no curso.

Construa e confira

4. Primeiro teste: a base local funciona?

Terminal
npx expo start

Neste momento, o objetivo é apenas confirmar que o servidor de desenvolvimento inicia sem erro. Encerre com Ctrl+C antes de substituir os arquivos.

Construa e confira

5. Leve o projeto que já existe

Com o projeto do Snack aberto, crie no projeto local as mesmas pastas e copie o conteúdo atual de cada arquivo para a raiz do novo projeto:

•App.js;

•a pasta components;

•a pasta screens;

•a pasta services;

•assets/santa-filomena.png.

Não copie node_modules. Também não substitua o package.json gerado pelo Expo por um package.json antigo: as dependências devem ser instaladas no projeto recém-criado para permanecer compatíveis com o SDK real.

Construa e confira

6. Instale a navegação que o aplicativo usa

Terminal
npm install @react-navigation/native @react-navigation/native-stack
npx expo install react-native-screens react-native-safe-area-context

O segundo comando deixa o Expo escolher versões compatíveis das dependências nativas com o SDK atual do projeto.

Construa e confira

7. Confira a estrutura antes de executar

Construa e confira

8. Execute novamente

Terminal
npx expo start

Se o terminal abrir o servidor sem erros de importação, o projeto já saiu do Snack sem perder a organização construída nos capítulos anteriores.

Construa e confira

9. Faça uma verificação de dependências

Terminal
npx expo-doctor

Corrija apenas problemas reais apontados para o projeto. Não atualize pacotes aleatoriamente durante este capítulo.

Checkpoint

10. Checkpoint 15 - O projeto existe fora do Snack

•projeto Expo local criado com template blank;

•fontes do Checkpoint 14 preservadas;

•dependências de navegação instaladas no projeto local;

•package.json real gerado/atualizado pelo próprio ambiente;

•servidor Expo inicia sem erro.

Construa e confira

11. O próximo problema já apareceu

O aplicativo agora existe no computador, mas ainda precisamos confirmar que ele funciona como aplicativo móvel de verdade no aparelho. É isso que faremos a seguir.

Capítulo 15 concluído

Marque a conclusão somente depois de copiar o código, observar a prévia e realizar os testes indicados.
