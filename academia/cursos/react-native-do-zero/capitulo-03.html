Os produtos entram no aplicativo

Ponto de partida

Agora olhe para a tela como um cliente. Você já sabe quem é a empresa. Mas ainda não consegue responder a uma pergunta básica:

O que eu posso pedir?

É dessa necessidade que nasce este capítulo. Vamos fazer os primeiros produtos aparecerem no aplicativo sem tentar construir, ao mesmo tempo, catálogo completo, carrinho, preço, quantidade ou pedido.

Construa e confira

1. Onde paramos

A estrutura principal continua pequena e conhecida:

App.js
components/
IdentidadeEmpresa.js
assets/
santa-filomena.png

O App.js organiza a tela e o cartão. IdentidadeEmpresa.js reúne aquilo que apresenta a empresa. Nenhum desses papéis precisa ser desfeito.

Construa e confira

2. O que está faltando?

A empresa já está apresentada, mas o aplicativo ainda não mostra aquilo que ela vende. Vamos começar com dois produtos que já fazem parte do contexto do projeto:

•Água mineral 20 L.

•Gás 13 kg.

Neste momento, os cartões serão simples: nome e uma descrição curta. Não colocaremos preço, quantidade, botão de compra ou imagens individuais ainda. A menor evolução útil agora é fazer os produtos existirem na interface e perceber como essa nova parte se organiza.

Construa e confira

3. Uma nova parte da tela precisa de um lugar próprio

Até aqui, IdentidadeEmpresa reúne a apresentação da empresa. Colocar os produtos dentro desse mesmo arquivo misturaria duas partes diferentes da interface.

Por isso, surge uma necessidade concreta: criar um componente para reunir a área de produtos.

IdentidadeEmpresa.js → apresenta quem é a empresa→Produtos.js → começa a apresentar o que a empresa vende

Na lista de arquivos do Snack, use o comando de novo arquivo, crie components/Produtos.js e confirme o nome. Esse arquivo reunirá a área de produtos.

Depois que o arquivo existir, digite o conteúdo abaixo.

components/Produtos.js - arquivo novo; digite todo o conteúdo em negrito
import * as React from 'react';
import { View, Text } from 'react-native';

export default function Produtos() {
  return (
    <View>
      <Text>Produtos</Text>
    </View>
  );
}

Ainda não estamos criando uma lista de produtos. Criamos apenas um lugar próprio para essa parte da interface.

Construa e confira

4. O aplicativo precisa usar Produtos

Criar Produtos.js não é suficiente. O App.js precisa importar esse componente e colocá-lo na tela.

Neste momento, não vamos mudar o posicionamento da tela. Primeiro vamos colocar Produtos no aplicativo e observar o resultado real. Se surgir uma limitação visível, ela é que deverá justificar a próxima alteração.

App.js - arquivo completo; digite somente as linhas em negrito
import * as React from 'react';
import { View, StyleSheet } from 'react-native';
import Constants from 'expo-constants';
import IdentidadeEmpresa from './components/IdentidadeEmpresa';
import Produtos from './components/Produtos';

export default function App() {
  return (
    <View style={styles.container}>
      <View style={styles.cartao}>
        <IdentidadeEmpresa />
        <Produtos />
      </View>
    </View>
  );
}
const styles = StyleSheet.create({
  container: {
    flex: 1,
    justifyContent: 'center',
    paddingTop: Constants.statusBarHeight,
    backgroundColor: '#eef3f7',
    padding: 16,
  },
  cartao: {
    backgroundColor: '#ffffff',
    borderRadius: 16,
    padding: 20,
  },
});

Linhas destacadas são as que entram ou mudam nesta etapa

Observe a pré-visualização.

A palavra Produtos deve aparecer abaixo da identidade da empresa. Ainda não parece um catálogo, mas agora a tela já possui um lugar separado para essa nova necessidade.

Um componente só passa a fazer parte da interface quando outro trecho do aplicativo o utiliza.

Construa e confira

5. A seção precisa se apresentar melhor

A palavra Produtos já aparece, mas ainda parece um texto solto. Vamos organizar essa pequena área usando propriedades que o projeto já conhece.

components/Produtos.js - arquivo completo; digite/ajuste somente as linhas em negrito
import * as React from 'react';
import { View, Text, StyleSheet } from 'react-native';

export default function Produtos() {
  return (
    <View style={styles.areaProdutos}>
      <Text style={styles.tituloSecao}>
        Produtos
      </Text>
    </View>
  );

const styles = StyleSheet.create({
  areaProdutos: {
    marginTop: 24,
  },
  tituloSecao: {
    fontSize: 20,
    fontWeight: 'bold',
    marginBottom: 12,
  },
});

Linhas destacadas são as que entram ou mudam nesta etapa

Observe a pré-visualização. A nova parte da interface continua simples, mas agora existe uma separação visual entre a identidade da empresa e a área de produtos.

Repare que não apareceu uma aula isolada sobre StyleSheet. Os estilos entraram porque a seção passou a precisar de organização.

Construa e confira

8. A tela cresceu: observe antes de mexer

Com dois produtos na tela, o aplicativo ficou maior. Antes de alterar qualquer propriedade do App.js, observe a pré-visualização inteira. Veja se o conteúdo continua bem posicionado, se alguma parte ficou apertada e se algo deixou de caber.

Se aparecer um problema, teremos uma necessidade concreta para resolver. Se não aparecer, não há motivo para mudar o código só porque sabemos que outra propriedade existe.

Essa ordem vale para todo o projeto: primeiro a limitação aparece; depois escolhemos a menor mudança capaz de resolvê-la.

11. Uma escolha deliberada: ainda sem preço, quantidade e botão

Um aplicativo de delivery real precisará de preço, quantidade, escolha e pedido. Mas colocar tudo agora misturaria várias necessidades diferentes em uma única etapa.

Neste capítulo, a conquista é menor e concreta: os produtos passaram a existir na interface. As próximas decisões entrarão quando o projeto realmente precisar delas.

14. O que aprendemos

Os conhecimentos deste capítulo apareceram porque o aplicativo passou a precisar deles:

•um novo componente para uma nova parte real da interface;

•importação e uso desse componente no App.js;

•reaproveitamento de View, Text e StyleSheet;

•reutilização do mesmo estilo em mais de um cartão de produto;

•organização progressiva da tela sem misturar ainda carrinho, quantidade ou pedido.

Também apareceu uma observação importante: componentes diferentes podem representar partes diferentes da mesma tela sem que o aluno precise aprender toda a arquitetura de React Native de uma vez.

17. O próximo problema já apareceu

Os dois produtos aparecem e a solução funciona. Agora imagine que a Santa Filomena Água & Gás precise mostrar cinco, dez ou vinte produtos.

Do jeito atual, cada novo produto exigiria repetir praticamente o mesmo bloco de View e Text, mudando apenas as informações.

Se a estrutura é quase a mesma e o conteúdo muda, será que precisamos continuar copiando o bloco inteiro?

Essa repetição é a próxima limitação do projeto. É dela que deverá nascer a evolução seguinte - somente quando decidirmos como representar um produto de forma reutilizável.
