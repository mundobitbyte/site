<section aria-labelledby="outra-maquina">
<h3 id="outra-maquina">“Abri a pasta, mas o botão não respondeu.”</h3>
<p>Uma colega vai conferir o balcão antes de usá-lo no atendimento. Você enviou os arquivos, ela abriu a página e o aviso apareceu, mas o botão continuou desabilitado. Na sua máquina funcionava. O que pode ter ficado para trás?</p>
<p><strong>Na sua cópia, localize <code>public/js/balcao/main.js</code>. Compare com <code>cliente-balcao/src/main.ts</code>.</strong> Um é o código que o navegador carrega; o outro é a fonte que você edita. Se a nova pasta recebeu somente os .ts, ainda precisa gerar o JavaScript. Se recebeu apenas um .js antigo, pode parecer pronta sem representar as últimas correções.</p>
<p>Vamos conferir a entrega em uma pasta nova, sem depender das instalações ou dos arquivos gerados da primeira cópia. Você não vai refazer o Café nem estudar as seis aulas inteiras outra vez. Vai reunir as mudanças que já construiu, preparar o ambiente e demonstrar o resultado.</p>
</section>

<section aria-labelledby="reconstruir-saida">
<h3 id="reconstruir-saida">Gerar o que o navegador realmente usa</h3>
<p><strong>No terminal da raiz de cafe-aurora-web3, confira o PHP e inicie o servidor.</strong> Se sua primeira cópia ainda ocupa a porta 8000, pare aquele servidor com Ctrl + C no terminal correspondente. Usaremos uma aplicação por vez nessa porta.</p>
<pre class="code-block"><code>php --version
php -d opcache.enable=0 -S localhost:8000 -t public</code></pre>
<p>Deixe esse terminal em execução. Abra outro terminal, confirme que ele está na raiz da nova aplicação e entre na pasta do cliente:</p>
<pre class="code-block"><code>cd cliente-balcao
node --version
npm --version
npm ci
npm run build</code></pre>
<p>Use a versão Node 24 já preparada na <a href="web3-capitulo2-aula2.html#guardar-bancada">Aula 2</a>. npm ci usa o package-lock para instalar uma cópia das dependências; não procura node_modules na solução anterior. O build verifica o TypeScript e gera <code>public/js/balcao/main.js</code>. Confira se o arquivo apareceu nesse caminho e se public/api, CSS e demais páginas continuam presentes.</p>
<p><strong>Abra <a href="http://localhost:8000/balcao.php" target="_blank" rel="noopener">http://localhost:8000/balcao.php</a> e clique em “Atualizar atendimento”.</strong> Confira também a <a href="http://localhost:8000/api/atendimento.php" target="_blank" rel="noopener">resposta da API</a>. O resultado deve vir da nova cópia, executada pelo terminal que você acabou de iniciar.</p>
<p>Se o build falhar, leia a primeira mensagem e confira o arquivo indicado; não entregue um .js de outra pasta para esconder o problema. Se o botão continuar desabilitado, abra o Console e a Rede: main.js foi encontrado? O script aponta para js/balcao/main.js? Os cinco ids ainda correspondem ao main.ts?</p>
<p>Se o PHP não for reconhecido no terminal do VS Code, retome a <a href="web3-capitulo2-aula1.html#balcao-aberto">orientação de Laragon da Aula 1</a> com o professor. O caminho de configuração foi fundamentado na documentação; sua execução em Windows/Laragon ainda precisa ser conferida no laboratório.</p>
