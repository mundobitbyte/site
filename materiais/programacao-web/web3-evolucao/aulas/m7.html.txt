<p>Uma cliente abre o Café pelo celular para consultar a retirada e enviar o cardápio a outra pessoa. O site já se adapta à tela menor. Podemos aproveitar o compartilhamento do aparelho sem transformar essa possibilidade em uma obrigação para todos os navegadores.</p>
<p>Vamos acrescentar uma página pequena de atendimento móvel. Ela reutiliza a API que já existe. Não vamos criar outro prazo nem um cadastro exclusivo para celular.</p>
<h3>Consulte antes de compartilhar</h3>
<p>Com o Laravel em execução, abra <code>http://localhost:8000/mobile.html</code>. Use o botão de consulta e confira a mensagem recebida. No VS Code, acompanhe <code>public/js/mobile.js</code>: o endereço consultado é <code>/api/atendimento</code>, com o mesmo contrato de três campos.</p>

<p>A página tem um retorno textual para informar consulta, falha e conclusão. O botão fica indisponível durante a espera e volta a funcionar depois. Não há razão para manter o cliente preso em “Consultando…” quando a conexão falha.</p>
<h3>Um recurso que depende do navegador</h3>
<p><code>navigator.share</code> faz parte da Web Share API: permite solicitar ao navegador o compartilhamento de um título e endereço. Não escolhemos nem controlamos o aplicativo que receberá o pedido. A pessoa continua decidindo se quer compartilhar e com quem.</p>
<p>O código confere se o recurso existe antes de usá-lo. Quando não existe, a página mantém um link que pode ser aberto e copiado. A recusa de permissão, a falta de suporte e o cancelamento não devem impedir o uso normal do cardápio.</p>
<p>Experimente o botão no navegador disponível. Se a janela de compartilhamento abrir, cancele uma vez e observe a orientação. Se não abrir, use o link alternativo. Não é necessário enviar uma mensagem real a alguém para concluir o exercício.</p>
<p>Recursos desse tipo dependem de suporte e contexto seguro, geralmente HTTPS; <code>localhost</code> recebe tratamento especial para desenvolvimento. Abrir pelo celular o IP de outro computador em HTTP não oferece automaticamente as mesmas condições. Não troque uma falha de ambiente por uma informação falsa de que o código compartilhou.</p>
<h3 id="checkpoint">Funciona também sem o recurso extra?</h3>
<p>Verifique consulta bem-sucedida, falha de consulta, ausência de compartilhamento nativo e link alternativo. Use teclado e ampliação de texto; o controle precisa continuar compreensível. Registre qual navegador usou e se o compartilhamento abriu ou ficou indisponível. Nosso próximo consumidor será outro programa, que pede um contrato XML em vez da resposta JSON do balcão.</p>
