<p>O objeto reuniu as regras do aviso. Porém, ao abrir a aplicação, ainda precisamos procurar arquivos para descobrir quem recebe uma consulta e quem monta a página. Isso fica mais difícil quando o Café ganha uma área de edição.</p>
<p>Vamos organizar uma única parte primeiro: a consulta do atendimento. O balcão continuará sendo o mesmo consumidor de JSON, as imagens e o CSS continuarão sendo os do Café e as mensagens do Web II permanecerão preservadas. A conquista desta etapa será enxergar a página funcionando através de um caminho organizado.</p>
<h3>Prepare o ambiente sem substituir seu projeto</h3>
<p>Preserve uma cópia da pasta e do banco antes de experimentar. No Windows, usaremos o terminal do Laragon para disponibilizar o PHP ao VS Code. O servidor que abrirá a aplicação nesta aula será iniciado por um comando; não é preciso instalar XAMPP ou WAMP junto. Confira <code>php -v</code>, <code>php --ini</code>, <code>php -m</code> e <code>composer --version</code>. O kit usa PHP 8.5, Laravel 13 e extensões PDO SQLite, mbstring, XML/DOM e OpenSSL. SOAP será necessário em uma etapa posterior.</p>
<p>Laragon organiza o ambiente local. Na <a href="https://laragon.org/pricing" target="_blank" rel="noopener noreferrer">política consultada em 28/10/2026</a>, há uso não comercial sem licença paga, com lembrete de licença e sem atualização automática. A prática não exige comprar uma licença. Use uma instalação da escola ou a modalidade permitida para o exercício. <strong>Composer</strong> instala bibliotecas PHP e suas dependências. <strong>Laravel</strong> é um framework: oferece uma estrutura para receber requisições, aplicar regras e devolver respostas. VS Code continua sendo o editor. Nenhuma dessas ferramentas elimina a necessidade de compreender o PHP.</p>
<p>Baixe os arquivos desta etapa pelo link ao final. Compare os arquivos com sua pasta anterior: <code>src</code>, <code>public/css</code>, <code>public/img</code> e <code>dados</code> pertencem ao mesmo Café. As pastas novas <code>app</code>, <code>bootstrap</code>, <code>config</code>, <code>resources</code> e <code>routes</code>, além de <code>artisan</code> e dos arquivos Composer, formam a estrutura de apoio fornecida. Não é necessário redigitar as configurações do framework.</p>
<p>Na cópia de trabalho, acrescente essa estrutura e aplique os arquivos apresentados abaixo. Não substitua <code>dados</code> nem suas credenciais por uma pasta vazia do download. Pelo explorador do VS Code, copie <code>.env.example</code> para <code>.env</code> somente se ainda não existir. <code>.env</code> guarda a configuração local e não vai para o Git nem para o download da turma.</p>
<pre class="code-block"><code>composer install --no-interaction --no-plugins
php artisan key:generate</code></pre>
<p>Execute na raiz, onde estão <code>composer.json</code> e <code>artisan</code>. <code>install</code> segue o <code>composer.lock</code>; <code>update</code> mudaria versões. <code>key:generate</code> prepara a chave da aplicação. Não gere outra chave a cada aula. Esta etapa usa sessões e cache em arquivos locais; ainda não precisa criar uma nova tabela.</p>
<h3>Uma requisição, três responsabilidades</h3>
<p>Ao visitar <code>/atendimento</code>, uma <strong>rota</strong> escolhe o código que atenderá o endereço. Um <strong>controller</strong> coordena a consulta. Uma <strong>view</strong> monta o HTML. Nossa classe continua preparando as mensagens. Essa separação conduz ao padrão MVC: Model representa os dados e regras; View apresenta; Controller coordena a requisição.</p>
{{arquivo:routes/web.php}}
{{arquivo:app/Http/Controllers/AtendimentoController.php}}
{{arquivo:resources/views/atendimento.blade.php}}
<p>Na view, <code>@extends</code> reaproveita o layout e <code>@section</code> preenche uma parte dele. <code>{{ $dados['nomeNegocio'] }}</code> imprime o nome com escape de HTML. Blade é o sistema de templates do Laravel; evita duplicar cabeçalho e rodapé em cada tela.</p>
<p>O ponto de entrada também muda: <code>public/index.php</code> inicia o Laravel. A antiga página inicial está preservada em <code>resources/views/inicio-legado.blade.php</code>. O download inclui essa adaptação; “legado” significa o que já existia, não algo que precisamos descartar.</p>
<h3>Abra pelo servidor certo</h3>
<p>Encerre o servidor PHP anterior com Ctrl+C antes de usar novamente a porta 8000. Na raiz, execute:</p>
<pre class="code-block"><code>php artisan serve --host=localhost --port=8000</code></pre>
<p>Abra <code>http://localhost:8000/atendimento</code>, depois <code>/api/atendimento</code> e <code>/balcao.php</code>. A rota <code>/api/atendimento.php</code> também foi mantida: assim o TypeScript existente continua consultando o mesmo endereço. Se extraiu uma cópia nova, faça o build de <code>cliente-balcao</code> antes de testar o balcão.</p>
<p>Para conhecer o apoio de geração de arquivos, execute <code>php artisan help make:controller</code>. O comando <code>php artisan make:controller AtendimentoController</code> gera o esqueleto quando o arquivo ainda não existe; não o execute para substituir nosso controller pronto. Esse apoio à criação é chamado de scaffolding. O código gerado precisa receber as regras reais da aplicação.</p>
<h3 id="checkpoint">O que deve continuar igual?</h3>
<p>A página inicial abre, a nova página mostra o aviso e o balcão recebe os mesmos três campos. Use <code>php artisan route:list</code> para localizar os endereços que você abriu. Se aparecer erro de extensão ou versão, resolva o ambiente antes de alterar regras do Café. Agora que os caminhos estão organizados, falta permitir que o prazo sobreviva sem ficar escrito na criação do objeto.</p>
