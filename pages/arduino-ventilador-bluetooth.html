Controle de Ventilador por Bluetooth

Como um toque no celular pode mudar uma escolha no Arduino? Aprenda esse caminho com três LEDs, entenda a comunicação Bluetooth e crie seu aplicativo no App Inventor.

Comece pelos LEDs. Esta atividade usa o Uno por USB e três LEDs para representar as velocidades. O HC-05 precisa de alimentação e sinais conferidos pelo professor. Relés e ventilador ficam fora dessa montagem; a etapa de 220 V depende de projeto e avaliação profissional. A simulação funciona apenas na tela.

Etapa 1 de 8

Entender o desafio

Ao terminar: Explicar como um toque pode virar um comando no Arduino.

Antes de começar: Reconheça o Uno, o LED, o resistor e o GND; retome os fundamentos do curso se necessário.

Imagine que você está estudando e quer mudar a velocidade do ventilador sem sair do lugar. O celular parece resolver isso com quatro botões: três velocidades e Desligar. Mas como esse toque chega ao Arduino? E como saber se a mensagem foi entendida?

Vamos descobrir esse caminho em partes. Primeiro, três LEDs vão representar as velocidades: LED 1 para baixa, LED 2 para média e LED 3 para alta. Assim podemos observar as escolhas sem conectar o ventilador. Nenhum LED representa uma medição do motor.

Combine o significado dos comandos

O aplicativo e o Arduino precisam seguir o mesmo combinado, chamado protocolo. Aqui, o texto 0 pede para apagar os LEDs; 1, 2 e 3 escolhem um deles. Depois de aplicar a escolha, o Arduino responde com o mesmo caractere. Essa resposta confirma o que o programa fez; não confirma rotação nem contato elétrico de um ventilador.

Programa 1 — faça os comandos funcionar pelo USB
Baixe o arquivo abaixo, abra-o na IDE e grave no Uno. Abra o Monitor Serial a 9600 bit/s. Envie um caractere de cada vez: 1, 2, 3 e 0. Somente o LED escolhido deve acender; 0 apaga todos. O Monitor também mostra o caractere de confirmação. Se enviar uma letra como X, o programa apaga os LEDs e responde 0.
01_serial_leds.inoBaixar .ino
// Mundo bit Byte — checkpoint 1: somente LEDs; nenhum motor ou rele.
// Uno: D5, D6 e D7 -> cada um a seu resistor de 330 ohms -> anodo LED.
// Os tres catodos vao ao GND. Monitor Serial: 9600, sem fim de linha.
const byte LEDS[] = {5, 6, 7};
byte velocidade = 0;

void selecionar(byte nova) {
  // Primeiro apaga todos; depois acende, no maximo, um indicador.
  for (byte i = 0; i < 3; i++) digitalWrite(LEDS[i], LOW);
  velocidade = nova <= 3 ? nova : 0;
  if (velocidade > 0) digitalWrite(LEDS[velocidade - 1], HIGH);
}

void setup() {
  for (byte i = 0; i < 3; i++) {
    digitalWrite(LEDS[i], LOW);
    pinMode(LEDS[i], OUTPUT);
  }
  Serial.begin(9600);
  selecionar(0);
}

void loop() {
  if (!Serial.available()) return;
  char comando = Serial.read();
  if (comando == '\r' || comando == '\n') return;
  selecionar(comando >= '0' && comando <= '3' ? comando - '0' : 0);
  Serial.write('0' + velocidade); // Confirmacao logica de um caractere.
}



Entenda o código antes de avançar
Na lista LEDS estão os pinos 5, 6 e 7. A função selecionar, um trecho que realiza uma tarefa definida, apaga os três LEDs antes de acender o escolhido. A repetição for percorre a lista; as condições if decidem se o comando é válido. Se vetor, função ou condição forem novos para você, retome esses assuntos no bloco Programação Aplicada antes de continuar.

// Mundo bit Byte — checkpoint 2: HC-05 com LEDs, sem motor ou rele.
// Identifique e valide alimentacao, niveis e baud rate do HC-05 antes da ligacao.
// Uno D2 (RX software) recebe TX do modulo com niveis compativeis.
// Uno D3 (TX software) envia ao RX do modulo por adaptacao de nivel validada.
// A alimentacao do modulo e o adaptador nao sao definidos por este codigo.
#include <SoftwareSerial.h>
SoftwareSerial bluetooth(2, 3); // RX, TX do Arduino.
const byte LEDS[] = {5, 6, 7};
byte velocidade = 0;

void selecionar(byte nova) {
  for (byte i = 0; i < 3; i++) digitalWrite(LEDS[i], LOW);
  velocidade = nova <= 3 ? nova : 0;
  if (velocidade > 0) digitalWrite(LEDS[velocidade - 1], HIGH);
}

void setup() {
  for (byte i = 0; i < 3; i++) {
    digitalWrite(LEDS[i], LOW);
    pinMode(LEDS[i], OUTPUT);
  }
  bluetooth.begin(9600); // Confirmar esta velocidade na variante real.
  selecionar(0);
}

void loop() {

Programa 3 — perceba quando as mensagens param
Imagine que o LED 3 está aceso e o celular para de enviar dados. Precisamos que o Uno perceba essa ausência por conta própria. O aplicativo envia ? a cada 500 milissegundos, ou meio segundo, como um sinal de “continuo aqui”. Essa verificação periódica também é conhecida como heartbeat.


Grave o programa 3. Se passarem 2000 milissegundos, ou 2 segundos, sem uma mensagem válida para essa verificação, ele apaga os LEDs. O sinal ? não escolhe velocidade e não recebe resposta. Depois de apagados pelo prazo, somente voltar a enviar ? não reacende os LEDs: é preciso um novo comando 1, 2 ou 3. Esses tempos servem ao exercício; não dimensionam a proteção de um motor.
03_bancada_supervisionada.inoBaixar .ino
// Mundo bit Byte — checkpoint 3: prototipo didatico SOMENTE COM LEDs.
// Nao conectar estas saidas a reles ou a qualquer circuito de 220 V.
// Uno: LEDs/resistores em D5,D6,D7; Bluetooth software em D2(RX),D3(TX).
// Alimentacao/niveis do HC-05: verificar a variante e a interface antes de montar.
// Protocolo: textos '0'..'3'; '?' a cada 500 ms mantem o enlace supervisionado.
// Retorno: um caractere '0'..'3' confirma somente o estado logico dos LEDs.
#include <SoftwareSerial.h>
SoftwareSerial bluetooth(2, 3);
const byte LEDS[] = {5, 6, 7};
const uint32_t PRAZO_MS = 2000UL; // Escolha didatica, nao parametro de seguranca de motor.
byte velocidade = 0;
uint32_t ultimaMensagem = 0;

void selecionar(byte nova) {
  for (byte i = 0; i < 3; i++) digitalWrite(LEDS[i], LOW);
  velocidade = nova <= 3 ? nova : 0;
  if (velocidade > 0) digitalWrite(LEDS[velocidade - 1], HIGH);
}

void confirmar() {
  bluetooth.write('0' + velocidade);
}

void verificarPrazo(uint32_t agora) {
  // Subtracao sem sinal tambem funciona quando millis() volta a zero.
  if (velocidade > 0 && (uint32_t)(agora - ultimaMensagem) >= PRAZO_MS) {
    selecionar(0);
    confirmar();
  }
}

void receber(char comando, uint32_t agora) {
  if (comando == '\r' || comando == '\n') return;
  // Uma mensagem de supervisao atrasada nao deve esconder um prazo ja expirado.
  verificarPrazo(agora);
  ultimaMensagem = agora;
  if (comando == '?') return; // Mantem comunicacao; nunca liga os LEDs.
  selecionar(comando >= '0' && comando <= '3' ? comando - '0' : 0);
  confirmar();
}

void setup() {
  for (byte i = 0; i < 3; i++) {
    digitalWrite(LEDS[i], LOW);
    pinMode(LEDS[i], OUTPUT);
  }
  selecionar(0);
  bluetooth.begin(9600); // Requer HC-05 configurado para 9600 em modo de dados.
  ultimaMensagem = millis();
}

void loop() {
  verificarPrazo(millis());
  // Processa um caractere por volta; nao bloqueia esperando texto ou delimitador.
  if (bluetooth.available()) receber(bluetooth.read(), millis());
}
