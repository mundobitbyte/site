TypeScript Essencial para o Café Aurora

Na última experiência do Capítulo 1, a cozinha informou um prazo e você conferiu como ele chegava ao site e ao balcão. Quando uma aba ficou aberta, foi preciso pedir outra página para enxergar o novo aviso. Nossa próxima necessidade será fazer o navegador consultar a informação do atendimento.

Antes dessa consulta, precisamos aprender a trabalhar com os dados que a tela usará: o nome do Café é um texto, o prazo é um número e o atendimento pode estar aberto ou encerrado. Vamos experimentar isso no VS Code que você já conhece, com uma tarefa pequena: mostrar o prazo, atualizá-lo e reconhecer uma troca de tipo.

O que é TypeScript e o que ele acrescenta?

TypeScript é uma linguagem construída sobre JavaScript, com recursos para descrever e verificar os tipos dos dados durante o desenvolvimento. JavaScript permite programar o comportamento das páginas. TypeScript acrescenta uma conferência: se dissermos que o prazo deve ser um número, ele pode apontar quando o código tenta colocar um texto nesse lugar.

Isso ajuda a encontrar incompatibilidades e a entender o que uma variável ou função espera receber. O navegador executará o JavaScript preparado pelas ferramentas a partir do nosso TypeScript; as indicações de tipo servem à conferência durante o desenvolvimento.

Quando essa ajuda faz diferença?

Em uma página com poucas instruções, JavaScript pode atender bem. Conforme aparecem mais dados, funções, arquivos e pessoas trabalhando no código, explicitar os tipos ajuda a manter os acordos entre essas partes. No Café, vamos começar pelo prazo e chegar aos produtos e às funções que preparam as informações. TypeScript não é obrigatório para toda página nem elimina a necessidade de testes.

Também há um limite importante: descrever um tipo não comprova que uma resposta recebida de fora tem aquele formato. Quando fizermos a consulta real ao PHP, precisaremos conferir os dados recebidos. Por enquanto, vamos aprender a representar e verificar valores conhecidos.

De onde vem o prazo desta experiência?

No fim da experiência da aba aberta, usamos 35 minutos. Vamos adotar esse aviso como referência inicial aqui. Se você escolheu outro prazo na sua cópia, pode mantê-la guardada: o kit de estudo começa com 35 para conseguirmos comparar os resultados.

Quem informa a estimativa é a equipe do Café. A variável apenas guarda o número informado, em minutos; o programa inicial não mede o trabalho da cozinha nem calcula uma previsão. Neste exercício, o valor estará escrito no arquivo TypeScript. Ele ainda não vem de uma consulta ao PHP.

Abra o exemplo no VS Code

Baixe o kit de TypeScript do Café Aurora. Localize o ZIP e extraia seu conteúdo em uma pasta de estudos. No VS Code, escolha Arquivo → Abrir Pasta e selecione a pasta cafe-aurora-typescript, que contém package.json. A aplicação PHP que você construiu continua na própria pasta.

No explorador lateral, localize a pasta src e abra main.ts. Esse será o arquivo de edição; a extensão .ts identifica TypeScript. O index.html é a página que apresenta a saída. Vamos primeiro colocar esse exemplo para funcionar.

Prepare as ferramentas uma vez

No VS Code, escolha Terminal → Novo Terminal. O painel que abre permite executar comandos na pasta do projeto. Confira o caminho mostrado: precisamos trabalhar na pasta que contém package.json.

O Node.js executa as ferramentas de desenvolvimento deste projeto. O npm gerencia sua instalação e os comandos preparados no kit. Vamos conferir se estão disponíveis. Digite um comando por vez e pressione Enter:

node --version
npm --version

O primeiro precisa mostrar v24. seguido dos demais números; o segundo, uma versão do npm. Se algum não for reconhecido, instale o Node.js 24 adequado ao computador, com o npm, e reabra o VS Code. No laboratório, peça orientação ao professor. Se já usa o terminal do Laragon, confira a versão antes de instalar outra cópia.

Com os dois comandos funcionando, instale as ferramentas listadas no projeto:

npm ci

Aguarde o comando terminar. Ele usa package-lock.json para instalar as versões preparadas para esta atividade e precisa de acesso à internet nessa etapa. Surgirá a pasta node_modules, com as ferramentas instaladas. Seus exercícios continuam em src.

Agora, encontre o resultado no navegador

No mesmo terminal, execute:

npm run dev

Esse comando inicia o Vite. Neste projeto, ele transforma o TypeScript para o navegador e mantém uma página local disponível enquanto você edita. Você continua escrevendo no VS Code; para esta prática, abrirá o endereço do Vite em vez de iniciar o Live Preview.

Abra no navegador o endereço mostrado pelo terminal. Ele geralmente começa com http://127.0.0.1:5173/; a porta pode mudar se já estiver ocupada. 127.0.0.1 aponta para o próprio computador. Abrir esse endereço não publica seu exercício na internet.

Mantenha esse terminal aberto: ele está atendendo à página. Com o exemplo inicial, a tela deve mostrar:

true significa verdadeiro: o atendimento está aberto. O prazo de 35 é a estimativa informada pela equipe para esta situação.

A cozinha enviou outro aviso

Entraram novos pedidos, e a equipe informou que o prazo passou de 35 para 45 minutos. Vamos representar esse novo aviso. Volte ao VS Code, abra src/main.ts e localize:

let tempoEstimado: number = 35;

Troque somente 35 por 45, mantendo os demais símbolos:

let tempoEstimado: number = 45;

Salve com Ctrl + S e observe a página no navegador. O prazo deve passar a 45 minutos. Você acabou de alterar um valor no TypeScript e acompanhar seu efeito na tela. A mudança pertence ao exemplo local; seu site PHP mantém os próprios dados.

A página abriu. O que ainda precisamos conferir?

Conseguimos ver 45 minutos. Agora precisamos conferir se o código respeita os tipos que declarou. O Vite prepara a execução, mas não verifica os tipos. No VS Code, escolha novamente Terminal → Novo Terminal, deixando o primeiro aberto. No segundo, confirme a mesma pasta do projeto e execute:

npm run verificar

O comando chama o verificador do TypeScript. Se ele terminar sem apontar erros, não encontrou incompatibilidades de tipos nesses arquivos. Isso complementa o teste na página. No próximo tópico, vamos ler o exemplo e provocar uma troca de número por texto para entender essa diferença.

Antes de seguir: você consegue localizar quem informou o prazo, o arquivo em que ele está representado e a página que mostra sua alteração? Confira também que a verificação terminou sem erros.

Se o resultado não apareceu, por onde começar?
  • Não encontrou package.json: confira a pasta aberta no VS Code e o caminho do terminal; abra a pasta extraída, não o ZIP.
  • O comando não reconhece node ou npm: conclua a preparação do Node.js 24 e reabra o VS Code. No Windows, se o PowerShell bloquear npm.ps1, selecione o perfil Prompt de Comando no terminal integrado e tente novamente, sem mudar políticas do computador.
  • A instalação apresentou erro: confira a conexão e leia a mensagem antes de iniciar o Vite. A prática depende dessa preparação concluída.
  • A página não abre ou não muda: confira se o terminal com npm run dev continua ativo, se abriu o endereço que ele informou e se salvou src/main.ts.

Como continuar nas próximas aulas

Ao voltar, abra esta pasta no VS Code, use npm run dev no terminal e abra o endereço informado. Não precisa repetir npm ci a cada aula com as dependências já instaladas. Para encerrar o servidor ao terminar, selecione seu terminal e pressione Ctrl + C; os arquivos salvos permanecem na pasta.

No tópico 1, você pode continuar no arquivo que acabou de alterar. Nos tópicos seguintes, cada exemplo completo corresponde à situação narrada naquela aula. Guarde sua tentativa antes de substituir src/main.ts. Os arquivos em exemplos permitem comparar ou recuperar o ponto de partida. No tópico 12, acrescentaremos um arquivo de apoio.

Quando quiser gerar os arquivos para distribuição

O comando npm run build verifica os tipos e prepara a versão estática em dist. Essa etapa será útil ao distribuir a página; agora, continue com a leitura do seu primeiro exemplo.

1 — Guardar dados com tipos

Objetivo: Alterar os dados do atendimento e identificar uma atribuição incompatível antes de entregar o código.

Você já mostrou o prazo de 35 minutos no navegador e representou o novo aviso de 45. Vamos ler como esse dado foi guardado e conferir o que acontece se o código receber texto onde esperava um número.

Continue em src/main.ts. Se já atualizou o prazo para 45 na abertura, mantenha sua alteração. O código abaixo mostra a referência inicial, com 35 minutos, para acompanharmos a leitura.

const nome = "Café Aurora";
let tempoEstimado: number = 35;
const pedidosAbertos: boolean = true;

document.body.textContent = `Café Aurora
Negócio: ${nome}
Atendimento aberto: ${pedidosAbertos}
Tempo estimado: ${tempoEstimado} minutos.`;

O que observar

nome recebe o texto entre aspas. O TypeScript deduz, ou infere, esse tipo a partir do valor. Em let tempoEstimado: number = 35, os dois pontos introduzem number: declaramos que a variável recebe números. Os 35 minutos vêm do aviso da equipe retomado na abertura. Se você já colocou 45, o tipo continua sendo number.

const declara uma variável que não pode receber outra atribuição; let permite mudar seu valor. pedidosAbertos: boolean usa o tipo dos valores true e false, verdadeiro e falso. Neste exemplo, true representa o atendimento aberto.

A crase delimita um texto em que ${...} insere o valor de uma variável. document representa a página no navegador; body é seu corpo, e textContent define o texto que aparecerá ali. A última instrução apresenta os dados desta experiência local. Alterar esse arquivo ainda não muda a aplicação PHP.

Experimente no Café

Na declaração de tempoEstimado, coloque o valor entre aspas: use "45" se já atualizou o aviso ou "35" se está na referência inicial. Salve e execute npm run verificar no segundo terminal. Leia a indicação de incompatibilidade entre string, texto, e number, número. A página pode continuar mostrando os algarismos, mas isso não significa que o tipo foi aceito. Retire as aspas, deixe 45, salve e repita a verificação.

Salve, observe a página e execute npm run verificar no segundo terminal. Corrija qualquer erro intencional antes de seguir.

Confira: O prazo representa a estimativa informada pela equipe, em minutos. Você localiza sua declaração, explica por que o texto entre aspas é recusado e termina com 45 na página e a verificação sem erros.

Com os dados bem representados, vamos usar números em um cálculo do Café.

2 — Calcular sem misturar texto e número

Objetivo: Usar números em uma operação e preparar o texto do resultado.

Uma pessoa escolheu três cafés coados. Cada um custa R$ 8,00. Vamos calcular o total antes de mostrar uma orientação na tela.

Em src/main.ts, use o exemplo completo abaixo. Salve e confira o resultado na página da bancada.

const preco: number = 8;
const quantidade: number = 3;
const total = preco * quantidade;

document.body.textContent = `Café Aurora
Café coado: ${quantidade} unidades.
Total: R$ ${total.toFixed(2)}`;

O cálculo vem antes da apresentação

preco e quantidade são números. O operador * multiplica esses valores; o tipo de total é inferido como number.

toFixed(2) prepara duas casas decimais e devolve uma string. Ele usa ponto neste exemplo curto; a formatação monetária completa poderá ser retomada na interface. A conta continua numérica até essa preparação do texto.

Experimente no Café

Troque a quantidade de 3 para 4 e confira R$ 32.00. Em seguida, tente atribuir "4" à variável numérica e execute npm run verificar. Corrija a atribuição antes de seguir.

Salve, observe a página e execute npm run verificar no segundo terminal. Corrija qualquer erro intencional antes de seguir.

Confira: A multiplicação usa números e você consegue identificar em qual ponto o resultado virou texto.

Saber o total não basta quando o atendimento está encerrado. Vamos escolher uma orientação.

3 — Decidir com if / else

Objetivo: Mostrar o prazo somente quando o atendimento está aberto e a estimativa existe.

O aviso atualizado é de 45 minutos. Mas a cozinha também pode estar recebendo pedidos sem conseguir informar uma estimativa naquele instante. Vamos representar essa ausência e escolher o que mostrar em cada situação.

Em src/main.ts, use o exemplo completo abaixo. Salve e confira o resultado na página da bancada.

const pedidosAbertos: boolean = true;
let tempoEstimado: number | null = 45;
let mensagem: string;

if (pedidosAbertos && tempoEstimado !== null) {
  mensagem = `Tempo estimado: ${tempoEstimado} minutos.`;
} else {
  mensagem = "Consulte a equipe antes de pedir.";
}

document.body.textContent = `Café Aurora\n${mensagem}`;

Escolhendo uma orientação

number | null permite dois casos: um número ou ausência de estimativa. null é um valor que escolhemos para representar essa ausência.

O operador && exige que as duas condições sejam verdadeiras. Depois de tempoEstimado !== null, o TypeScript reconhece o caso numérico dentro do bloco. Essa redução das possibilidades é chamada de narrowing. O else orienta a pessoa a consultar a equipe.

Experimente no Café

Na declaração de tempoEstimado, substitua 45 por null e confira a orientação. Depois troque true por false na declaração de pedidosAbertos, representando o atendimento encerrado. Guarde sua tentativa; no próximo exemplo, calcularemos o prazo de um pedido específico.

Salve, observe a página e execute npm run verificar no segundo terminal. Corrija qualquer erro intencional antes de seguir.

Confira: Sem estimativa, a página pede que a pessoa consulte a equipe e não anuncia um prazo fictício.

Com os casos representados, vamos reunir um cálculo em uma função.

4 — Reutilizar uma ação com função

Objetivo: Declarar o que uma função recebe e o que entrega.

Para um pedido específico, o preparo leva 40 minutos e a retirada precisa considerar mais 5. Vamos calcular esse prazo sem espalhar a soma e sua apresentação pelo programa.

Em src/main.ts, use o exemplo completo abaixo. Salve e confira o resultado na página da bancada.

function calcularPrazo(preparo: number, margem: number): number {
  return preparo + margem;
}

const prazo = calcularPrazo(40, 5);
document.body.textContent = `Café Aurora
Tempo estimado: ${prazo} minutos.`;

Duas funções, duas responsabilidades

calcularPrazo recebe dois números e retorna outro número. Os dois pontos depois dos parâmetros descrevem o tipo de cada entrada; : number depois dos parênteses descreve o retorno.

A chamada fornece os valores na mesma ordem. return entrega o resultado para quem chamou. O tipo do retorno pode ser inferido, mas aqui o declaramos para deixar o acordo visível.

Experimente no Café

Use calcularPrazo(30, 10) e confira 40 minutos. Experimente passar "30" como primeiro argumento e rode a verificação de tipos; em seguida, corrija o argumento.

Salve, observe a página e execute npm run verificar no segundo terminal. Corrija qualquer erro intencional antes de seguir.

Confira: Você distingue o número calculado do texto apresentado e consegue localizar o argumento recusado.

A mesma função pode ser escrita de outra forma. Vamos reconhecer essa sintaxe antes das listas.

5 — Reconhecer uma arrow function

Objetivo: Ler uma função escrita com => e reconhecer seus parâmetros e retorno.

Vamos manter o cálculo do prazo e mudar sua forma de escrita. A regra continua sendo preparo mais margem; o que muda é como a função aparece no arquivo.

Em src/main.ts, use o exemplo completo abaixo. Salve e confira o resultado na página da bancada.

const calcularPrazo = (preparo: number, margem: number): number => preparo + margem;

const formatarPrazo = (minutos: number): string => {
  return `Tempo estimado: ${minutos} minutos.`;
};

const prazo = calcularPrazo(40, 5);
document.body.textContent = `Café Aurora
${formatarPrazo(prazo)}`;

A função continua recebendo e devolvendo valores

A variável calcularPrazo guarda uma função. Os parâmetros continuam numéricos e o retorno continua sendo number. Com uma expressão depois de =>, seu resultado é devolvido diretamente.

formatarPrazo usa um bloco com chaves e return. Ela recebe o número calculado e entrega uma string. Essa sintaxe reaparecerá nas operações de listas e nas interfaces; não é preciso converter toda função para ela.

Experimente no Café

Use preparo 30 e margem 10. Confira os 40 minutos. Compare com a função do tópico anterior e aponte parâmetros, operação e retorno nas duas formas.

Salve, observe a página e execute npm run verificar no segundo terminal. Corrija qualquer erro intencional antes de seguir.

Confira: Você reconhece a mesma regra nas duas formas e distingue a função de cálculo da função de apresentação.

6 — Representar um produto com um objeto

Objetivo: Descrever os campos de um produto e acessar seus valores.

Nome, preço e disponibilidade pertencem ao mesmo produto. Vamos reuni-los para evitar variáveis soltas que poderiam acabar descrevendo produtos diferentes.

Em src/main.ts, use o exemplo completo abaixo. Salve e confira o resultado na página da bancada.

type Produto = {
  id: number;
  nome: string;
  preco: number;
  disponivel: boolean;
};

const produto: Produto = {
  id: 1, nome: "Café coado", preco: 8, disponivel: true,
};

document.body.textContent = `Café Aurora
Produto: ${produto.nome}
Preço: R$ ${produto.preco.toFixed(2)}
Disponível: ${produto.disponivel}`;

Um nome para o formato do produto

type Produto nomeia o formato esperado: id numérico, nome textual, preco numérico e disponivel booleano. O objeto produto precisa atender a essa descrição.

Acesso com ponto lê um campo, como produto.nome. A descrição não cria um produto: o objeto com valores é criado logo depois. O editor pode apontar um campo ausente ou um valor incompatível enquanto você escreve.

Experimente no Café

Troque o nome e o preço para outro produto do Café. Retire temporariamente preco do objeto e execute a verificação. Leia a indicação do campo obrigatório e complete-o novamente.

Salve, observe a página e execute npm run verificar no segundo terminal. Corrija qualquer erro intencional antes de seguir.

Confira: Você distingue a descrição Produto do objeto produto e consegue acessar seus campos.

Um objeto representa um produto. Vamos guardar vários deles no mesmo conjunto.

7 — Guardar vários produtos em um array

Objetivo: Construir uma coleção cujos itens seguem o mesmo formato.

O cardápio tem café, pão e bolo. Vamos reunir os três produtos em uma lista, mantendo para cada um o formato que acabamos de descrever.

Em src/main.ts, use o exemplo completo abaixo. Salve e confira o resultado na página da bancada.

type Produto = { id: number; nome: string; preco: number; disponivel: boolean };

const produtos: Produto[] = [
  { id: 1, nome: "Café coado", preco: 8, disponivel: true },
  { id: 2, nome: "Pão artesanal", preco: 12, disponivel: true },
  { id: 3, nome: "Bolo de laranja", preco: 9, disponivel: true },
];

document.body.textContent = `Café Aurora
Produtos cadastrados: ${produtos.length}`;

Cada posição precisa respeitar o formato

Produto[] descreve um array de produtos. Os colchetes de valores reúnem os objetos separados por vírgula. A propriedade length informa quantos itens existem.

O TypeScript confere cada item. A lista pode crescer sem que um preço textual ou um nome ausente passe despercebido pela verificação. Uma lista vazia também é válida e tem length igual a zero.

Experimente no Café

Acrescente um quarto produto com identificador próprio, nome e preço numérico. Salve e confira a contagem. Depois deixe o array vazio e observe zero produtos.

Salve, observe a página e execute npm run verificar no segundo terminal. Corrija qualquer erro intencional antes de seguir.

Confira: A contagem acompanha os itens e todos respeitam o mesmo formato.

Já sabemos quantos produtos existem. Agora vamos mostrar uma linha para cada um.

8 — Mostrar a lista com map

Objetivo: Representar uma lista de produtos com campos conhecidos e produzir sua apresentação.

O Café já tem produtos conhecidos do Web I. Nesta bancada vamos usar três deles para conferir nome e preço sem depender de um servidor novo.

Em src/main.ts, use o exemplo completo abaixo. Salve e confira o resultado na página da bancada.

type Produto = {
  id: number;
  nome: string;
  preco: number;
  disponivel: boolean;
};

const produtos: Produto[] = [
  { id: 1, nome: "Café coado", preco: 8, disponivel: true },
  { id: 2, nome: "Pão artesanal", preco: 12, disponivel: true },
  { id: 3, nome: "Bolo de laranja", preco: 9, disponivel: true },
];

const linhas = produtos.map((produto) => {
  return `${produto.nome} — R$ ${produto.preco.toFixed(2)}`;
});

document.body.textContent = `Café Aurora\n${linhas.join("\n")}`;

Um formato para cada produto

type Produto dá um nome ao formato do objeto. Cada item precisa de id, nome e preco com os tipos indicados. Produto[] descreve um array desses itens.

map transforma cada produto em uma linha de texto; o tipo de produto é inferido a partir do array. toFixed(2) produz texto com duas casas decimais e ponto; join("\n") reúne as linhas. Esta saída curta serve para observar os dados, sem refazer o layout do cardápio.

Experimente no Café

Acrescente um produto com id 4, nome e preço numérico. Confira a nova linha. Retire temporariamente seu preco e observe a indicação do editor; complete o campo antes de verificar.

Salve, observe a página e execute npm run verificar no segundo terminal. Corrija qualquer erro intencional antes de seguir.

Confira: O novo produto aparece e a verificação reconhece quando falta um campo obrigatório.

Com a lista apresentada, podemos selecionar produtos e procurar um item específico.

9 — Selecionar e encontrar produtos

Objetivo: Distinguir uma lista filtrada de um resultado que pode não existir.

Uma pessoa quer saber quantos produtos custam até R$ 9,00. Outra pergunta pelo produto de código 2. São duas consultas diferentes sobre os mesmos dados.

Em src/main.ts, use o exemplo completo abaixo. Salve e confira o resultado na página da bancada.

type Produto = { id: number; nome: string; preco: number; disponivel: boolean };

const produtos: Produto[] = [
  { id: 1, nome: "Café coado", preco: 8, disponivel: true },
  { id: 2, nome: "Pão artesanal", preco: 12, disponivel: true },
  { id: 3, nome: "Bolo de laranja", preco: 9, disponivel: true },
];

const acessiveis = produtos.filter((produto) => produto.preco <= 9);
const escolhido = produtos.find((produto) => produto.id === 2);
let mensagem = "Produto não encontrado.";

if (escolhido !== undefined) {
  mensagem = `${escolhido.nome}: R$ ${escolhido.preco.toFixed(2)}`;
}

document.body.textContent = `Café Aurora
Até R$ 9,00: ${acessiveis.length} produtos.
${mensagem}`;

Encontrar também pode falhar

filter devolve um array, que pode estar vazio. find devolve o primeiro produto que corresponde à condição ou undefined quando não encontra nenhum.

Por isso verificamos escolhido !== undefined antes de acessar seu nome e seu preço. undefined é o resultado ausente desta busca; não é um produto com campos vazios.

10 — Ler campos com desestruturação

Objetivo: Retirar campos de um objeto para variáveis com nomes claros.

A mensagem usa o nome e o preço do produto várias vezes. Podemos dar nomes locais a esses campos para deixar essa parte do código mais fácil de acompanhar.

Em src/main.ts, use o exemplo completo abaixo. Salve e confira o resultado na página da bancada.

type Produto = { id: number; nome: string; preco: number; disponivel: boolean };
const produto: Produto = { id: 1, nome: "Café coado", preco: 8, disponivel: true };
const { nome, preco } = produto;

document.body.textContent = `Café Aurora
${nome} — R$ ${preco.toFixed(2)}`;

Os nomes precisam existir no objeto

const { nome, preco } = produto lê os campos e cria variáveis com esses nomes. Seus tipos são inferidos a partir de Produto; não precisamos repetir as anotações.

O objeto continua existindo. A desestruturação não renomeia seus campos nem o modifica. Se escrevermos um nome que não pertence a Produto, o verificador indica essa diferença.

Confira: Você localiza a origem de cada variável retirada e o objeto mantém seus valores.

11 — Criar uma nova versão com spread

Objetivo: Ler campos de um objeto e preparar outro objeto com um valor atualizado.

Vamos voltar ao aviso de 45 minutos que representamos no começo. A cozinha informou agora 55. Precisamos preparar o novo aviso e manter o anterior para comparar os dois antes de escolher qual apresentar.

Em src/main.ts, use o exemplo completo abaixo. Salve e confira o resultado na página da bancada.

interface Atendimento {
  nome: string;
  tempoEstimado: number;
}

const atendimento: Atendimento = {
  nome: "Café Aurora",
  tempoEstimado: 45,
};

const { nome, tempoEstimado } = atendimento;
const atualizado: Atendimento = { ...atendimento, tempoEstimado: 55 };

document.body.textContent = `${nome}
Antes: ${tempoEstimado} minutos.
Depois: ${atualizado.tempoEstimado} minutos.
Original preservado: ${atendimento.tempoEstimado} minutos.`;

Copiar e atualizar um campo

interface Atendimento descreve os campos desse objeto. Assim como o type usado no produto, ela nomeia um formato; não precisamos de comparações avançadas entre os dois recursos nesta unidade.

A desestruturação retira nome e tempoEstimado para variáveis. O spread ... copia os campos no novo objeto e o campo escrito depois substitui a estimativa.

Aqui os campos são valores simples; spread não faz uma cópia profunda de objetos internos.

Salve, observe a página e execute npm run verificar no segundo terminal. Corrija qualquer erro intencional antes de seguir.

Confira: Você consegue apontar qual objeto mudou e qual continua servindo de referência.

12 — Organizar dados para as próximas interfaces

Objetivo: Usar um dado e seu tipo a partir de outro arquivo.

Vamos organizar o aviso de 55 minutos em dois arquivos. Se você experimentou 60 no tópico anterior, guarde essa tentativa: aqui retomamos os 55 da referência. No Capítulo 1, o PHP passou a preparar a informação em um arquivo de apoio. Vamos usar a mesma intenção nesta experiência do navegador: deixar claro quem prepara e quem apresenta.

Crie src/atendimento.ts com este conteúdo:

export type Atendimento = {
  nome: string;
  tempoEstimado: number;
};

export function obterAtendimento(): Atendimento {
  return { nome: "Café Aurora", tempoEstimado: 55 };
}

Agora substitua src/main.ts pelo exemplo abaixo. Os dois arquivos precisam estar na mesma pasta.

import { obterAtendimento } from "./atendimento.js";
import type { Atendimento } from "./atendimento.js";

const atendimento: Atendimento = obterAtendimento();

document.body.textContent = `${atendimento.nome}
Tempo estimado: ${atendimento.tempoEstimado} minutos.`;

Um recurso pode atravessar o arquivo; seu tipo não precisa executar

export disponibiliza o tipo e a função no arquivo de apoio. import traz a função para main.ts. import type traz somente a descrição Atendimento para a verificação.

Usamos ./atendimento.js no caminho pensando no JavaScript gerado; a configuração do projeto e o Vite localizam atendimento.ts durante o desenvolvimento.

O objeto ainda é preparado localmente: não substituímos a função PHP por esta função de estudo nem fizemos uma requisição ao servidor.

Salve, observe a página e execute npm run verificar no segundo terminal. Corrija qualquer erro intencional antes de seguir.

Confira: A mensagem usa o valor do arquivo de apoio, e a verificação aponta um campo renomeado que o consumidor ainda tenta usar.

99 — Exercícios TypeScript

Objetivo: Aplicar os conceitos nos dados do Café e explicar os resultados.

Agora resolva pequenas mudanças com menos orientação. Continue na bancada; guarde seus arquivos antes de substituir um exemplo. Não é necessário construir outro site ou aplicativo.

1. Um prazo bem representado

Defina o nome do Café, a situação do atendimento e um prazo numérico. Acrescente uma variável com a margem de retirada e mostre o prazo final. Provoque uma atribuição de texto, reconheça o erro de tipo e corrija.

Resultado para conferir: O prazo final é uma soma numérica; a verificação passa depois da correção.

2. Sem prazo disponível

Represente uma estimativa ausente com null e informe que a pessoa deve consultar a equipe. Teste também atendimento encerrado. Não apresente zero como substituto automático da ausência.

Resultado para conferir: Os casos aberto com prazo, aberto sem prazo e encerrado têm orientações coerentes.

3. Duas funções para a consulta

Escreva uma função que calcula o prazo a partir de preparo e margem. Escreva outra que recebe esse resultado e prepara a mensagem. Declare parâmetros e retornos.

Resultado para conferir: Uma função entrega número, a outra texto. Uma chamada com argumento incompatível é identificada.

4. Encontrar no cardápio

Crie uma lista de quatro produtos tipados. Mostre seus nomes com map, filtre por um limite de preço e procure um identificador com find. Teste também um identificador ausente.

Resultado para conferir: A lista, o filtro e a busca têm resultados distintos; um produto ausente não provoca acesso a undefined.

5. Comparar o aviso novo com o anterior

Descreva o atendimento com interface. Faça uma cópia com spread e altere o prazo dessa cópia. Mostre os dois valores usando desestruturação onde ela ajudar a leitura.

Resultado para conferir: O aviso novo muda e o objeto anterior continua com seu valor inicial.

6. Preparar em um arquivo, apresentar em outro

Como no tópico 12, separe a preparação do atendimento em um arquivo de apoio. Faça main.ts usar a função e seu tipo. Altere o prazo somente no apoio, confira a página e provoque um nome de campo incompatível para reconhecer o erro antes de corrigir.

Resultado para conferir: A apresentação recebe o valor do apoio e o verificador identifica um campo inexistente. Explique por que o exemplo ainda não consulta o PHP.
