TypeScript Essencial para o Café Aurora

O site e o balcão do Café Aurora já buscam a mesma informação no PHP. Daqui a pouco, o navegador também precisará trabalhar com esses dados. Antes dessa ligação, vamos experimentar como o TypeScript nos ajuda a perceber uma troca de tipos durante o desenvolvimento.

A base é o JavaScript que você já trabalhou no Web I; a revisão do módulo React Native é um apoio se precisar, não um curso inteiro para fazer antes.

Abra a bancada e veja o primeiro resultado

Baixe o kit de TypeScript do Café Aurora e descompacte em outra pasta. Abra a pasta que contém package.json no VS Code. Sua aplicação PHP continua guardada como está; esta bancada permite fazer pequenas experiências nos mesmos dados do Café.

Vamos usar Node.js 24, npm, TypeScript e Vite. Node.js executa as ferramentas no computador; npm instala as dependências declaradas no projeto; TypeScript verifica os tipos; Vite prepara o código para o navegador e serve a página local. Se estiver usando o terminal do Laragon, confira as versões disponíveis em vez de instalar outra cópia sem necessidade.

node --version
npm --version
npm ci
npm run dev

O primeiro comando precisa mostrar uma versão 24.x. Se Node.js ou npm não forem reconhecidos, prepare o Node.js 24 no laboratório com a orientação do professor e reabra o terminal. npm ci instala exatamente as dependências do arquivo de trava, package-lock.json; precisa de acesso à rede nessa preparação.

Abra o endereço local exibido pelo Vite no terminal. Ele geralmente começa com http://127.0.0.1:5173/, mas pode escolher outra porta. Mantenha esse terminal aberto.

Abra src/main.ts e altere 40 para 45. Salve e veja o prazo mudar. Essa será a rotina: ler um trecho, experimentar e observar. No tópico 1, veremos como conferir também o tipo desse valor.

A página abriu. O que ainda precisamos conferir?

O navegador recebe JavaScript preparado a partir do TypeScript. As anotações de tipo não fazem parte dessa execução. O Vite transforma o arquivo, mas não faz a verificação de tipos. Abra um segundo terminal na mesma pasta e execute:

npm run verificar

Um resultado sem erro significa que o verificador não encontrou incompatibilidades nos arquivos de src. Isso não substitui testar o comportamento na página. Se um erro aparecer, leia arquivo e linha; depois de corrigir, execute o comando novamente.

Nos tópicos 1 a 8, substitua somente o conteúdo de src/main.ts pelo exemplo completo da página. Salve sua tentativa antes de trocar. No tópico 9, acrescentaremos um arquivo de apoio. Não é necessário repetir a instalação a cada tópico.

Ao terminar a bancada, npm run build verifica os tipos e gera os arquivos estáticos em dist. Por enquanto, concentre-se na experiência do tópico 1.

Unidade em desenvolvimento · versão experimental para avaliação.

1 — const, let e tipos básicos

Objetivo: Alterar os dados do atendimento e identificar uma atribuição incompatível antes de entregar o código.

A tela do balcão já mostra um prazo. Vamos representar essa informação em TypeScript e experimentar o que acontece quando um número vira texto.

Em src/main.ts, use o exemplo completo abaixo. Salve e confira o resultado na página da bancada.

const nome = "Café Aurora";
let tempoEstimado: number = 25;
const pedidosAbertos: boolean = true;

tempoEstimado = 40;

document.body.textContent = `Café Aurora
Negócio: ${nome}
Atendimento aberto: ${pedidosAbertos}
Tempo estimado: ${tempoEstimado} minutos.`;

O que observar

O nome é inferido como texto pelo valor recebido. Em tempoEstimado, : number declara que a variável recebe números; : boolean descreve verdadeiro ou falso.

const impede reatribuir a variável; let permite atribuir outro valor. A crase monta uma mensagem com os valores entre ${...}. A última instrução mostra texto no corpo da página: é apenas a saída desta bancada, não uma alteração no site PHP.

Experimente no Café

Troque 40 por "40", salve e execute npm run verificar no segundo terminal. Leia a indicação de tipo incompatível. Corrija para 45, sem aspas, e confira a mensagem na página.

Salve, observe a página e execute npm run verificar no segundo terminal. Corrija qualquer erro intencional antes de seguir.

Confira: A verificação aceita 45 e recusa "40". Você consegue explicar a diferença entre o texto e o número.

2 — Condições e valores ausentes

Objetivo: Mostrar o prazo somente quando o atendimento está aberto e a estimativa existe.

A cozinha pode estar recebendo pedidos sem conseguir informar uma estimativa naquele instante. Não vamos inventar zero minutos para preencher esse espaço.

Em src/main.ts, use o exemplo completo abaixo. Salve e confira o resultado na página da bancada.

const pedidosAbertos: boolean = true;
let tempoEstimado: number | null = 40;
let mensagem: string;

if (pedidosAbertos && tempoEstimado !== null) {
  mensagem = `Tempo estimado: ${tempoEstimado} minutos.`;
} else {
  mensagem = "Consulte a equipe antes de pedir.";
}

document.body.textContent = `Café Aurora\n${mensagem}`;

Escolhendo uma orientação

number | null permite dois casos: um número ou ausência de estimativa. null é um valor que escolhemos para representar essa ausência.

O operador && exige que as duas condições sejam verdadeiras. Depois de tempoEstimado !== null, o TypeScript reconhece o caso numérico dentro do bloco. Essa redução das possibilidades é chamada de narrowing. O else orienta a pessoa a consultar a equipe.

Experimente no Café

Substitua 40 por null e confira a orientação. Depois experimente pedidosAbertos = false. Para continuar, deixe o arquivo com o caso que você quiser: o próximo exemplo é independente deste.

Salve, observe a página e execute npm run verificar no segundo terminal. Corrija qualquer erro intencional antes de seguir.

Confira: Sem estimativa, a página pede que a pessoa consulte a equipe e não anuncia um prazo fictício.

Com os casos representados, vamos reunir um pequeno cálculo em uma função.

3 — Funções e arrow functions

Objetivo: Declarar o que uma função recebe e o que entrega.

Para um pedido específico, o preparo leva 40 minutos e a retirada precisa considerar mais 5. Vamos calcular esse prazo sem espalhar a soma e sua apresentação pelo programa.

Em src/main.ts, use o exemplo completo abaixo. Salve e confira o resultado na página da bancada.

function calcularPrazo(preparo: number, margem: number): number {
  return preparo + margem;
}

const formatarPrazo = (minutos: number): string => {
  return `Tempo estimado: ${minutos} minutos.`;
};

const prazo = calcularPrazo(40, 5);
document.body.textContent = `Café Aurora\n${formatarPrazo(prazo)}`;

Duas funções, duas responsabilidades

calcularPrazo recebe dois números e retorna outro número. formatarPrazo recebe o resultado e retorna texto, por isso seu retorno é string.

A sintaxe com => é uma arrow function; ela continua sendo uma função. O TypeScript consegue inferir muitos retornos, mas aqui os declaramos para deixar o acordo visível.

Experimente no Café

Use calcularPrazo(30, 10) e confira 40 minutos. Experimente passar "30" como primeiro argumento e rode a verificação de tipos; em seguida, corrija o argumento.

Salve, observe a página e execute npm run verificar no segundo terminal. Corrija qualquer erro intencional antes de seguir.

Confira: Você distingue o número calculado do texto apresentado e consegue localizar o argumento recusado.

O cardápio tem vários produtos. Vamos descrever o formato de cada item.

4 — Arrays, objetos, type e map

Objetivo: Representar uma lista de produtos com campos conhecidos e produzir sua apresentação.

O Café já tem produtos conhecidos do Web I. Nesta bancada vamos usar três deles para conferir nome e preço sem depender de um servidor novo.

Em src/main.ts, use o exemplo completo abaixo. Salve e confira o resultado na página da bancada.

type Produto = {
  id: number;
  nome: string;
  preco: number;
};

const produtos: Produto[] = [
  { id: 1, nome: "Café coado", preco: 8 },
  { id: 2, nome: "Pão artesanal", preco: 12 },
  { id: 3, nome: "Bolo de laranja", preco: 9 },
];

const linhas = produtos.map((produto) => {
  return `${produto.nome} — R$ ${produto.preco.toFixed(2)}`;
});

document.body.textContent = `Café Aurora\n${linhas.join("\n")}`;

Um formato para cada produto

type Produto dá um nome ao formato do objeto. Cada item precisa de id, nome e preco com os tipos indicados. Produto[] descreve um array desses itens.

map transforma cada produto em uma linha de texto; o tipo de produto é inferido a partir do array. toFixed(2) produz texto com duas casas decimais e ponto; join("\n") reúne as linhas. Esta saída curta serve para observar os dados, sem refazer o layout do cardápio.

Experimente no Café

Acrescente um produto com id 4, nome e preço numérico. Confira a nova linha. Retire temporariamente seu preco e observe a indicação do editor; complete o campo antes de verificar.

Salve, observe a página e execute npm run verificar no segundo terminal. Corrija qualquer erro intencional antes de seguir.

Confira: O novo produto aparece e a verificação reconhece quando falta um campo obrigatório.

Com a lista organizada, podemos selecionar produtos e procurar um item específico.

5 — filter, find e undefined

Objetivo: Distinguir uma lista filtrada de um resultado que pode não existir.

Uma pessoa quer saber quantos produtos custam até R$ 9,00. Outra pergunta pelo produto de código 2. São duas consultas diferentes sobre os mesmos dados.

Em src/main.ts, use o exemplo completo abaixo. Salve e confira o resultado na página da bancada.

type Produto = { id: number; nome: string; preco: number };

const produtos: Produto[] = [
  { id: 1, nome: "Café coado", preco: 8 },
  { id: 2, nome: "Pão artesanal", preco: 12 },
  { id: 3, nome: "Bolo de laranja", preco: 9 },
];

const acessiveis = produtos.filter((produto) => produto.preco <= 9);
const escolhido = produtos.find((produto) => produto.id === 2);
let mensagem = "Produto não encontrado.";

if (escolhido !== undefined) {
  mensagem = `${escolhido.nome}: R$ ${escolhido.preco.toFixed(2)}`;
}

document.body.textContent = `Café Aurora
Até R$ 9,00: ${acessiveis.length} produtos.
${mensagem}`;

Encontrar também pode falhar

filter devolve um array, que pode estar vazio. find devolve o primeiro produto que corresponde à condição ou undefined quando não encontra nenhum.

Por isso verificamos escolhido !== undefined antes de acessar seu nome e seu preço. undefined é o resultado ausente desta busca; não é um produto com campos vazios.

Experimente no Café

Troque o código procurado de 2 para 99 e confira “Produto não encontrado”. Depois altere o limite do filtro para 8 e confira que a contagem passou para um.

Salve, observe a página e execute npm run verificar no segundo terminal. Corrija qualquer erro intencional antes de seguir.

Confira: Uma busca sem resultado produz uma orientação legível, sem tentar acessar propriedades de undefined.

6 — Desestruturação, spread e interface

Objetivo: Ler campos de um objeto e preparar outro objeto com um valor atualizado.

A estimativa do atendimento passou de 40 para 55 minutos. Precisamos comparar o aviso anterior com o novo antes de decidir qual será apresentado.

Em src/main.ts, use o exemplo completo abaixo. Salve e confira o resultado na página da bancada.

interface Atendimento {
  nome: string;
  tempoEstimado: number;
}

const atendimento: Atendimento = {
  nome: "Café Aurora",
  tempoEstimado: 40,
};

const { nome, tempoEstimado } = atendimento;
const atualizado: Atendimento = { ...atendimento, tempoEstimado: 55 };

document.body.textContent = `${nome}
Antes: ${tempoEstimado} minutos.
Depois: ${atualizado.tempoEstimado} minutos.
Original preservado: ${atendimento.tempoEstimado} minutos.`;

Copiar e atualizar um campo

interface Atendimento descreve os campos desse objeto. Assim como o type usado no produto, ela nomeia um formato; não precisamos de comparações avançadas entre os dois recursos nesta unidade.

A desestruturação retira nome e tempoEstimado para variáveis. O spread ... copia os campos no novo objeto e o campo escrito depois substitui a estimativa.

Aqui os campos são valores simples; spread não faz uma cópia profunda de objetos internos.

Experimente no Café

Mude somente tempoEstimado no objeto atualizado para 60. Confira que o original ainda mostra 40. Tente usar "60" e verifique a incompatibilidade antes de corrigir.

Salve, observe a página e execute npm run verificar no segundo terminal. Corrija qualquer erro intencional antes de seguir.

Confira: Você consegue apontar qual objeto mudou e qual continua servindo de referência.

7 — &&, ||, !, ternário e ??

Objetivo: Escolher mensagens e valores alternativos sem confundir zero com ausência.

O nome de exibição pode estar vazio e uma estimativa válida pode ser zero. Os dois casos não devem receber automaticamente o mesmo tratamento.

Em src/main.ts, use o exemplo completo abaixo. Salve e confira o resultado na página da bancada.

const apelido: string = "";
const pedidosAbertos: boolean = true;
const prazo: number | null = 0;

const nomeExibido = apelido || "Café Aurora";
const podeInformarPrazo = pedidosAbertos && prazo !== null;
const situacao = pedidosAbertos ? "Aberto" : "Encerrado";
const prazoExibido = prazo ?? "Consulte a equipe";

document.body.textContent = `${nomeExibido}
Atendimento: ${situacao}
Pedidos encerrados: ${!pedidosAbertos}
Pode informar prazo: ${podeInformarPrazo}
Prazo: ${prazoExibido}`;

Ausência e valor falso são casos diferentes

|| usa o segundo valor quando o primeiro é falsy, como uma string vazia ou zero. ?? usa a alternativa apenas para null ou undefined e preserva zero.

&& combina as condições; ! inverte um booleano; condição ? valor1 : valor2 escolhe um dos valores.

Neste exemplo, prazo representa uma estimativa informada; não é garantia de preparo imediato nem validação de permissão.

Experimente no Café

Compare o resultado de prazo ?? "Consulte a equipe" com prazo || "Consulte a equipe" usando zero. Depois use null e observe a alternativa. Troque pedidosAbertos para false para conferir o ternário e a negação.

Salve, observe a página e execute npm run verificar no segundo terminal. Corrija qualquer erro intencional antes de seguir.

Confira: Você escolhe ?? quando zero deve continuar sendo um valor e reconhece quando || substitui esse zero.

8 — Promise, async/await, try/catch e JSON

Objetivo: Receber uma resposta de estudo, validar o prazo e tratar uma falha.

Antes de ligar o balcão ao servidor, vamos ensaiar o recebimento de um prazo. O texto abaixo é uma resposta local controlada: ainda não existe uma consulta de rede neste exemplo.

Em src/main.ts, use o exemplo completo abaixo. Salve e confira o resultado na página da bancada.

async function carregar(): Promise<void> {
  document.body.textContent = "Consultando o prazo do Café Aurora…";

  try {
    const texto = await Promise.resolve('{"tempoEstimado":35}');
    const dados: unknown = JSON.parse(texto);

    if (
      typeof dados !== "object" || dados === null ||
      !("tempoEstimado" in dados) ||
      typeof dados.tempoEstimado !== "number" ||
      !Number.isFinite(dados.tempoEstimado) || dados.tempoEstimado < 0
    ) {
      throw new Error("O prazo recebido não é válido.");
    }

    document.body.textContent =
      `Café Aurora\nTempo estimado: ${dados.tempoEstimado} minutos.`;
  } catch (erro) {
    const mensagem = erro instanceof Error ? erro.message : "Falha na consulta.";
    document.body.textContent = `Café Aurora\n${mensagem}`;
  }
}

carregar();

Declarar um tipo não valida uma resposta

Promise.resolve entrega um resultado assíncrono local; async permite usar await dentro da função. Promise<void> indica que a função termina sem devolver um valor útil a quem a chamou.

JSON.parse transforma o texto, mas não garante seu formato: guardamos o resultado como unknown.

Primeiro conferimos objeto não nulo, depois a existência de tempoEstimado, seu tipo numérico e seu intervalo. O operador in confere a propriedade, typeof identifica o tipo e Number.isFinite recusa valores não finitos.

throw cria a falha que o catch trata. Como erro também é desconhecido, instanceof Error permite ler sua mensagem com segurança.

Experimente no Café

Troque o JSON por {"tempoEstimado":"35"}, mantendo as aspas externas do texto, e confira a recusa. Tente também null, {} e um JSON malformado. Ao fim, use novamente um prazo numérico não negativo e veja a consulta funcionar.

Salve, observe a página e execute npm run verificar no segundo terminal. Corrija qualquer erro intencional antes de seguir.

Confira: Texto numérico, campo ausente e JSON inválido não viram uma estimativa aceita. O caso válido continua funcionando.

9 — Módulos, import e export

Objetivo: Usar um dado e seu tipo a partir de outro arquivo.

Na primeira experiência do Web III, o PHP passou a preparar a informação em um arquivo de apoio. Podemos organizar esta pequena parte do cliente com a mesma intenção: deixar claro quem prepara e quem apresenta.

Crie src/atendimento.ts com este conteúdo:

export type Atendimento = {
  nome: string;
  tempoEstimado: number;
};

export function obterAtendimento(): Atendimento {
  return { nome: "Café Aurora", tempoEstimado: 35 };
}

Agora substitua src/main.ts pelo exemplo abaixo. Os dois arquivos precisam estar na mesma pasta.

import { obterAtendimento } from "./atendimento.js";
import type { Atendimento } from "./atendimento.js";

const atendimento: Atendimento = obterAtendimento();

document.body.textContent = `${atendimento.nome}
Tempo estimado: ${atendimento.tempoEstimado} minutos.`;

Um recurso pode atravessar o arquivo; seu tipo não precisa executar

export disponibiliza o tipo e a função no arquivo de apoio. import traz a função para main.ts. import type traz somente a descrição Atendimento para a verificação.

Usamos ./atendimento.js no caminho pensando no JavaScript gerado; a configuração do projeto e o Vite localizam atendimento.ts durante o desenvolvimento.

O objeto ainda é preparado localmente: não substituímos a função PHP por esta função de estudo nem fizemos uma requisição ao servidor.

Experimente no Café

Altere a estimativa somente em src/atendimento.ts e confira o resultado. Depois renomeie um campo na descrição e no retorno, mas não em main.ts; rode npm run verificar e localize o consumidor que precisa ser ajustado. Mantenha os nomes coerentes ao terminar.

Salve, observe a página e execute npm run verificar no segundo terminal. Corrija qualquer erro intencional antes de seguir.

Confira: A mensagem usa o valor do arquivo de apoio, e a verificação aponta um campo renomeado que o consumidor ainda tenta usar.

99 — Exercícios TypeScript

Objetivo: Aplicar os conceitos nos dados do Café e explicar os resultados.

Agora resolva pequenas mudanças com menos orientação. Continue na bancada; guarde seus arquivos antes de substituir um exemplo. Não é necessário construir outro site ou aplicativo.

1. Um prazo bem representado

Defina o nome do Café, a situação do atendimento e um prazo numérico. Acrescente uma variável com a margem de retirada e mostre o prazo final. Provoque uma atribuição de texto, reconheça o erro de tipo e corrija.

Resultado para conferir: O prazo final é uma soma numérica; a verificação passa depois da correção.

2. Sem prazo disponível

Represente uma estimativa ausente com null e informe que a pessoa deve consultar a equipe. Teste também atendimento encerrado. Não apresente zero como substituto automático da ausência.

Resultado para conferir: Os casos aberto com prazo, aberto sem prazo e encerrado têm orientações coerentes.

3. Duas funções para a consulta

Escreva uma função que calcula o prazo a partir de preparo e margem. Escreva outra que recebe esse resultado e prepara a mensagem. Declare parâmetros e retornos.

Resultado para conferir: Uma função entrega número, a outra texto. Uma chamada com argumento incompatível é identificada.

4. Encontrar no cardápio

Crie uma lista de quatro produtos tipados. Mostre seus nomes com map, filtre por um limite de preço e procure um identificador com find. Teste também um identificador ausente.

Resultado para conferir: A lista, o filtro e a busca têm resultados distintos; um produto ausente não provoca acesso a undefined.

5. Comparar o aviso novo com o anterior

Descreva o atendimento com interface. Faça uma cópia com spread e altere o prazo dessa cópia. Mostre os dois valores usando desestruturação onde ela ajudar a leitura.

Resultado para conferir: O aviso novo muda e o objeto anterior continua com seu valor inicial.

6. Receber, conferir e organizar

Adapte a resposta local do tópico 8. Aceite apenas prazo numérico finito e não negativo. Separe a preparação em um arquivo de apoio, como no tópico 9. Teste número válido, texto, campo ausente e JSON inválido.

Resultado para conferir: O caso válido aparece; os demais são recusados. O verificador passa e nenhum dado é aceito apenas por uma afirmação de tipo.

Ao terminar, demonstre uma alteração que funciona e uma entrada que seu código recusa. Explique o que a verificação de tipos percebeu e o que você precisou conferir durante a execução. Você pode guardar dúvidas e descobertas nas anotações do Meu estudo.
