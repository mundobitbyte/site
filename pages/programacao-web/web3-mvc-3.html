Marina quer informar 47 minutos uma vez e encontrar esse valor na próxima consulta. Trocar o número em new AvisoAtendimento(...) serviu para investigar a regra; não serve como rotina da cozinha. O dado precisa permanecer guardado.

No Web II você usou um banco para preservar mensagens. Vamos acrescentar o atendimento ao mesmo banco SQLite, sem apagar a tabela de mensagens. O formulário da equipe virá depois. Primeiro precisamos conseguir gravar e ler com segurança.

Guarde o dado, não a frase

Precisamos de uma linha para o atendimento atual: id identifica essa linha; nome, aberto e minutos guardam os valores. Veja a correspondência com nomeNegocio, pedidosAbertos e tempoEstimado. Os nomes da tabela não surgiram de outra situação; representam os três dados que já conhecemos.

Uma migration descreve uma mudança na estrutura do banco e permite que o Laravel registre quais mudanças já executou. Ela não é o arquivo do banco nem uma cópia de segurança. A migration fornecida cria a tabela se necessário, preserva dados existentes e inclui a linha inicial somente quando ela não existe.

Antes de executar, faça a cópia do seu arquivo dados/cafe-aurora.sqlite com o servidor parado. Na raiz, execute php src/inicializar-banco.php se estiver começando por um checkpoint sem banco. Esse preparo já é conhecido do Web II. Depois execute php artisan migrate. Não use migrate:fresh: esse comando pode apagar tabelas e não faz parte desta sequência.

Do registro ao objeto e às telas

O model AtendimentoAtual informa ao Laravel qual tabela representa. Seus casts convertem a situação para booleano e o prazo para inteiro, preservando null. Quando pedimos mensagens, ele reutiliza nossa classe AvisoAtendimento. Não criamos uma segunda regra de prazo no controller.

Conferir app/Models/AtendimentoAtual.php

Caminho a partir da raiz da aplicação. Abra o arquivo no VS Code e compare com a explicação desta etapa.

<?php
namespace App\Models;
use Illuminate\Database\Eloquent\Model;

class AtendimentoAtual extends Model
{
    protected $table = 'atendimento';
    public $timestamps = false;
    protected $fillable = ['nome', 'aberto', 'minutos'];
    protected function casts(): array { return ['aberto' => 'boolean', 'minutos' => 'integer']; }

    public function mensagens(): array
    {
        require_once base_path('src/AvisoAtendimento.php');
        return (new \AvisoAtendimento($this->nome, $this->aberto, $this->minutos))->mensagens();
    }
}

Para que o PHP já existente e o Laravel encontrem a mesma informação, o repositório cuida de ler e gravar a linha. Repositório, aqui, é um arquivo de funções que conversa com o banco; não é o repositório GitHub. As consultas preparadas recebem valores separados do SQL.

<?php
require_once __DIR__ . "/banco.php";
require_once __DIR__ . "/AvisoAtendimento.php";

function prepararAtendimento(PDO $pdo): void
{
    $pdo->exec("CREATE TABLE IF NOT EXISTS atendimento (
        id INTEGER PRIMARY KEY CHECK(id = 1),
        nome TEXT NOT NULL CHECK(length(nome) BETWEEN 1 AND 100),
        aberto INTEGER NOT NULL CHECK(aberto IN (0, 1)),
        minutos INTEGER CHECK(minutos IS NULL OR minutos BETWEEN 0 AND 240)
    )");
    $pdo->exec("INSERT OR IGNORE INTO atendimento(id, nome, aberto, minutos) VALUES(1, 'Café Aurora', 1, 30)");
}

function lerConfiguracaoAtendimento(PDO $pdo): array
{
    $linha = $pdo->query("SELECT nome, aberto, minutos FROM atendimento WHERE id = 1")->fetch();
    if (!$linha) {
        throw new RuntimeException("Prepare a tabela de atendimento pelo terminal.");
    }
    return ["nomeNegocio" => $linha["nome"], "pedidosAbertos" => (bool) $linha["aberto"],
        "tempoEstimado" => $linha["minutos"] === null ? null : (int) $linha["minutos"]];
}

function conferirConfiguracaoAtendimento(mixed $dados): AvisoAtendimento
{
    if (!is_array($dados) || array_is_list($dados) ||
        array_diff(array_keys($dados), ["nomeNegocio", "pedidosAbertos", "tempoEstimado"]) ||
        !isset($dados["nomeNegocio"], $dados["pedidosAbertos"]) ||
        !array_key_exists("tempoEstimado", $dados) ||
        !is_string($dados["nomeNegocio"]) || !is_bool($dados["pedidosAbertos"]) ||
        ($dados["tempoEstimado"] !== null && !is_int($dados["tempoEstimado"]))) {
        throw new InvalidArgumentException("Confira os três campos e seus tipos.");
    }
    return new AvisoAtendimento(trim($dados["nomeNegocio"]), $dados["pedidosAbertos"], $dados["tempoEstimado"]);
}

function salvarConfiguracaoAtendimento(PDO $pdo, AvisoAtendimento $atendimento): void
{
    $consulta = $pdo->prepare("UPDATE atendimento SET nome = :nome, aberto = :aberto, minutos = :minutos WHERE id = 1");
    $consulta->bindValue(":nome", $atendimento->nomeNegocio);
    $consulta->bindValue(":aberto", (int) $atendimento->pedidosAbertos, PDO::PARAM_INT);
    $consulta->bindValue(":minutos", $atendimento->tempoEstimado,
        $atendimento->tempoEstimado === null ? PDO::PARAM_NULL : PDO::PARAM_INT);
    $consulta->execute();
}

Execute php tests/alterar-localmente.php na raiz. Com o servidor Laravel em execução, consulte /atendimento, /api/atendimento.php e o balcão. O prazo deve ser 47 minutos. Pare e reinicie o servidor: o dado precisa permanecer. Execute o preparo novamente e confirme que não voltou sozinho para 30.

Abra também a área de mensagens do Web II e confira que os registros anteriores continuam presentes. O checkpoint de download não carrega mensagens particulares, banco ou credenciais: ele permite reconstruir uma referência limpa, não substituir seus dados.

Persistiu sem contrariar a regra?

Confira aberto com prazo, aberto sem prazo e encerrado. Para os dois últimos testes, altere os valores no script local; não edite as frases de saída. Zero é válido, negativo é recusado. Guarde as evidências do antes e depois. O próximo problema já apareceu: se a equipe poderá editar por uma tela, precisamos reconhecer quem está autorizado.
