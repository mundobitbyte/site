A gravação precisa ser confirmada

Web III — Em desenvolvimento.

Já sabemos quem pode alterar e quais valores o serviço aceita. Marina pode finalmente usar um formulário para informar o prazo, sem abrir o arquivo de programação.

Vamos reaproveitar os mesmos três dados. Nome, situação e minutos são configuração; as frases mostradas ao cliente continuam sendo preparadas depois.

Preparar os arquivos desta etapa

Baixar a referência da etapa 4. Ela contém a aplicação ao final desta etapa; não é uma nova tarefa nem uma substituição automática da sua solução.

Continue na sua pasta de trabalho que concluiu a etapa 3 deste percurso. A raiz é o lugar onde aparecem public e cliente-balcao. Não crie uma pasta cafe-aurora-web3 dentro dessa raiz.

  1. Salve os arquivos e pare o servidor antes de copiar dados. Preserve uma cópia da pasta atual.
  2. Extraia o download em uma pasta de referência separada. Abra o LEIA-ME-ETAPA.md que está dentro de cafe-aurora-web3.
  3. Compare os caminhos listados abaixo com sua pasta de trabalho. Acrescente os arquivos de apoio que ainda não existem. Para um arquivo já existente, compare a alteração antes de aplicá-la: não apague uma mudança sua sem entender a diferença. Os arquivos discutidos na aula são os que vamos construir e compreender.

Mantenha sua pasta dados-emuladores: ela não vem no download. Antes de trocar configurações ou executar os testes, encerre com Ctrl+C e aguarde a exportação. Depois use npm run retomar para recuperar os dados já guardados.

Já começou com uma referência que não tinha o comando retomar?

Se npm run retomar informar “Missing script”, não recomece o Café. Essa cópia ainda usa os comandos da referência anterior. Antes de fechar os emuladores antigos, abra outro terminal na mesma raiz, com as ferramentas locais já instaladas, e guarde a sessão:

npx firebase emulators:export ./dados-emuladores --project demo-cafe-aurora-web3

Aguarde a conclusão e confira dados-emuladores/firebase-export-metadata.json. Se já houver uma exportação, confira qual cópia quer preservar antes de confirmar sua substituição. Então encerre o terminal antigo com Ctrl+C.

Compare o package.json e o .gitignore do download desta etapa com os seus. Incorpore os scripts emuladores e retomar e a exclusão de dados-emuladores, preservando as demais configurações. Agora execute npm run retomar e confira o atendimento antes de continuar.

Se os emuladores já estavam fechados e não existe exportação, essa sessão não pode ser recuperada por trocar um comando. O início e o preparo da primeira etapa recriam apenas os dados iniciais; uma imagem ou descrição não exportada terá de ser refeita. Sua aplicação e seus arquivos-fonte continuam preservados.

Conferir cliente-balcao/src/operador.ts

Caminho a partir da raiz da aplicação. Abra o arquivo no VS Code e compare com a explicação desta etapa.

import { onAuthStateChanged, signInWithEmailAndPassword, signOut } from "firebase/auth";
import { doc,getDocFromServer } from "firebase/firestore";
import { auth,banco } from "./servico.js";
import { alterarAtendimento } from "./dados.js";
import { conferirConfiguracao } from "./atendimento.js";
import { elemento,comPrazo } from "./tela.js";

const login = document.querySelector<HTMLFormElement>("#entrar");
const formulario = document.querySelector<HTMLFormElement>("#alterar");
const retorno = document.querySelector<HTMLElement>("#retorno-operador");
login?.addEventListener("submit", async evento => {
  evento.preventDefault(); const botao = login.querySelector<HTMLButtonElement>("button")!; botao.disabled = true;
  try {
    await signInWithEmailAndPassword(auth,elemento<HTMLInputElement>("#email").value,elemento<HTMLInputElement>("#senha").value);
    elemento<HTMLInputElement>("#senha").value = "";
    if (retorno) retorno.textContent = "Identidade reconhecida. A permissão será conferida pelo serviço.";
  } catch { if (retorno) retorno.textContent = "Entrada não confirmada. Confira os dados e o emulador de identidade."; }
  finally { botao.disabled = false; }
});
document.querySelector("#sair")?.addEventListener("click", async () => {
  try { await signOut(auth); if (retorno) retorno.textContent = "Você saiu do Café."; }
  catch { if (retorno) retorno.textContent = "Não foi possível confirmar a saída."; }
});
onAuthStateChanged(auth, async usuario => {
  const identidade = document.querySelector("#identidade");
  if (identidade) identidade.textContent = usuario ? `Identidade: ${usuario.email}.` : "Visitante: consulta pública disponível.";
  const campos = formulario?.querySelector<HTMLFieldSetElement>("fieldset");
  if (campos) campos.disabled = true;
  const sessao = usuario?.uid;
  if (!usuario || !formulario) return;
  try {
    const token = await usuario.getIdTokenResult();
    if (token.claims.operador !== true) { if (retorno) retorno.textContent = "Sua identidade permite consultar, mas não alterar."; return; }
    const foto = await comPrazo(getDocFromServer(doc(banco,"atendimento","atual")));
    if (auth.currentUser?.uid !== sessao) return;
    const d = conferirConfiguracao(foto.data());
    elemento<HTMLInputElement>("#nome").value = d.nomeNegocio;
    elemento<HTMLSelectElement>("#aberto").value = d.pedidosAbertos ? "1" : "0";
    elemento<HTMLInputElement>("#minutos").value = d.tempoEstimado === null ? "" : String(d.tempoEstimado);
    if (campos) campos.disabled = false;
  } catch { if (retorno) retorno.textContent = "Configuração não confirmada. Entre novamente ou confira o serviço."; }
});
formulario?.addEventListener("submit", async evento => {
  evento.preventDefault(); const botao = formulario.querySelector<HTMLButtonElement>("button")!; botao.disabled = true;
  const minutos = elemento<HTMLInputElement>("#minutos").value.trim();
  try {
    const dados = conferirConfiguracao({ nomeNegocio: elemento<HTMLInputElement>("#nome").value.trim(),pedidosAbertos:elemento<HTMLSelectElement>("#aberto").value === "1",tempoEstimado:minutos === "" ? null : Number(minutos) });
    if (retorno) retorno.textContent = "Aguardando confirmação da gravação…";
    await alterarAtendimento(dados);
    if (retorno) retorno.textContent = "Alteração confirmada. Consulte a outra tela para conferir.";
  } catch { if (retorno) retorno.textContent = "Alteração não confirmada. Confira os campos, a permissão e a conexão antes de tentar novamente."; }
  finally { botao.disabled = false; }
});

O código lê os dados do servidor e os confere. A variável que identifica a sessão impede apresentar uma resposta privada depois que a pessoa saiu ou mudou de identidade durante a espera.

Conferir cliente-balcao/src/dados.ts

Caminho a partir da raiz da aplicação. Abra o arquivo no VS Code e compare com a explicação desta etapa.

import { doc, getDocFromServer, onSnapshot, updateDoc } from "firebase/firestore";
import { banco } from "./servico.js";
import { conferirConfiguracao, prepararMensagens } from "./atendimento.js";
import type { Atendimento, Configuracao } from "./atendimento.js";

const referencia = doc(banco, "atendimento", "atual");
export async function obterAtendimento(): Promise<Atendimento> {
  const foto = await getDocFromServer(referencia);
  if (foto.metadata.hasPendingWrites) throw new Error("Aguardando confirmação do serviço.");
  if (!foto.exists()) throw new Error("Prepare o atendimento do exercício.");
  return prepararMensagens(conferirConfiguracao(foto.data()));
}

export async function alterarAtendimento(dados: Configuracao): Promise<void> {
  await updateDoc(referencia, { ...conferirConfiguracao(dados) });
}

updateDoc atualiza o documento de atendimento já preparado. A mensagem de confirmação aparece depois de a gravação ser aceita pelo serviço. Durante uma falha de rede, não podemos anunciar que a alteração já foi confirmada apenas porque ela apareceu em uma cópia local.

Deixe minutos em branco e salve. O código converte vazio para null, que significa ausência de estimativa. Depois informe zero. Ao fechar os pedidos, a mensagem de encerramento deve prevalecer sobre o prazo.

O formulário não substitui a regra

Saia e entre como leitor. A consulta pública continua acessível, mas os controles de alteração não devem ser liberados. Os testes da etapa anterior verificam também a recusa no serviço, independentemente desses controles.

Informe um valor fora do intervalo e confirme a recusa. Repita npm test com os emuladores de uso parados, depois retome e prepare a bancada. Registre separadamente a orientação do formulário e a decisão das regras.

A outra tela recebeu o dado salvo?

Comprove alteração autorizada, recusa de leitor, zero, ausência e encerramento. A página do visitante ainda depende do botão para pedir a informação atual. Na próxima etapa, ela poderá acompanhar mudanças enquanto estiver aberta.
