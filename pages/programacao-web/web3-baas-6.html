Web III · Serviços com Firebase

A foto tem um lugar e uma referência

Web III — Em desenvolvimento.

A foto do café coado precisa ser atualizada. O formulário de atendimento guarda textos, booleanos e números; uma imagem é um arquivo binário. Guardar tudo no mesmo documento de dados confundiria responsabilidades.

Vamos usar Storage para o arquivo e Firestore para a referência que liga esse arquivo ao produto. A imagem original continua disponível enquanto a nova não for confirmada.

Preparar os arquivos desta etapa

Baixar a referência da etapa 6. Ela contém a aplicação ao final desta etapa; não é uma nova tarefa nem uma substituição automática da sua solução.

Continue na sua pasta de trabalho que concluiu a etapa 5 deste percurso. A raiz é o lugar onde aparecem public e cliente-balcao. Não crie uma pasta cafe-aurora-web3 dentro dessa raiz.

  1. Salve os arquivos e pare o servidor antes de copiar dados. Preserve uma cópia da pasta atual.
  2. Extraia o download em uma pasta de referência separada. Abra o LEIA-ME-ETAPA.md que está dentro de cafe-aurora-web3.
  3. Compare os caminhos listados abaixo com sua pasta de trabalho. Acrescente os arquivos de apoio que ainda não existem. Para um arquivo já existente, compare a alteração antes de aplicá-la: não apague uma mudança sua sem entender a diferença. Os arquivos discutidos na aula são os que vamos construir e compreender.

Mantenha sua pasta dados-emuladores: ela não vem no download. Antes de trocar configurações ou executar os testes, encerre com Ctrl+C e aguarde a exportação. Depois use npm run retomar para recuperar os dados já guardados.

Envie uma imagem do produto

Acrescente os arquivos da etapa e faça o build. Encerre os emuladores com Ctrl+C, aguarde a exportação e use npm run retomar para importar os dados e carregar também Storage. Entre como operador; o preparo inicial não precisa ser repetido em uma sessão importada. No balcão, escolha uma imagem fictícia de café, em PNG, JPEG ou WebP, de até 2 MiB, e escreva a descrição conhecida do produto. Para testar sem procurar outra foto, você pode selecionar public/img/cafe-coado.webp do próprio projeto. Nesse caso a aparência será igual; a confirmação virá da gravação, do caminho no serviço e da descrição consultada no cardápio.

Conferir cliente-balcao/src/imagens.ts

Caminho a partir da raiz da aplicação. Abra o arquivo no VS Code e compare com a explicação desta etapa.

import { ref, uploadBytes, getDownloadURL, deleteObject } from "firebase/storage";
import { doc, setDoc } from "firebase/firestore";
import { armazenamento, banco, auth } from "./servico.js";

export async function enviarImagem(arquivo: File, descricao: string): Promise<string> {
  const usuario = auth.currentUser;
  if (!usuario) throw new Error("Entre como operador para enviar imagem.");
  if (!["image/png", "image/jpeg", "image/webp"].includes(arquivo.type) || arquivo.size === 0 || arquivo.size > 2 * 1024 * 1024) throw new Error("Escolha PNG, JPEG ou WebP de até 2 MiB.");
  const caminho = `imagens/${usuario.uid}/${crypto.randomUUID()}`;
  const objeto = ref(armazenamento, caminho);
  await uploadBytes(objeto, arquivo, { contentType: arquivo.type });
  try {
    await setDoc(doc(banco, "produtos", "cafe-coado"), { nome: "Café coado", descricao, imagemCaminho: caminho });
  } catch (erro) {
    await deleteObject(objeto).catch(() => {});
    throw erro;
  }
  return getDownloadURL(objeto);
}

O caminho inclui a identidade do operador e um identificador aleatório. Não usamos o nome digitado do arquivo como endereço confiável. A extensão e o tipo declarado ajudam a filtrar a entrada; a regra de Storage também verifica permissão, tamanho e tipo permitido.

Conferir storage.rules

Caminho a partir da raiz da aplicação. Abra o arquivo no VS Code e compare com a explicação desta etapa.

rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    match /imagens/{uid}/{id} {
      allow read: if true;
      allow create: if resource == null && request.auth != null && request.auth.uid == uid
        && request.auth.token.operador == true
        && id.matches('[a-zA-Z0-9_-]+')
        && request.resource.size > 0 && request.resource.size <= 2 * 1024 * 1024
        && request.resource.contentType.matches('image/(png|jpeg|webp)');
      allow update: if false;
      allow delete: if request.auth != null && request.auth.uid == uid && request.auth.token.operador == true;
    }
  }
}

O exemplo não permite sobrescrever um objeto já existente pelo cliente. Uma nova foto recebe outro identificador. As imagens desta bancada são públicas e fictícias; não use esse mesmo desenho para documentos ou fotos pessoais que precisem de acesso restrito.

Relacione o arquivo com o produto

Depois do upload, o código grava em produtos/cafe-coado o nome, a descrição e imagemCaminho. Não grava o conteúdo inteiro da imagem nesse documento. Se a associação falhar, tenta remover o arquivo enviado; isso é uma compensação entre serviços, não uma transação atômica que garanta os dois passos de uma vez.

import { ref,getDownloadURL } from "firebase/storage";
import { banco,armazenamento } from "./servico.js";

const formulario = document.querySelector<HTMLFormElement>("#imagem-produto");
async function conferirImagem(): Promise<void> {
  const foto = await comPrazo(getDocFromServer(doc(banco,"produtos","cafe-coado")));
  if (!foto.exists()) return;
  const d: unknown = foto.data();
  if (typeof d !== "object" || d === null || !("imagemCaminho" in d) || typeof d.imagemCaminho !== "string" || !/^imagens\/[a-zA-Z0-9_-]+\/[a-zA-Z0-9_-]+$/.test(d.imagemCaminho)) throw new Error();

}
document.querySelector("#consultar-imagem")?.addEventListener("click", () => { conferirImagem().catch(()=>{elemento("#retorno-imagem").textContent="Imagem não confirmada. A apresentação anterior foi preservada.";}); });
formulario?.addEventListener("submit", async evento => {
  evento.preventDefault(); const botao = formulario.querySelector<HTMLButtonElement>("button")!; botao.disabled=true;
  try {
    const arquivo=elemento<HTMLInputElement>("#arquivo-imagem").files?.[0]; if (!arquivo) throw new Error("Escolha um arquivo.");
    const descricao=elemento<HTMLInputElement>("#descricao-imagem").value.trim();
    if (descricao.length<10 || descricao.length>400) throw new Error("Escreva uma descrição de 10 a 400 caracteres.");
    await enviarImagem(arquivo,descricao); await conferirImagem(); elemento("#retorno-imagem").textContent="Arquivo e referência confirmados. Confira a imagem.";

Caminho a partir da raiz da aplicação. Abra o arquivo no VS Code e compare com a explicação desta etapa.

import { doc, getDocFromServer } from "firebase/firestore";
import { ref, getDownloadURL } from "firebase/storage";
import { banco, armazenamento } from "./servico.js";
import { comPrazo } from "./tela.js";
import { aplicarProdutoConfirmado } from "./catalogo-interface.js";

const botao = document.querySelector<HTMLButtonElement>("#consultar-midia-cardapio");
botao?.addEventListener("click", async () => {
  const retorno = document.querySelector<HTMLElement>("#retorno-midia-cardapio")!;
  botao.disabled = true;
  retorno.textContent = "Conferindo a atualização enviada pela equipe…";
  try {
    const documento = await comPrazo(getDocFromServer(doc(banco, "produtos", "cafe-coado")));
    if (!documento.exists()) { retorno.textContent = "Ainda não há outra foto. O cardápio conhecido foi preservado."; return; }
    const d: unknown = documento.data();
    if (typeof d !== "object" || d === null || !("imagemCaminho" in d) || typeof d.imagemCaminho !== "string" ||
        !/^imagens\/[a-zA-Z0-9_-]+\/[a-zA-Z0-9_-]+$/.test(d.imagemCaminho) ||
        !("descricao" in d) || typeof d.descricao !== "string" || d.descricao.length < 10 || d.descricao.length > 400 ||
        !("nome" in d) || typeof d.nome !== "string" || d.nome.trim().length === 0 || d.nome.length > 100) throw new Error("Referência de produto inválida.");
    const endereco = await comPrazo(getDownloadURL(ref(armazenamento, d.imagemCaminho)));
    aplicarProdutoConfirmado({nome:d.nome,descricao:d.descricao,enderecoImagem:endereco});
  } catch {
    retorno.textContent = "Não foi possível conferir a foto. O cardápio conhecido continua disponível.";
  } finally { botao.disabled = false; }
});
Conferir cliente-balcao/src/catalogo-interface.ts

Caminho a partir da raiz da aplicação. Abra o arquivo no VS Code e compare com a explicação desta etapa.

interface ProdutoConfirmado { nome: string; descricao: string; enderecoImagem: string }

export function aplicarProdutoConfirmado(dados: ProdutoConfirmado, raiz: ParentNode = document): void {
  const card=raiz.querySelector('[data-produto="cafe-coado"]');
  const imagem=card?.querySelector<HTMLImageElement>('img');
  const titulo=card?.querySelector('h3');
  const descricao=card?.querySelector<HTMLElement>('[data-descricao-produto]');
  const retorno=raiz.querySelector<HTMLElement>('#retorno-midia-cardapio');
  if(!imagem || !titulo || !descricao || !retorno) throw new Error('Aguarde o cardápio e consulte novamente.');
  const preco=descricao.querySelector('strong');
  titulo.textContent=dados.nome;
  descricao.textContent=dados.descricao+' ';
  if(preco)descricao.append(preco);
  const anterior=imagem.src;
  imagem.onerror=()=>{imagem.onerror=null;imagem.src=anterior;retorno.textContent='Texto confirmado; a foto não carregou e a imagem anterior foi preservada.';};
  imagem.src=dados.enderecoImagem;
  retorno.textContent='Texto e referência da foto recebidos do serviço. Confira o carregamento da imagem.';
}

Se o serviço não confirmar a referência ou a imagem não carregar, a apresentação anterior é preservada com uma orientação. Receber um endereço de download não comprova que o arquivo já apareceu na tela.
