Aviso local não é push remoto

Web III — Em desenvolvimento.

A assinatura atualiza o atendimento enquanto a página acompanha o serviço. Um aviso fora dessa experiência exige outro caminho: permissão do navegador, inscrição e mensageria. Não é a mesma coisa que receber um onSnapshot.

Vamos separar uma notificação local de um envio push real. A primeira pode ajudar a observar a autorização do navegador; a segunda depende de serviços e de um ambiente que não faz parte do nosso emulador.

Preparar os arquivos desta etapa

Baixar a referência da etapa 9. Ela contém a aplicação ao final desta etapa; não é uma nova tarefa nem uma substituição automática da sua solução.

Se você já tinha uma bancada em uso na referência anterior, confira a orientação abaixo antes de encerrar os emuladores. Primeiro guardamos a sessão; depois atualizamos os arquivos.

Já começou com uma referência que não tinha o comando retomar?

Se npm run retomar informar “Missing script”, não recomece o Café. Essa cópia ainda usa os comandos da referência anterior. Antes de fechar os emuladores antigos, abra outro terminal na mesma raiz, com as ferramentas locais já instaladas, e guarde a sessão:

npx firebase emulators:export ./dados-emuladores --project demo-cafe-aurora-web3

Aguarde a conclusão e confira dados-emuladores/firebase-export-metadata.json. Se já houver uma exportação, confira qual cópia quer preservar antes de confirmar sua substituição. Então encerre o terminal antigo com Ctrl+C.

Compare o package.json e o .gitignore do download desta etapa com os seus. Incorpore os scripts emuladores e retomar e a exclusão de dados-emuladores, preservando as demais configurações. Agora execute npm run retomar e confira o atendimento antes de continuar.

Se os emuladores já estavam fechados e não existe exportação, essa sessão não pode ser recuperada por trocar um comando. O início e o preparo da primeira etapa recriam apenas os dados iniciais; uma imagem ou descrição não exportada terá de ser refeita. Sua aplicação e seus arquivos-fonte continuam preservados.

Continue na sua pasta de trabalho que concluiu a etapa 8 deste percurso. A raiz é o lugar onde aparecem public e cliente-balcao. Não crie uma pasta cafe-aurora-web3 dentro dessa raiz.

  1. Salve os arquivos e pare o servidor antes de copiar dados. Preserve uma cópia da pasta atual.
  2. Extraia o download em uma pasta de referência separada. Abra o LEIA-ME-ETAPA.md que está dentro de cafe-aurora-web3.
  3. Compare os caminhos listados abaixo com sua pasta de trabalho. Acrescente os arquivos de apoio que ainda não existem. Para um arquivo já existente, compare a alteração antes de aplicá-la: não apague uma mudança sua sem entender a diferença. Os arquivos discutidos na aula são os que vamos construir e compreender.

Mantenha sua pasta dados-emuladores: ela não vem no download. Antes de trocar configurações ou executar os testes, encerre com Ctrl+C e aguarde a exportação. Depois use npm run retomar para recuperar os dados já guardados.

Observe a autorização sem prometer um envio remoto

Faça os builds do cliente e das Functions e retome os emuladores. No balcão, use “Experimentar notificação local” se quiser verificar esse recurso. A solicitação só ocorre depois do clique. Você pode recusar e continuar consultando o Café normalmente.

Quando permitido e suportado, o próprio navegador cria um aviso identificado como demonstração local. Ele não chegou do Firebase Cloud Messaging e não comprova entrega com a página fechada. A interface também informa falta de suporte ou recusa.

Conferir cliente-balcao/src/notificacoes.ts

Caminho a partir da raiz da aplicação. Abra o arquivo no VS Code e compare com a explicação desta etapa.

import { isSupported,getMessaging,getToken,deleteToken } from "firebase/messaging";
import { doc,setDoc,deleteDoc } from "firebase/firestore";
import { httpsCallable } from "firebase/functions";
import { app,auth,banco,funcoes } from "./servico.js";
import { modo,chaveVapid } from "./ambiente.js";
import { elemento } from "./tela.js";

document.querySelector("#notificacao-local")?.addEventListener("click", async () => {
  const retorno=elemento("#retorno-avisos");
  if (!("Notification" in window) || !window.isSecureContext) { retorno.textContent="Notificação local indisponível neste navegador/contexto. A consulta continua funcionando."; return; }
  try {
    const permissao=await Notification.requestPermission();
    if(permissao!=="granted") { retorno.textContent="Você não autorizou a demonstração local. Nenhum envio push foi realizado."; return; }
    new Notification("Café Aurora — demonstração local", {body:"Este aviso foi criado neste navegador. Não veio do Firebase Cloud Messaging."});
    retorno.textContent="Notificação local solicitada ao navegador. Não houve envio pelo FCM; confira separadamente se o sistema a exibiu.";
  } catch { retorno.textContent="O navegador não confirmou a notificação local. A consulta continua disponível."; }
});

document.querySelector("#permitir-avisos")?.addEventListener("click",async()=>{
  const retorno=elemento("#retorno-avisos");
  if(modo!=="nuvem"||!chaveVapid){retorno.textContent="O envio real não é emulado. Use um ambiente HTTPS de mensageria aprovado para esta etapa.";return;}
  if(!auth.currentUser){retorno.textContent="Entre antes de inscrever este navegador.";return;}
  try{
    if(!(await isSupported())){retorno.textContent="Navegador sem suporte à mensageria. A consulta do Café continua disponível.";return;}
    const permissao=await Notification.requestPermission();
    if(permissao!=="granted"){retorno.textContent="Avisos não autorizados. Você pode continuar consultando o Café.";return;}
    const registro=await navigator.serviceWorker.register("/firebase-messaging-sw.js");
    await navigator.serviceWorker.ready;
    const token=await getToken(getMessaging(app),{vapidKey:chaveVapid,serviceWorkerRegistration:registro});
    if(!token)throw new Error();
    await setDoc(doc(banco,"inscricoes",auth.currentUser.uid),{token});
    retorno.textContent="Navegador inscrito. Isso ainda não comprova envio ou recebimento.";
  }catch{retorno.textContent="Inscrição não confirmada. A consulta do Café continua disponível.";}
});
document.querySelector("#enviar-aviso")?.addEventListener("click",async()=>{
  try{await httpsCallable(funcoes,"enviarAviso",{timeout:20000})({});elemento("#retorno-avisos").textContent="Serviço aceitou o envio para este operador. Confira separadamente a chegada ao navegador.";}
  catch{elemento("#retorno-avisos").textContent="Envio real não confirmado. Confira o ambiente, a inscrição e a permissão.";}
});
document.querySelector("#revogar-avisos")?.addEventListener("click",async()=>{
  try{
    if(auth.currentUser)await deleteDoc(doc(banco,"inscricoes",auth.currentUser.uid));
    if(modo==="nuvem"&&await isSupported())await deleteToken(getMessaging(app));
    elemento("#retorno-avisos").textContent="Inscrição removida para esta identidade. A permissão do navegador pode ser revista nas configurações do site.";
  }catch{elemento("#retorno-avisos").textContent="Remoção não confirmada. Tente novamente.";}
});

Leia o trajeto do push real

O código de integração real verifica suporte, pede permissão após uma ação, registra um service worker e solicita um token de inscrição. O token identifica uma inscrição de navegador; não deve aparecer em uma lista pública de clientes. O serviço guarda a inscrição somente para sua identidade.

Conferir cliente-balcao/src/mensageria-sw.js

Caminho a partir da raiz da aplicação. Abra o arquivo no VS Code e compare com a explicação desta etapa.

import { initializeApp } from "firebase/app";
import { getMessaging,onBackgroundMessage } from "firebase/messaging/sw";
import { modo,configuracao } from "./ambiente.ts";
if (modo === "nuvem") {
  const mensageria = getMessaging(initializeApp(configuracao));
  onBackgroundMessage(mensageria, async mensagem => {
    const d = mensagem.data;
    if (!d || typeof d.title !== "string" || typeof d.body !== "string") return;
    await self.registration.showNotification(d.title.slice(0,100), { body: d.body.slice(0,300), tag: "atendimento-cafe", data: { url: "/balcao.html" } });
  });
  self.addEventListener("notificationclick", evento => {
    evento.notification.close();
    evento.waitUntil(self.clients.openWindow(new URL("/balcao.html",self.location.origin).href));
  });
}

Um service worker é um script com um contexto próprio, usado aqui para tratar mensagens em segundo plano. Ele tem outro arquivo de saída, public/firebase-messaging-sw.js, preparado pelo segundo build. Não é o mesmo main.js da página.

No modo local, “Permitir avisos neste navegador” informa que o envio remoto não foi emulado. “Enviar um aviso de teste para mim” também deve ser recusado pela função. Não trocamos essa recusa por uma mensagem falsa de envio concluído.

Faça o registro corresponder ao que ocorreu

Um teste real exige projeto configurado, origem segura, inscrição válida, chave pública VAPID e serviço de envio preparado pelo professor. O código limita o ensaio ao próprio operador. Aceitação pelo serviço não comprova que o navegador recebeu ou que a pessoa leu.

Sem esse ambiente, registre “push real não executado”. A prática local permite examinar suporte, consentimento e alternativas. O atendimento continua utilizável sem notificação; não pressionamos o cliente a autorizar um recurso para consultar o Café.

Você consegue distinguir os três acontecimentos?

Explique atualização na página, notificação local e push remoto. Registre suporte e escolha de permissão se os testou. Demonstre a recusa explícita de envio remoto no emulador. Na última etapa, outra integração exigirá o mesmo cuidado com a origem do resultado: um rascunho de texto não pode ser confundido com uma publicação confiável.
