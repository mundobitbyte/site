E se a orientação de prazo não vier?

O botão já apresenta os três textos nos lugares certos. Na última experiência, você conseguiu distinguir o objeto local da resposta PHP. Falta uma conferência antes de trocar a origem dos dados.

Antes de alterar o arquivo, faça uma conferência curta: em cliente-balcao/src/atendimento.ts, retire somente a linha mensagemTempo do objeto devolvido por obterAtendimento. Mantenha a interface como está. No terminal de cliente-balcao, execute npm run build.

O verificador apontou o campo ausente? Recoloque a linha e gere novamente. Ele conseguiu proteger um objeto que nós escrevemos. Vamos investigar o que muda quando a entrada precisa ser conferida durante a execução.

Imagine que uma alteração no servidor deixe de devolver mensagemTempo. A interface TypeScript descreve o formato esperado, mas essa descrição não inspeciona automaticamente uma resposta recebida durante a execução. O balcão não pode apresentar “undefined” como se fosse uma orientação.

Vamos ensaiar esse caso na mesma cópia, ainda sem rede. Prepararemos uma entrada que pode ter qualquer formato, conferiremos os campos e só depois a entregaremos à função de apresentação.

Desconhecido não significa liberado

O tipo unknown diz: “ainda não sabemos o formato deste valor”. Ao contrário de afirmar Atendimento, ele não permite ler os campos antes de conferi-los. É uma maneira de representar a entrada que precisa ser examinada.

Nossa nova função conferirAtendimento recebe unknown e só devolve Atendimento se encontrar os três textos. Se recusar a entrada, usa throw new Error(...), como a guarda dos elementos na aula anterior. A ação do botão receberá esse erro e mostrará uma orientação.

Antes de escrever, acompanhe os motivos da recusa:

  1. typeof dados !== "object" recusa números, textos e outros valores que não são objetos. null também precisa de uma verificação própria: em JavaScript, seu typeof é "object".
  2. Array.isArray(dados) identifica arrays, que também são objetos, mas não são a resposta de três campos que combinamos.
  3. "nomeNegocio" in dados pergunta se a propriedade existe. O ! nega esse resultado; só lemos o valor depois de verificar a presença.
  4. typeof dados.nomeNegocio !== "string" recusa outro tipo. trim() retira espaços nas pontas; compará-lo com "" recusa um texto vazio ou só com espaços.

O || reúne motivos de recusa. A avaliação para no primeiro verdadeiro; por isso a ordem importa. Repetiremos a conferência para mensagemStatus e mensagemTempo. No retorno, construiremos um objeto apenas com os três campos aceitos.

Em cliente-balcao/src/atendimento.ts, mantenha a interface e complete o arquivo assim:

export interface Atendimento {
  nomeNegocio: string;
  mensagemStatus: string;
  mensagemTempo: string;
}

export function conferirAtendimento(dados: unknown): Atendimento {
  if (typeof dados !== "object" || dados === null || Array.isArray(dados)) {
    throw new Error("A resposta precisa ser um objeto.");
  }
  if (!("nomeNegocio" in dados) || typeof dados.nomeNegocio !== "string" || dados.nomeNegocio.trim() === "") {
    throw new Error("Nome do negócio ausente ou inválido.");
  }
  if (!("mensagemStatus" in dados) || typeof dados.mensagemStatus !== "string" || dados.mensagemStatus.trim() === "") {
    throw new Error("Mensagem de situação ausente ou inválida.");
  }
  if (!("mensagemTempo" in dados) || typeof dados.mensagemTempo !== "string" || dados.mensagemTempo.trim() === "") {
    throw new Error("Mensagem de prazo ausente ou inválida.");
  }
  return {
    nomeNegocio: dados.nomeNegocio,
    mensagemStatus: dados.mensagemStatus,
    mensagemTempo: dados.mensagemTempo,
  };
}

export function obterAtendimento(): Atendimento {
  const dados: unknown = {
    nomeNegocio: "Café Aurora",
    mensagemStatus: "Pedidos para retirada estão abertos.",
    mensagemTempo: "Tempo estimado: 30 minutos.",
  };
  return conferirAtendimento(dados);
}

Observe a mudança em obterAtendimento: agora ela prepara dados: unknown e entrega essa entrada à conferência. Por enquanto os valores continuam escritos aqui. Essa separação permitirá trocar a origem posteriormente sem refazer as verificações.

Um campo extra é ignorado na construção do retorno. A função confere o formato básico, não decide se o Café está aberto nem recalcula minutos. Essas decisões continuam no PHP quando a consulta real chegar.

O balcão precisa explicar a recusa

Se a conferência lançar um erro, a apresentação não deve seguir com dados incompletos. Vamos retomar try e catch do Web I, agora em torno do ensaio local.

Em main.ts, preserve os imports, as procuras, as guardas e a função apresentar. Substitua somente o bloco do addEventListener pelo seguinte:

botao.addEventListener("click", () => {
  try {
    apresentar(obterAtendimento());
    aviso.textContent = "Ensaio local conferido; ainda não houve consulta ao servidor.";
  } catch (erro) {
    situacao.textContent = "";
    tempo.textContent = "";
    aviso.textContent = "O ensaio recebeu dados inválidos. Confira sua tentativa.";
    console.error(erro);
  }
});

No try, conferimos e apresentamos. Se houver recusa, o catch retira situação e prazo anteriores e informa o problema. console.error(erro) ajuda a localizar o campo no Console do navegador; o visitante recebe uma frase compreensível.

Comparar o main.ts completo

Use para conferir o lugar do evento, sem trocar desnecessariamente os elementos ou o HTML.

import { obterAtendimento } from "./atendimento.js";
import type { Atendimento } from "./atendimento.js";

const nome = document.querySelector("#nome-negocio");
const situacao = document.querySelector("#mensagem-status");
const tempo = document.querySelector("#mensagem-tempo");
const botao = document.querySelector("#atualizar-atendimento");
const aviso = document.querySelector("#aviso-consulta");

if (!(nome instanceof HTMLElement) || !(situacao instanceof HTMLElement) ||
    !(tempo instanceof HTMLElement) || !(botao instanceof HTMLButtonElement) ||
    !(aviso instanceof HTMLElement)) {
  throw new Error("Confira os elementos do balcão no HTML.");
}

const apresentar = (atendimento: Atendimento) => {
  nome.textContent = atendimento.nomeNegocio;
  situacao.textContent = atendimento.mensagemStatus;
  tempo.textContent = atendimento.mensagemTempo;
};

botao.disabled = false;
botao.textContent = "Conferir apresentação";
aviso.textContent = "Ensaio local: este botão ainda não consulta o PHP.";

botao.addEventListener("click", () => {
  try {
    apresentar(obterAtendimento());
    aviso.textContent = "Ensaio local conferido; ainda não houve consulta ao servidor.";
  } catch (erro) {
    situacao.textContent = "";
    tempo.textContent = "";
    aviso.textContent = "O ensaio recebeu dados inválidos. Confira sua tentativa.";
    console.error(erro);
  }
});

Salve, gere com npm run build e recarregue o balcão. Clique em “Conferir apresentação” com a entrada válida. O resultado deve continuar igual ao da aula anterior.

Uma alteração por vez, um resultado para conferir

Em obterAtendimento, retire somente a linha mensagemTempo do objeto dados. Mantenha o tipo unknown. Salve, faça build, recarregue e clique.

Na abertura, retirar esse campo fez o build falhar. Agora o build pode passar: dados foi declarado unknown, não Atendimento. É a função de conferência que deve recusar esse formato durante a execução. O prazo antigo não fica apresentado como se fosse o resultado do ensaio.

Abra o Console e encontre “Mensagem de prazo ausente ou inválida.”. Recoloque a linha com o texto correto, gere, recarregue e clique de novo. A apresentação deve se recuperar.

Depois teste separadamente, sempre voltando ao caso válido antes do seguinte:

  • Troque a frase de prazo pelo número 30: existe um campo, mas seu tipo está errado.
  • Use " " no lugar da frase: continua sendo string, mas não informa nada.
  • Substitua o objeto de entrada por null e depois por []: ambos precisam ser recusados no primeiro teste.
  • Acrescente um campo local observacao: "ensaio": os três textos válidos continuam sendo aceitos e o campo extra não ganha um elemento na página.

As alterações são feitas somente no valor de dados dentro de obterAtendimento. Cada tentativa exige build e recarregamento. Ao terminar, restaure o objeto válido de três textos, com 30 minutos, gere e confira a recuperação.

Não resolva o problema escrevendo as Atendimento na entrada: essa afirmação não faz os campos surgirem nem valida o que chegou. A conferência precisa acontecer de verdade.

Aceitar, recusar e recuperar

Crie um caso inválido diferente dos que repetiu, mostre qual condição o recusa e corrija a entrada. Explique por que o tipo unknown não permite tratar um valor como Atendimento sem conferência e por que passar no build não garante a forma de uma resposta externa.

Conferir os arquivos ao fim da Aula 4

A referência termina com o objeto local válido. Preserve suas tentativas fora de src para que o verificador não as misture à solução em uso. O HTML e a API permanecem como antes; npm ci só é necessário para preparar uma cópia nova.

Podemos trocar a origem sem perder a conferência

A apresentação está pronta e a entrada incompleta é recusada. Agora podemos substituir o objeto local pelos dados da API. Buscar, conferir e apresentar terão papéis claros; o botão passará, enfim, a pedir o aviso atual ao PHP.
