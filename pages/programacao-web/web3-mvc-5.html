O cardápio tem relações

Web III — Em desenvolvimento.

Marina mudou o preço do café coado. O aviso está atualizado, mas o cardápio ainda guarda produtos no JSON e também possui uma apresentação antiga em HTML. Se alterarmos só um desses lugares, voltaremos ao problema de duas respostas para a mesma informação.

Vamos aproveitar os três produtos, as descrições, as imagens e as categorias que já existem. O objetivo não é inventar outro cardápio: é permitir que o mesmo cardápio seja consultado e atualizado a partir do banco.

Importe e veja os produtos conhecidos

Acrescente os arquivos desta etapa, execute php artisan migrate e depois php artisan cafe:importar-cardapio na raiz. A primeira ação acrescenta as tabelas; a segunda lê public/dados/produtos.json e inclui os produtos que ainda não existem.

Abra http://localhost:8000/cardapio. Você deve reconhecer café coado, pão artesanal e bolo de laranja com as imagens anteriores. A antiga entrada /cardapio.php redireciona para essa página, em vez de continuar mostrando preços fixos. Uma mudança só está concluída quando o visitante consegue encontrá-la.

Um produto pertence a uma categoria

A categoria “comida” aparece em dois produtos. Podemos representá-la uma vez e relacionar os produtos a ela. A tabela de produtos guarda a identificação da categoria; a chave estrangeira impede uma referência a uma categoria inexistente.

Nosso identificador de categoria é texto, como bebida, e não um número criado automaticamente. Por isso a migration declara explicitamente esse tipo e a relação. Não troque por uma chave numérica sem revisar os registros que já usam esses nomes.

Caminho a partir da raiz da aplicação. Abra o arquivo no VS Code e compare com a explicação desta etapa.

<?php
namespace App\Models;
use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\Relations\BelongsTo;

class Produto extends Model
{
    public $timestamps = false;
    public $incrementing = false;
    protected $keyType = 'string';
    protected $fillable = ['id','nome','categoria','preco_centavos','imagem','alt','descricao','disponivel'];
    protected function casts(): array { return ['preco_centavos'=>'integer','disponivel'=>'boolean']; }
    public function grupo(): BelongsTo { return $this->belongsTo(Categoria::class, 'categoria'); }
    public function dadosPublicos(): array
    {
        return ['id'=>$this->id,'nome'=>$this->nome,'categoria'=>$this->categoria,
            'precoCentavos'=>$this->preco_centavos,'imagem'=>$this->imagem,'alt'=>$this->alt,
            'descricao'=>$this->descricao,'disponivel'=>$this->disponivel];
    }
}

ORM significa mapeamento objeto-relacional. Com Eloquent, o ORM do Laravel, podemos consultar um Produto como objeto e acessar sua categoria pela relação grupo. Isso não elimina tabelas, SQL ou a necessidade de conferir consultas. Organiza a passagem entre objetos PHP e registros.

O preço passa de preco: 8, no JSON conhecido, para preco_centavos: 800, no banco. Guardar centavos inteiros evita usar frações decimais como unidade de cálculo de dinheiro neste exercício. A API publica precoCentavos; a view divide por 100 apenas ao formatar a apresentação.

Conferir app/Console/Commands/ImportarCardapio.php

Caminho a partir da raiz da aplicação. Abra o arquivo no VS Code e compare com a explicação desta etapa.

<?php
namespace App\Console\Commands;
use App\Models\Categoria;
use App\Models\Produto;
use Illuminate\Console\Command;
use Illuminate\Support\Facades\DB;

class ImportarCardapio extends Command
{
    protected $signature = 'cafe:importar-cardapio';
    protected $description = 'Importa o JSON conhecido sem sobrescrever produtos já existentes';
    public function handle(): int
    {
        $lista=json_decode(file_get_contents(public_path('dados/produtos.json')),true,32,JSON_THROW_ON_ERROR);
        DB::transaction(function () use ($lista) {
            foreach ($lista as $p) {
                Categoria::firstOrCreate(['id'=>$p['categoria']], ['nome'=>ucfirst($p['categoria'])]);
                Produto::firstOrCreate(['id'=>$p['id']], ['nome'=>$p['nome'],'categoria'=>$p['categoria'],
                    'preco_centavos'=>(int)round($p['preco']*100),'imagem'=>basename($p['imagem']),
                    'alt'=>$p['alt'],'descricao'=>$p['descricao'],'disponivel'=>true]);
            }
        });
        $this->info('Catálogo conferido. Produtos existentes foram preservados.');
        return self::SUCCESS;
    }
}

Observe firstOrCreate: localizar o produto vem antes de incluí-lo. Reexecutar a importação não deve duplicar os três produtos nem desfazer uma edição feita pela equipe. O JSON continua como origem do primeiro preenchimento, não como uma ordem para sobrescrever o banco a cada consulta.

Altere o preço e percorra o caminho inteiro

Entre como operador e abra /operador/produtos/cafe-coado. Mude 800 para 850 centavos e salve. Agora abra /cardapio como visitante: o preço deve ser R$ 8,50. Reexecute a importação e confira que continua assim.

<?php
namespace App\Http\Controllers;
use App\Models\Categoria;
use App\Models\Produto;
use Illuminate\Http\Request;
use Illuminate\Validation\Rule;

class CatalogoController
{
    public function pagina()
    {
        return view('cardapio', ['produtos'=>Produto::query()->orderBy('nome')->get()]);
    }
    public function listar(Request $r)
    {
        $entrada=$r->validate(['categoria'=>['nullable','string',Rule::exists('categorias','id')]]);
        $lista=Produto::query()->with('grupo')
            ->when($entrada['categoria']??null,fn($q,$categoria)=>$q->where('categoria',$categoria))->orderBy('nome')->get();
        return response()->json(['data'=>$lista->map(fn(Produto $p)=>$p->dadosPublicos())]);
    }
    public function editar(Produto $produto) { return view('editar-produto',['produto'=>$produto,'categorias'=>Categoria::all()]); }
    public function salvar(Request $r, Produto $produto)
    {
        $dados=$r->validate(['nome'=>['required','string','max:100'],'categoria'=>['required','string',Rule::exists('categorias','id')],
            'preco_centavos'=>['required','integer','between:0,1000000'],'descricao'=>['required','string','between:10,400'],
            'disponivel'=>['required','boolean']]);
        $produto->update($dados);
        return redirect()->route('operador.produto',$produto)->with('aviso','Produto atualizado.');
    }
}

Na API /api/produtos, o conjunto fica dentro de data. Essa é uma nova resposta do catálogo, não uma mudança no contrato do atendimento. Abra /api/produtos?categoria=bebida e compare com a lista completa. O parâmetro passa por validação antes de ser usado na consulta.

Em with('grupo'), o Laravel antecipa a consulta das categorias relacionadas. Sem esse cuidado, percorrer uma lista pode gerar uma consulta adicional para cada produto. Para perceber o problema, imagine o mesmo código com cem produtos; não precisamos criar cem registros artificiais para entender a consequência.

Uma mudança não pode se perder no trajeto

Verifique importação repetida, relação com categoria, edição autorizada e preço atualizado na página pública e na API. Confirme que uma pessoa sem sessão não altera o produto e que preço negativo é recusado. Rode composer test. Na próxima etapa, a informação que consultaremos será de outro serviço; será preciso tratar também o que o Café não controla.
