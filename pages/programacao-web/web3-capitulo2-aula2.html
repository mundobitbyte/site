Primeiro, uma mensagem dentro do balcão

A API já devolve o aviso da cozinha. Antes de ligar a consulta, vamos conferir uma ligação menor: fazer o código TypeScript escrever uma mensagem dentro da página PHP que já existe.

Continue na cópia do Café usada na Aula 1. Confirme que a API responde e que o balcão abre pelo servidor PHP. Mantenha esse servidor em execução no terminal. Se precisar reabri-lo, retome o começo da aula anterior.

Na bancada do Essencial, o Vite acompanhava suas alterações e entregava uma página de teste. Aqui o PHP já entrega a página. Precisamos gerar um arquivo JavaScript para ela carregar. Essa geração é o build. O VS Code continua sendo nosso editor.

Levar as ferramentas sem perder suas experiências

Guarde a bancada TypeScript e a pasta entregas como estão. No VS Code, mantenha aberta a pasta da aplicação PHP. Dentro dela, ao lado de public e src, crie a pasta cliente-balcao.

Da bancada, copie para cliente-balcao somente estes três arquivos:

package.json, package-lock.json e tsconfig.json

O primeiro lista os comandos e as ferramentas; o lock registra as versões exatas; o tsconfig mantém as verificações já usadas. Não copie node_modules, dist, o HTML da bancada nem sua configuração Vite antiga. O destino do build será diferente.

Crie cliente-balcao/src e copie para ela os dois arquivos que concluiu no tópico 12:

main.ts e atendimento.ts

Se você renomeou campos nos desafios, guarde ambos antes desta experiência. Vamos trabalhar com a referência de dois arquivos para comparar a mudança de formato na próxima aula.

Vou recuperar os arquivos de referência do TypeScript

Extraia o kit do TypeScript Essencial em outra pasta. O src/main.ts do ZIP é o exemplo 1. Os dois arquivos do fim do tópico 12 estão em exemplos/12/main.ts e exemplos/12/atendimento.ts. Copie esses dois para cliente-balcao/src. Os três arquivos de ferramentas estão na raiz do kit.

Essa recuperação não exige refazer o Essencial nem substituir suas soluções. Você pode rever a prática dos dois arquivos se precisar localizar o que cada um fazia.

Abra um segundo terminal no VS Code: em Terminal → Novo Terminal, deixe o primeiro executando o PHP. No terminal novo, que começa na raiz do Café, entre no cliente:

cd cliente-balcao
node --version
npm --version

O caminho agora precisa terminar em cliente-balcao, a pasta que contém package.json. O kit usa Node 24: o primeiro comando deve começar com v24.. O segundo mostra a versão do npm. Se não forem reconhecidos, retome a preparação do Essencial e confira o PATH com o professor; não instale versões diferentes por tentativa.

Com as ferramentas reconhecidas, execute nesse terminal:

npm ci

O npm instala as versões do lockfile em cliente-balcao/node_modules. É preciso conexão nesta instalação. Faça isso ao preparar uma cópia nova, não a cada mudança no código. Seus arquivos editáveis continuam em src.

Decidir onde o JavaScript vai ficar

O navegador não executa o arquivo .ts diretamente. Vamos colocar sua versão JavaScript em public/js/balcao/main.js. Essa pasta será dedicada ao comportamento do balcão; não mova para ela PHP, CSS ou arquivos pessoais.

Dentro de cliente-balcao, crie vite.config.mjs. Ele configura o Vite em JavaScript de módulo. O defineConfig organiza essas opções; o arquivo se chamará .mjs, enquanto nossas práticas continuam em .ts.

As opções importantes são o ponto de entrada, o destino e a preservação do que já existe. entry aponta para main.ts. outDir usa .. para sair de cliente-balcao e alcançar a pasta pública do Café. emptyOutDir: false impede apagar o conteúdo do destino; publicDir: false evita a cópia automática de outra pasta pública. Escreva:

import { defineConfig } from "vite";

export default defineConfig({
  publicDir: false,
  build: {
    outDir: "../public/js/balcao",
    emptyOutDir: false,
    lib: {
      entry: "src/main.ts",
      formats: ["es"],
      fileName: "main",
    },
    minify: false,
    sourcemap: false,
  },
});

lib pede a geração a partir dessa entrada, sem um index.html do Vite. formats: ["es"] usa módulos JavaScript, como os imports já estudados. fileName: "main" mantém o nome main.js. minify: false conserva a saída legível; sourcemap: false dispensa o arquivo auxiliar de mapeamento nesta prática.

A saída main.js será substituída a cada build correto. A opção de preservação protege os outros arquivos, não transforma o JavaScript gerado em um arquivo para editar manualmente.

Escolher um lugar para a mensagem

No exercício isolado, document.body.textContent ocupava o corpo inteiro da bancada. No balcão, isso apagaria os links e todo o restante da página. Vamos escolher um único parágrafo.

Em public/balcao.php, acrescente o parágrafo abaixo logo depois dos dois parágrafos de atendimento, antes do </section> correspondente:

<p id="aviso-consulta" role="status">Informação recebida ao abrir a página.</p>

O id permite localizar esse elemento. role="status" identifica uma mensagem de estado para tecnologias assistivas. Antes do fechamento </body>, acrescente:

<script type="module" src="js/balcao/main.js"></script>

Esse caminho parte da página pública. O atributo type="module" permite carregar o JavaScript de módulo gerado. Mantenha o começo PHP, cabeçalho, seção e rodapé que já existem.

Quero comparar o arquivo completo sem perder meu HTML

Substitua apenas cliente-balcao/src/main.ts pelo exemplo pequeno abaixo. Mantenha atendimento.ts guardado na mesma pasta: voltaremos a usá-lo na próxima aula.

querySelector("#aviso-consulta") procura o parágrafo pelo id; o # indica esse tipo de seletor. Como uma procura também pode não encontrar nada, o TypeScript considera essa possibilidade. instanceof HTMLElement confere se encontramos um elemento HTML antes de mudar seu texto.

const aviso = document.querySelector("#aviso-consulta");

if (aviso instanceof HTMLElement) {
  aviso.textContent = "O código TypeScript já está ligado ao balcão.";
}

O if cria esse trecho seguro para acessar textContent. Não precisamos afirmar que o elemento existe com um ! nem enfraquecer a verificação.

Gerar e ver a mudança

Salve os arquivos. No segundo terminal, ainda em cliente-balcao, execute:

npm run build

Esse comando primeiro roda npm run verificar, a checagem de tipos já usada no Essencial. Se ela passar, o Vite gera o JavaScript. Confira a mensagem de conclusão no terminal e o arquivo public/js/balcao/main.js no Explorador.

Recarregue o balcão pelo servidor PHP. Não abra a página da bancada Vite nem use Live Preview para esse PHP.

O prazo e os links continuam ali? A pequena mudança comprova a ligação: PHP entregou o HTML, o navegador carregou o JavaScript gerado e esse código alterou somente o parágrafo escolhido. Ainda não fizemos uma consulta à API.

Mude a mensagem no TypeScript para “A equipe já pode conferir esta tela.” e salve. Recarregue antes do build: a mensagem anterior permanece, porque a saída ainda é a anterior. Agora execute build e recarregue novamente. Sua frase chegou?

Depois da experiência, volte à mensagem de referência, gere novamente e recarregue. Esse cuidado deixa claro de qual versão do código a tela veio.

Quando é preciso gerar outra vez?

  • Alterou o TypeScript: salve, execute build e recarregue a página para carregar o JavaScript novo.
  • Alterou somente o PHP: salve e faça uma nova consulta ou recarregue a página. Não precisa de build TypeScript.
  • Alterou o HTML do balcão: salve e recarregue.

Experimente atribuir um número a aviso.textContent, execute build e leia o erro de tipo. O JavaScript anterior pode continuar no disco; ele não comprova que a tentativa nova deu certo. Corrija para texto e repita o build antes de seguir.

Se a mensagem não aparecer, confira o id, o caminho do script, o terminal e a última saída do build. Um 404 de main.js indica que ele não foi gerado no destino esperado ou que o caminho está incorreto. Não edite o arquivo gerado para esconder o problema.

Mostre uma mudança pequena do começo ao fim

Apresente sua própria frase no parágrafo, preservando o restante do balcão. Aponte o .ts que editou, o .js que foi gerado, o terminal de build e o terminal PHP. Explique por que salvá-lo não atualiza automaticamente a saída nesta configuração.

Conferir os arquivos ao fim da Aula 2

Extraia a referência em outra pasta. Ela inclui os arquivos de fonte e o lockfile; execute npm ci e npm run build em cliente-balcao antes de abrir o balcão. Não inclui node_modules nem JavaScript previamente gerado. Sua bancada original não deve ser substituída.

A ligação funciona. Agora, os dados.

A mensagem mostrou que o código chega ao balcão sem apagar a página. Na próxima aula, vamos voltar aos dois arquivos e aos três nomes que o PHP devolve. Primeiro acertaremos a apresentação com um objeto local; depois trocaremos sua origem.
