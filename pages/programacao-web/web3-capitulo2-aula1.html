O balcão do Café Aurora ficou aberto enquanto a equipe atendia. Parte dos pedidos já saiu, e a cozinha avisou: agora a retirada leva 30 minutos.

Abra o balcão da sua cópia do Café e confira o prazo que aparece. Vamos continuar a aplicação que você concluiu no Capítulo 1. Se ela já estiver aberta, mantenha essa aba: precisamos observar a resposta que está nela.

Preciso reabrir o projeto e o servidor

No VS Code, use Arquivo → Abrir Pasta e escolha a pasta da sua aplicação PHP, aquela que contém public e src. Em Terminal → Novo Terminal, confira a versão:

php --version

A referência herdada do Web II usa PHP 8.5 ou posterior da série 8. Se o comando não for reconhecido, veja a orientação de Laragon abaixo. Para iniciar o servidor, execute nesta mesma pasta:

php -d opcache.enable=0 -S localhost:8000 -t public

-S inicia o servidor de desenvolvimento; localhost:8000 é seu endereço. -t public entrega somente a pasta pública. A opção -d opcache.enable=0 desativa o cache de código somente neste servidor de desenvolvimento, para que uma nova consulta use o arquivo que você acabou de salvar; não altera o php.ini. Deixe o terminal aberto. Se já havia um servidor nessa porta, encerre-o com Ctrl + C no terminal dele antes de iniciar outro.

Abra http://localhost:8000/balcao.php. Esse endereço é da aplicação no seu computador; o Mundo bit Byte apresenta as instruções e os arquivos.

Uso Laragon e o VS Code não encontra o PHP

No Laragon, abra Menu → Laragon → Terminal e confira php --version. O terminal do Laragon tem seu próprio ambiente. Para usar as ferramentas no terminal do VS Code, a documentação indica Menu → Tools → Path → Add Laragon to Path; depois feche e reabra o VS Code e confira novamente a versão. No laboratório, faça essa configuração com o professor.

Confirme o PHP 8.5 adequado à referência, em vez de presumir que a versão escolhida para o servidor do Laragon também é a do terminal. Nesta prática usamos o servidor do comando acima. Orientação oficial sobre o PATH. O procedimento foi fundamentado na documentação; a execução em Windows/Laragon ainda precisa de conferência no laboratório.

Um endereço para pedir só o aviso

Já temos quem prepare a resposta: a função obterAtendimento(), em src/atendimento.php. Ela devolve o nome do Café, a situação dos pedidos e a orientação de prazo. Vamos usar essa mesma função em um endereço novo.

O formato JSON, que você conheceu no capítulo 9 do Web I, permite enviar dados com nomes de campos e valores. Aqui teremos três pares. Não precisamos montar outra página HTML para transportá-los.

No Explorador do VS Code, crie a pasta api dentro de public. Dentro dela, crie o arquivo atendimento.php. Há dois arquivos com esse nome: o de src prepara o atendimento; o de public/api responde à consulta.

O arquivo novo usará require_once, como no Capítulo 1. Agora há dois níveis até a raiz: de api para public, e de public para a pasta do projeto. Por isso usamos dirname(__DIR__, 2). O ponto . junta esse caminho com "/src/atendimento.php".

header() informa o tipo da resposta: application/json, com texto UTF-8. Ele vem antes do echo, que envia o corpo. json_encode() transforma o array PHP em JSON; JSON_UNESCAPED_UNICODE mantém os acentos legíveis. Escreva no arquivo novo:

<?php
require_once dirname(__DIR__, 2) . "/src/atendimento.php";
header("Content-Type: application/json; charset=utf-8");
echo json_encode(obterAtendimento(), JSON_UNESCAPED_UNICODE);

Salve e abra uma nova aba em http://localhost:8000/api/atendimento.php. O servidor PHP continua no mesmo terminal. Não use Live Preview para executar esse arquivo.

Seu navegador pode mostrar tudo em uma linha ou oferecer uma visualização formatada. Confira os nomes e valores: a aparência não muda os dados.

Esse endereço é uma pequena API: uma interface pela qual outro programa pode pedir a informação. Nossa primeira operação é uma consulta. Ao abrir a URL, o navegador envia uma requisição HTTP GET. Na continuidade, o código do balcão fará esse pedido.

Os três nomes já estavam no Café

Compare o JSON com o return de src/atendimento.php. Você encontra os mesmos nomes? Nenhum campo foi inventado para o TypeScript.

  • nomeNegocio traz o nome que o PHP preparou.
  • mensagemStatus informa se os pedidos estão abertos ou encerrados.
  • mensagemTempo já é uma frase; não é apenas o número 30.

Volte à aba antiga do balcão. Ela ainda mostra o prazo anterior? Recarregue somente a aba da API. O JSON mostra 30, mas isso não troca o conteúdo que o balcão já recebeu. Temos uma fonte compartilhada e respostas recebidas em momentos diferentes.

Deixar claro o que essa consulta aceita

O endereço está respondendo. Vamos terminar o arquivo dizendo que ele aceita consultas GET, que uma nova consulta deve buscar a informação atual e que um problema interno não deve revelar caminhos de arquivos.

$_SERVER["REQUEST_METHOD"] informa o método recebido. Se ele não for GET, responderemos 405, “método não permitido”, e Allow: GET. exit encerra essa resposta sem continuar até a função. Uma consulta bem-sucedida mantém o código 200.

Cache-Control: no-store pede que essa resposta não seja armazenada. Em caso de falha interna, o código 500 acompanha uma orientação genérica. No try tentamos ler e converter; catch (Throwable $erro) recebe um erro ou exceção do PHP. JSON_THROW_ON_ERROR faz uma falha de conversão chegar a esse tratamento. O sinal | reúne as duas opções do JSON. A mensagem técnica pode ser consultada pelo desenvolvedor no terminal, sem ser enviada ao visitante.

Substitua o conteúdo de public/api/atendimento.php pela versão completa:

<?php
ini_set("display_errors", "0");
header("Content-Type: application/json; charset=utf-8");
header("Cache-Control: no-store");

if ($_SERVER["REQUEST_METHOD"] !== "GET") {
    http_response_code(405);
    header("Allow: GET");
    echo json_encode(["erro" => "Método não permitido."]);
    exit;
}

try {
    require_once dirname(__DIR__, 2) . "/src/atendimento.php";
    echo json_encode(obterAtendimento(), JSON_UNESCAPED_UNICODE | JSON_THROW_ON_ERROR);
} catch (Throwable $erro) {
    http_response_code(500);
    echo json_encode(["erro" => "Não foi possível consultar o atendimento."]);
}

ini_set("display_errors", "0") impede que avisos técnicos sejam impressos no corpo desta resposta; não muda a configuração de outras páginas. O campo erro só aparece em uma falha: ele não faz parte dos três campos de sucesso.

Salve e consulte novamente a API. O JSON correto deve continuar igual. Abra as ferramentas do navegador com F12 ou o menu Inspecionar, escolha Rede / Network e recarregue essa aba. Selecione a requisição atendimento.php: em Cabeçalhos, procure GET, status 200 e Content-Type com application/json. Em Resposta, confira os três campos. Os nomes dos painéis podem variar conforme o navegador.

Se aparecer 404, confira a pasta e a URL. Se aparecer 500, leia o terminal e confira o caminho do require_once. Corrija o arquivo indicado e tente novamente. Se o próprio código PHP aparecer como texto, você abriu pelo servidor errado: use o endereço iniciado pelo comando PHP.

Mostre o caminho do aviso

Sem refazer o Café, você acrescentou uma forma de consultar o atendimento em JSON. Antes de guardar sua cópia, demonstre:

  1. Onde uma única função prepara os textos usados pelas duas páginas e pela API.
  2. Qual campo representa a orientação de prazo e por que ele é texto.
  3. Como a API muda ao encerrar os pedidos, sem copiar a regra para outro arquivo.
  4. Por que uma aba aberta conserva a resposta anterior até fazer outra consulta.

Registre seu valor anterior, a mudança para 30 e uma resposta observada. Use suas anotações ou o Meu estudo; visitar a aula não substitui realizar a prática.
