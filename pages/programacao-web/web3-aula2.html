O atendimento continua

O visitante consulta o site, e a equipe usa a tela do balcão. Na aula anterior, você fez as duas buscarem a informação de atendimento no mesmo arquivo. Vamos continuar nessa cópia do Café.

Com o servidor PHP em execução no seu computador, abra a página inicial e o balcão em abas separadas. Recarregue ambas: elas devem mostrar o prazo que você escolheu ao encerrar a primeira aula.

Vou retomar pelo arquivo de conferência

Baixe a versão ao fim da aula 1 e descompacte em outra pasta. A referência começa com 55 minutos e já tem as duas páginas conectadas. Abra no terminal a pasta que contém public e execute php -S localhost:8000 -t public.

Um pedido de mudança, agora sem o passo a passo

A cozinha informou que o movimento diminuiu: o preparo está em 20 minutos. Faça essa alteração no projeto e confira o que aparece nas duas páginas. Tente escolher o arquivo antes de abrir a ajuda.

Onde faço a alteração?

Em src/atendimento.php, altere $tempoEstimado para 20, salve e recarregue as duas abas. As páginas recebem o texto preparado pela função. Se ainda precisar ligar uma delas, retome a ligação do balcão e do site na primeira aula.

Se os dois prazos mudaram, você já está usando a organização que construiu. Vamos ver como ela se comporta quando a cozinha para de receber pedidos.

A cozinha encerrou os pedidos

No fim do atendimento, informar um prazo maior seria uma orientação errada. Quem consulta o Café precisa saber que novos pedidos para retirada estão encerrados.

No arquivo src/atendimento.php, altere $pedidosAbertos para false. Salve e recarregue as duas páginas.

O valor de $tempoEstimado continua no programa. Por que ele deixou de aparecer? Acompanhe o if na função: com false, ela prepara a mensagem de encerramento no lugar do prazo. A decisão que existia no Web II continua valendo para as duas apresentações.

Reabra o atendimento com true e recarregue as abas. Os 20 minutos devem voltar a aparecer. Deixe o atendimento aberto para a próxima experiência.

O balcão ficou aberto enquanto o prazo mudou

Durante o atendimento, a equipe pode deixar a tela aberta entre uma consulta e outra. Vamos acompanhar essa situação sem recarregar tudo ao mesmo tempo.

Mantenha a aba do balcão mostrando 20 minutos. No arquivo compartilhado, altere o prazo para 35, salve e recarregue somente a página inicial.

O site mostra 35 minutos. O balcão ainda mostra 20. Parece a divergência da primeira aula, mas confira os arquivos: agora existe uma única definição do prazo.

A diferença está na resposta que cada aba recebeu. Quando você recarregou a página inicial, o navegador pediu outra página e o PHP preparou o HTML com 35 minutos. O balcão ainda está exibindo a resposta de antes da mudança.

Recarregue o balcão. Os 35 minutos chegaram? Não foi preciso corrigir outro arquivo; foi preciso pedir uma nova resposta.

Conseguimos organizar onde a informação é preparada. Isso, por si só, não faz uma aba aberta consultar o servidor novamente. Essa diferença será importante para o próximo passo do Café.

Explique a diferença que você acabou de observar

Imagine que alguém da equipe diga: “As telas ficaram diferentes outra vez. A mudança não funcionou?”. Responda usando o que você acabou de fazer.

Para sustentar a resposta, mostre onde o prazo é definido e qual aba ainda precisava receber uma nova página. Se estiver em dupla, explique ao colega; se estiver sozinho, acompanhe o caminho apontando os trechos no editor.

Quando as duas páginas tinham cópias da decisão, recarregar não resolvia a diferença. Agora, com a decisão compartilhada, uma nova consulta traz a informação atual. Esse é o limite que acabamos de localizar.

Antes de guardar sua entrega

Volte à página inicial e siga para o cardápio. Confira os links e a apresentação. No balcão, use “Voltar ao site”. As mudanças deste capítulo ficaram no início PHP da página inicial, na nova tela e no arquivo de apoio.

Para fechar a entrega, use também o contato e o painel que já funcionavam no Web II: envie uma mensagem fictícia e confira se ela aparece após o login. Assim verificamos se o Café continua atendendo pelo caminho anterior.

Estou usando a referência e preciso preparar o banco e o painel

A referência não inclui banco nem credenciais. Na raiz dessa cópia, execute os comandos que você usou no Web II:

php src/verificar-ambiente.php
php src/inicializar-banco.php
php src/criar-administrador.php

O último comando pede usuário e senha pelo terminal. Crie uma credencial local e use apenas dados fictícios nesta conferência. Se precisar recuperar essa preparação, consulte o registro das mensagens e o painel do Web II.

Vou repetir também os testes automatizados do Web II

Se a sua cópia já está preparada, execute composer test. Na referência, instale primeiro as dependências com composer install. Permanecem os requisitos da entrega do Web II: PHP ^8.5, PDO/SQLite e PHPUnit ^13.0. A aula sobre a suíte explica essa preparação.

Se algo falhar, registre o caminho que percorreu e a mensagem recebida antes de mudar outros arquivos. Localizar o problema é mais útil do que refazer o projeto inteiro.

O que você leva deste capítulo

O Café ganhou uma tela de consulta para o balcão. Site e balcão preparam a informação no mesmo lugar, preservando suas apresentações. Você também verificou que uma aba aberta precisa fazer uma nova consulta para receber uma mudança.

Guarde seu projeto com o atendimento aberto. Se ainda não consegue explicar algum desses resultados, volte à experiência correspondente e acompanhe o que acontece na tela. Você pode registrar essa dúvida nas anotações do Meu estudo.

Conferir os arquivos do Capítulo 1

Abra a referência em outra pasta para comparar. Ela mantém as duas páginas conectadas e o prazo de 55 minutos da primeira aula; as mudanças desta aula são experiências na sua cópia.

Como consultar o prazo sem carregar tudo outra vez?

A equipe quer manter o balcão aberto, mas precisa receber o prazo atual. Recarregar cabeçalho, rodapé e todo o restante a cada consulta parece trabalho a mais.

No Web I, você usou fetch() para buscar os produtos do cardápio. Podemos aproveitar essa ideia para pedir ao PHP somente os dados do atendimento? Essa será a próxima necessidade: decidir o que o servidor deve devolver para uma consulta assim.

Antes de ligar essa consulta, vamos preparar os dados do cliente com TypeScript Essencial. São exemplos curtos sobre o próprio Café para reconhecer tipos e conferir valores recebidos.
