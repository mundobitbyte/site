A mensagem chegou. E o aviso do atendimento?

A pequena frase da aula anterior apareceu dentro do balcão e os links continuaram no lugar. Agora a equipe precisa apresentar o nome do Café, a situação dos pedidos e a orientação de prazo nos lugares certos.

Abra seu cliente-balcao/src/atendimento.ts e, em outra aba, a resposta da API. A bancada usava dois campos; o PHP devolve três. Vamos compará-los antes de mudar qualquer nome.

Primeiro acertaremos a apresentação com um objeto local. O botão desta aula será chamado “Conferir apresentação”: ele ainda não faz uma consulta à API. Assim podemos enxergar o que muda na tela antes de acrescentar a espera pela rede.

Os nomes vêm da resposta que já existe

Da bancada do tópico 12 para o retorno PHP
Na bancadaNo PHPO que muda
nome: stringnomeNegocio: stringO cliente acompanha o nome já usado no retorno do servidor.
tempoEstimado: numbermensagemTempo: stringReceberemos a frase preparada, não somente um número.
Não havia este campomensagemStatus: stringA situação dos pedidos passa a fazer parte do objeto do cliente.

Se a cozinha encerra os pedidos, mensagemTempo deixa de anunciar minutos e orienta a consultar o horário de atendimento. Por isso não basta renomear tempoEstimado: o significado e o tipo mudaram. Não some “minutos” a uma frase que já veio pronta.

Esses nomes são o combinado entre quem fornece e quem recebe os dados; chamaremos esse combinado de contrato. Por enquanto vamos representá-lo localmente. As regras de abertura e prazo continuam sendo preparadas no PHP.

Se você experimentou nomes próprios no Essencial, compare cada um com esta referência antes de substituí-lo nesta cópia de integração. Sua bancada original e as entregas continuam guardadas.

Em cliente-balcao/src/atendimento.ts, atualize a interface e o objeto local:

export interface Atendimento {
  nomeNegocio: string;
  mensagemStatus: string;
  mensagemTempo: string;
}

export function obterAtendimento(): Atendimento {
  return {
    nomeNegocio: "Café Aurora",
    mensagemStatus: "Pedidos para retirada estão abertos.",
    mensagemTempo: "Tempo estimado: 30 minutos.",
  };
}

A função continua síncrona: ao chamá-la, recebemos o objeto que acabamos de escrever. O : Atendimento verifica seu retorno; não dispara nenhuma consulta. Os três valores são textos, e o retorno passa a incluir mensagemStatus.

Dar um endereço a cada texto da tela

Em public/balcao.php, acrescente o id ao título que já apresenta o nome:

<h1 id="nome-negocio"><?= htmlspecialchars($nomeNegocio, ENT_QUOTES, "UTF-8") ?></h1>

No parágrafo que apresenta a situação, mantenha o PHP e identifique o elemento:

<p id="mensagem-status"><?= htmlspecialchars($mensagemStatus, ENT_QUOTES, "UTF-8") ?></p>

Faça o mesmo no parágrafo do prazo:

<p id="mensagem-tempo"><?= htmlspecialchars($mensagemTempo, ENT_QUOTES, "UTF-8") ?></p>

Esses ids permitem localizar os elementos sem alterar o lugar de cada um na página. O parágrafo aviso-consulta da Aula 2 continua na seção.

Logo antes desse parágrafo, acrescente o botão:

<button id="atualizar-atendimento" type="button" disabled>Conferir apresentação</button>

type="button" descreve uma ação sem enviar um formulário. Ele começa desabilitado com disabled; só será habilitado depois de o JavaScript encontrar os elementos. O id foi escolhido para continuar útil quando a consulta real chegar.

Preparar em um arquivo, apresentar em outro

Vamos retomar os imports do tópico 12. import traz a função; import type traz a descrição Atendimento para o verificador. Os arquivos .ts continuam na mesma pasta; a escrita ./atendimento.js acompanha a saída JavaScript, como na bancada.

A procura que fizemos para um parágrafo agora alcança os cinco elementos. A guarda usa !, “não”, e ||, “ou”: se algum elemento não tiver o tipo esperado, throw new Error(...) interrompe a ligação com uma mensagem no Console. O botão precisa ser um HTMLButtonElement, pois usaremos sua propriedade disabled.

apresentar será uma função de seta que recebe Atendimento e muda somente três textContent. Essa função é declarada depois das guardas, para manter a verificação dos elementos. O clique será ligado com addEventListener, que você já usou no Web I.

Em cliente-balcao/src/main.ts, use esta ligação completa:

import { obterAtendimento } from "./atendimento.js";
import type { Atendimento } from "./atendimento.js";

const nome = document.querySelector("#nome-negocio");
const situacao = document.querySelector("#mensagem-status");
const tempo = document.querySelector("#mensagem-tempo");
const botao = document.querySelector("#atualizar-atendimento");
const aviso = document.querySelector("#aviso-consulta");

if (!(nome instanceof HTMLElement) || !(situacao instanceof HTMLElement) ||
    !(tempo instanceof HTMLElement) || !(botao instanceof HTMLButtonElement) ||
    !(aviso instanceof HTMLElement)) {
  throw new Error("Confira os elementos do balcão no HTML.");
}

const apresentar = (atendimento: Atendimento) => {
  nome.textContent = atendimento.nomeNegocio;
  situacao.textContent = atendimento.mensagemStatus;
  tempo.textContent = atendimento.mensagemTempo;
};

botao.disabled = false;
botao.textContent = "Conferir apresentação";
aviso.textContent = "Ensaio local: este botão ainda não consulta o PHP.";

botao.addEventListener("click", () => {
  apresentar(obterAtendimento());
  aviso.textContent = "Ensaio local conferido; ainda não houve consulta ao servidor.";
});

Os nomes à esquerda, como tempo, apontam para elementos HTML. À direita, atendimento.mensagemTempo é um campo do objeto. A função de apresentação coloca o valor no elemento correspondente.

Salve, execute npm run build no terminal de cliente-balcao e recarregue o balcão no servidor PHP. O botão fica habilitado, e o aviso identifica o ensaio local. Clique em “Conferir apresentação”. O nome, a situação e a frase de prazo devem continuar nos seus lugares.

Fazer a diferença aparecer

Com os mesmos valores locais e do PHP, o resultado pode parecer igual. Vamos separar as origens com uma experiência pequena.

Somente no retorno local de atendimento.ts, mude a frase para “Tempo estimado: 25 minutos.”. Estamos ensaiando a apresentação de outro aviso; a cozinha ainda informa 30 no servidor.

Salve, gere o JavaScript e recarregue o balcão. Ao abrir, o PHP apresenta 30. Clique em “Conferir apresentação”. Agora aparecem os 25 do objeto local. O aviso logo abaixo continua dizendo que é um ensaio.

Abra ou recarregue a API: ela ainda devolve 30. O botão não leu esse endereço, e alterar o TypeScript não mudou a fonte PHP. Essa comparação nos ajuda a explicar de onde cada informação veio.

Volte o objeto local para 30, execute build e recarregue. Mantemos a referência coerente para a próxima aula. Nenhum cabeçalho, rodapé ou link precisou ser reconstruído.

Mostre de onde veio cada valor

Demonstre a troca local 30 → 25 e explique por que a API não acompanhou. Aponte a correspondência dos três campos com os elementos da página e justifique por que mensagemTempo é texto. Confira que o link “Voltar ao site” e o restante do Café continuam funcionando.
