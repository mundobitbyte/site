Uma identidade para a equipe

Web III — Em desenvolvimento.

A consulta pública funciona. Marina, porém, não quer que qualquer pessoa possa se passar pela equipe. Vamos acrescentar reconhecimento de identidade, ainda sem liberar a alteração do aviso.

Firebase Authentication oferece operações de autenticação. Vamos usá-las no emulador. Essas identidades são diferentes da conta do Meu MbB e do administrador da aplicação PHP anterior; cada sistema tem seu próprio contexto.

Preparar os arquivos desta etapa

Baixar a referência da etapa 2. Ela contém a aplicação ao final desta etapa; não é uma nova tarefa nem uma substituição automática da sua solução.

Continue na sua pasta de trabalho que concluiu a etapa 1 deste percurso. A raiz é o lugar onde aparecem public e cliente-balcao. Não crie uma pasta cafe-aurora-web3 dentro dessa raiz.

  1. Salve os arquivos e pare o servidor antes de copiar dados. Preserve uma cópia da pasta atual.
  2. Extraia o download em uma pasta de referência separada. Abra o LEIA-ME-ETAPA.md que está dentro de cafe-aurora-web3.
  3. Compare os caminhos listados abaixo com sua pasta de trabalho. Acrescente os arquivos de apoio que ainda não existem. Para um arquivo já existente, compare a alteração antes de aplicá-la: não apague uma mudança sua sem entender a diferença. Os arquivos discutidos na aula são os que vamos construir e compreender.

Mantenha sua pasta dados-emuladores: ela não vem no download. Antes de trocar configurações ou executar os testes, encerre com Ctrl+C e aguarde a exportação. Depois use npm run retomar para recuperar os dados já guardados.

Entre com uma identidade de exercício

Acrescente os arquivos da etapa, faça o build do cliente e mantenha os emuladores abertos. Se estavam parados, use npm run retomar na raiz para importar a sessão guardada; não é necessário recriar a identidade a cada aula. Use npm run preparar somente se iniciou uma bancada sem dados.

Abra http://localhost:5000/balcao.html. O preparo oferece operador@example.test e leitor@example.test, com a senha fictícia senha-ficticia-aurora. Esses dados existem somente na bancada local. Não reutilize essa senha fora do emulador.

Entre como leitor. A página deve identificar a conta reconhecida. Use Sair e repita como operador. Nesta etapa, não há formulário de alteração disponível: reconhecer uma pessoa não é o mesmo que autorizar uma escrita.

import {initializeApp} from "firebase/app";
import {getFirestore,connectFirestoreEmulator} from "firebase/firestore";
import {modo,configuracao} from "./ambiente.js";
if(modo==="local" && !["localhost","127.0.0.1"].includes(location.hostname))throw new Error("Abra pelo endereço do emulador local.");
export const app=initializeApp(configuracao);
export const banco=getFirestore(app);
if(modo==="local")connectFirestoreEmulator(banco,"127.0.0.1",8080);
import {getAuth,connectAuthEmulator} from "firebase/auth";
export const auth=getAuth(app);
if(modo==="local")connectAuthEmulator(auth,"http://127.0.0.1:9099",{disableWarnings:true});
Conferir cliente-balcao/src/operador.ts

Caminho a partir da raiz da aplicação. Abra o arquivo no VS Code e compare com a explicação desta etapa.

import { onAuthStateChanged, signInWithEmailAndPassword, signOut } from "firebase/auth";
import { doc,getDocFromServer } from "firebase/firestore";
import { auth,banco } from "./servico.js";
import { alterarAtendimento } from "./dados.js";
import { conferirConfiguracao } from "./atendimento.js";
import { elemento,comPrazo } from "./tela.js";

const login = document.querySelector<HTMLFormElement>("#entrar");
const formulario = document.querySelector<HTMLFormElement>("#alterar");
const retorno = document.querySelector<HTMLElement>("#retorno-operador");
login?.addEventListener("submit", async evento => {
  evento.preventDefault(); const botao = login.querySelector<HTMLButtonElement>("button")!; botao.disabled = true;
  try {
    await signInWithEmailAndPassword(auth,elemento<HTMLInputElement>("#email").value,elemento<HTMLInputElement>("#senha").value);
    elemento<HTMLInputElement>("#senha").value = "";
    if (retorno) retorno.textContent = "Identidade reconhecida. A permissão será conferida pelo serviço.";
  } catch { if (retorno) retorno.textContent = "Entrada não confirmada. Confira os dados e o emulador de identidade."; }
  finally { botao.disabled = false; }
});
document.querySelector("#sair")?.addEventListener("click", async () => {
  try { await signOut(auth); if (retorno) retorno.textContent = "Você saiu do Café."; }
  catch { if (retorno) retorno.textContent = "Não foi possível confirmar a saída."; }
});
onAuthStateChanged(auth, async usuario => {
  const identidade = document.querySelector("#identidade");
  if (identidade) identidade.textContent = usuario ? `Identidade: ${usuario.email}.` : "Visitante: consulta pública disponível.";
  const campos = formulario?.querySelector<HTMLFieldSetElement>("fieldset");
  if (campos) campos.disabled = true;
  const sessao = usuario?.uid;
  if (!usuario || !formulario) return;
  try {
    const token = await usuario.getIdTokenResult();
    if (token.claims.operador !== true) { if (retorno) retorno.textContent = "Sua identidade permite consultar, mas não alterar."; return; }
    const foto = await comPrazo(getDocFromServer(doc(banco,"atendimento","atual")));
    if (auth.currentUser?.uid !== sessao) return;
    const d = conferirConfiguracao(foto.data());
    elemento<HTMLInputElement>("#nome").value = d.nomeNegocio;
    elemento<HTMLSelectElement>("#aberto").value = d.pedidosAbertos ? "1" : "0";
    elemento<HTMLInputElement>("#minutos").value = d.tempoEstimado === null ? "" : String(d.tempoEstimado);
    if (campos) campos.disabled = false;
  } catch { if (retorno) retorno.textContent = "Configuração não confirmada. Entre novamente ou confira o serviço."; }
});
formulario?.addEventListener("submit", async evento => {
  evento.preventDefault(); const botao = formulario.querySelector<HTMLButtonElement>("button")!; botao.disabled = true;
  const minutos = elemento<HTMLInputElement>("#minutos").value.trim();
  try {
    const dados = conferirConfiguracao({ nomeNegocio: elemento<HTMLInputElement>("#nome").value.trim(),pedidosAbertos:elemento<HTMLSelectElement>("#aberto").value === "1",tempoEstimado:minutos === "" ? null : Number(minutos) });
    if (retorno) retorno.textContent = "Aguardando confirmação da gravação…";
    await alterarAtendimento(dados);
    if (retorno) retorno.textContent = "Alteração confirmada. Consulte a outra tela para conferir.";
  } catch { if (retorno) retorno.textContent = "Alteração não confirmada. Confira os campos, a permissão e a conexão antes de tentar novamente."; }
  finally { botao.disabled = false; }
});

Acompanhe a identidade sem guardar a senha

signInWithEmailAndPassword pede a confirmação da identidade ao serviço. onAuthStateChanged acompanha entrada e saída. O campo de senha é limpo depois da entrada; nosso código não a grava em localStorage nem em um documento público.

O preparo atribui ao operador uma informação de permissão chamada claim. Ela não é escolhida pelo formulário do navegador. Na próxima etapa, veremos como o serviço verifica essa informação mesmo que alguém altere os controles da página.

Teste uma senha incorreta e confira a orientação. A consulta pública do atendimento deve continuar funcionando depois da tentativa recusada e depois da saída. Não transforme uma falha de entrada em um bloqueio do Café inteiro.

O que foi confirmado, exatamente?

Registre entrada recusada, leitor reconhecido, operador reconhecido e saída. Explique por que escrever “operador” no HTML não concederia uma permissão no serviço. Agora precisamos expressar quem pode ler, quem pode escrever e quais dados serão aceitos.
