Rascunho não é publicação

Café Aurora · cerca de 8 horas-aula de estudo, prática e verificação

Web III — Em desenvolvimento.

Marina está revisando a descrição do café coado. Ainda não quer que o cliente veja o texto: precisa conferir os ingredientes com a equipe. Se todo “Salvar” publicasse imediatamente, não haveria espaço para essa revisão.

Vamos separar edição local, rascunho salvo e publicação confirmada. São estados diferentes. A interface precisa deixar claro o que já chegou ao servidor e o que o visitante consegue consultar.

Salve sem publicar

Após o build, entre como operador e localize a descrição do café. Escreva uma frase com 10 a 400 caracteres e use “Salvar rascunho”. Em uma janela sem login, abra o cardápio: a descrição pública deve continuar igual.

Conferir cliente-balcao/src/componentes/EditorProduto.tsx

Caminho a partir da raiz da aplicação. Abra o arquivo no VS Code e compare com a explicação desta etapa.

import { useState } from "react";
import type { Produto, Sessao } from "../servicos/api.js";
import { gravarProduto } from "../servicos/api.js";
import { conferirDescricao } from "../regras.js";

export function EditorProduto({ produto, sessao, aoSalvar }: { produto: Produto; sessao: Sessao; aoSalvar: () => Promise<void> }) {
  const [texto, setTexto] = useState(produto.rascunho ?? produto.descricao);
  const [aviso, setAviso] = useState("");
  const [ocupado, setOcupado] = useState(false);
  async function salvar(acao: "rascunho" | "publicar") {
    setOcupado(true);
    try {
      const descricao = conferirDescricao(texto);
      await gravarProduto(sessao, produto.id, descricao, acao);
      setTexto(descricao);
      await aoSalvar();
      setAviso(acao === "publicar" ? "Descrição publicada após confirmação." : "Rascunho salvo. O visitante ainda vê a descrição anterior.");
    } catch (e) { setAviso(e instanceof Error ? e.message : "Não foi possível salvar."); }
    finally { setOcupado(false); }
  }
  return <section><h3>Editar {produto.nome}</h3>
    <p><label htmlFor={`descricao-${produto.id}`}>Descrição</label><textarea id={`descricao-${produto.id}`} value={texto} maxLength={400} onChange={e => setTexto(e.target.value)} /></p>
    <button disabled={ocupado} onClick={() => void salvar("rascunho")}>Salvar rascunho</button>{" "}
    <button disabled={ocupado || produto.rascunho == null || texto !== produto.rascunho} onClick={() => void salvar("publicar")}>Publicar rascunho salvo</button>{" "}
    <button disabled={ocupado} onClick={() => { setTexto(produto.rascunho ?? produto.descricao); setAviso("Edição local cancelada."); }}>Cancelar edição local</button>
    <p role="status">{aviso}</p>
  </section>;
}

O componente começa com o rascunho que já existe ou, na ausência dele, com a descrição pública. O texto digitado fica no estado local. conferirDescricao retira espaços nas extremidades e confere o tamanho antes do envio.

A operação informa ao serviço qual ação está sendo solicitada: rascunho ou publicar. O serviço valida identidade, token, produto e descrição. Para o visitante, a resposta pública não deve incluir o rascunho privado.

Publique o texto que foi conferido

Depois da confirmação do rascunho, o botão “Publicar rascunho salvo” fica disponível. Se você alterar o texto outra vez, precisa salvar essa revisão antes de publicá-la. Isso evita publicar por engano uma versão diferente daquela que a equipe acabou de conferir.

Use o botão de publicação e consulte novamente o cardápio na janela de visitante. A nova descrição deve aparecer. O endereço antigo /cardapio.php já leva à área que consulta o banco atual; não mantemos o catálogo preso ao JSON inicial.

Ao atualizar a lista após uma gravação, carregarProdutos(true) preserva os componentes até chegar a nova resposta. Esvaziar a lista nesse momento desmontaria o editor e poderia apagar o texto em que a pessoa está trabalhando. A identificação estável do produto também participa dessa continuidade.

Cancelamento e falha também precisam ser claros

Altere um texto e use “Cancelar edição local”. O componente volta ao último rascunho ou à descrição recebida; não apaga uma publicação no banco. Depois tente salvar uma frase curta demais. A interface precisa recusar e preservar a possibilidade de corrigir.

Se a gravação falhar por indisponibilidade, não mostre “publicado”. Restaure a conexão, consulte o estado e repita a ação conscientemente. A interface auxilia a equipe; a confirmação continua vindo do servidor.

Qual versão o cliente vê agora?

Demonstre rascunho privado, confirmação separada de publicação, cancelamento local e correção de texto inválido. Mostre o resultado como operador e como visitante. Falta reunir verificações que possam ser repetidas e preparar a aplicação em outra pasta.
