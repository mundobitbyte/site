A cozinha mudou o prazo. O botão percebeu?

O balcão está aberto e o ensaio local funciona. Enquanto isso, chegaram mais pedidos à cozinha. A nova orientação é de 47 minutos. A equipe precisa consultar essa informação sem fechar o balcão que já está na tela.

Deixe o balcão aberto. Em src/atendimento.php, mude somente $tempoEstimado = 30; para $tempoEstimado = 47; e salve. Recarregue a API em outra aba: ela já informa 47. No balcão que ficou aberto, clique em “Conferir apresentação”. Ainda aparecem os 30 do objeto local?

O botão fez exatamente o que construímos: conferiu e apresentou um objeto escrito no TypeScript. Agora chegou a hora de trocar sua origem. Manteremos os três campos, a conferência e os elementos HTML. Quem fornecerá os valores será o PHP.

Continue na sua cópia da Aula 4, preservando a bancada original. Mantenha o terminal PHP ativo na raiz de cafe-aurora-web3 e o segundo terminal em cliente-balcao. Esta página do Mundo bit Byte apresenta o roteiro; sua aplicação roda em http://localhost:8000/balcao.php.

Pedir não é o mesmo que já ter recebido

No capítulo 9 do Web I, o cardápio buscava um arquivo JSON com fetch. Aqui o endereço termina em PHP: o servidor executa a função compartilhada e devolve JSON. A espera pela resposta continua existindo.

Por isso obterAtendimento deixará de devolver Atendimento imediatamente. Ela será async, com retorno Promise<Atendimento>: uma promessa cujo resultado, se a consulta e a conferência derem certo, será Atendimento. Os sinais < e > descrevem o tipo do resultado; não criam os dados nem garantem que a rede funcionará.

await fetch aguarda a resposta sem bloquear a página inteira. O endereço é relativo ao documento aberto no navegador: balcao.php e api/atendimento.php pertencem a localhost:8000. Ele não é relativo à pasta do main.js gerado. cache: "no-store" pede uma consulta sem reaproveitar uma resposta guardada.

Retomamos resposta.ok: receber HTTP 404 ou 500 não é um sucesso, mesmo que fetch tenha recebido uma resposta. A mensagem com crases e ${resposta.status} registra o código para investigação no Console.

Antes de ler o corpo, examinamos o cabeçalho Content-Type. get pode devolver null; depois dessa guarda, split(";")[0] separa o tipo de uma indicação como charset=UTF-8. trim e toLowerCase permitem comparar “application/json” sem espaços nas pontas ou diferença entre maiúsculas e minúsculas.

O segundo await aguarda a leitura do JSON. O resultado entra como unknown na mesma conferência da Aula 4. Um cabeçalho JSON não garante que existam nossos três textos.

Em cliente-balcao/src/atendimento.ts, preserve a interface e conferirAtendimento. Substitua apenas obterAtendimento pela função abaixo:

export async function obterAtendimento(): Promise<Atendimento> {
  const resposta = await fetch("api/atendimento.php", { cache: "no-store" });
  if (!resposta.ok) {
    throw new Error(`A consulta respondeu HTTP ${resposta.status}.`);
  }
  const tipo = resposta.headers.get("Content-Type");
  if (tipo === null || tipo.split(";")[0].trim().toLowerCase() !== "application/json") {
    throw new Error("A resposta não foi identificada como JSON.");
  }
  const dados: unknown = await resposta.json();
  return conferirAtendimento(dados);
}
Conferir o atendimento.ts completo

A conferência permanece igual. Sai somente o objeto local, entra a consulta.

export interface Atendimento {
  nomeNegocio: string;
  mensagemStatus: string;
  mensagemTempo: string;
}

export function conferirAtendimento(dados: unknown): Atendimento {
  if (typeof dados !== "object" || dados === null || Array.isArray(dados)) {
    throw new Error("A resposta precisa ser um objeto.");
  }
  if (!("nomeNegocio" in dados) || typeof dados.nomeNegocio !== "string" || dados.nomeNegocio.trim() === "") {
    throw new Error("Nome do negócio ausente ou inválido.");
  }
  if (!("mensagemStatus" in dados) || typeof dados.mensagemStatus !== "string" || dados.mensagemStatus.trim() === "") {
    throw new Error("Mensagem de situação ausente ou inválida.");
  }
  if (!("mensagemTempo" in dados) || typeof dados.mensagemTempo !== "string" || dados.mensagemTempo.trim() === "") {
    throw new Error("Mensagem de prazo ausente ou inválida.");
  }
  return {
    nomeNegocio: dados.nomeNegocio,
    mensagemStatus: dados.mensagemStatus,
    mensagemTempo: dados.mensagemTempo,
  };
}

export async function obterAtendimento(): Promise<Atendimento> {
  const resposta = await fetch("api/atendimento.php", { cache: "no-store" });
  if (!resposta.ok) {
    throw new Error(`A consulta respondeu HTTP ${resposta.status}.`);
  }
  const tipo = resposta.headers.get("Content-Type");
  if (tipo === null || tipo.split(";")[0].trim().toLowerCase() !== "application/json") {
    throw new Error("A resposta não foi identificada como JSON.");
  }
  const dados: unknown = await resposta.json();
  return conferirAtendimento(dados);
}

Execute npm run build agora. O verificador deve apontar que o main.ts ainda tenta entregar uma Promise diretamente a apresentar. Esse erro mostra a outra ponta da mudança: quem chama a função também precisa esperar. Vamos corrigir antes de abrir o resultado.

Um clique, uma consulta, uma orientação

Durante a espera, o prazo anterior não pode parecer uma informação recém-consultada. Retiraremos situação e prazo, manteremos o nome e escreveremos “Consultando o atendimento…”. O botão ficará desabilitado até a consulta terminar, impedindo pedidos simultâneos.

No evento, async permite usar await obterAtendimento(). Só depois vem apresentar. O catch já conhecido recebe falhas de rede, de leitura ou de conferência. Acrescentaremos finally, o bloco executado depois do try/catch tanto no sucesso quanto no erro: ali devolvemos o botão à pessoa.

Também guardamos se o botão tinha foco. Alguns navegadores retiram o foco ao desabilitá-lo. Ao terminar, só o devolvemos se ele tiver ido para o corpo da página; se a pessoa escolheu outro controle, respeitamos essa escolha. preventScroll: true evita deslocar a tela ao devolver o foco.

Em main.ts, mantenha os imports, as procuras, as guardas e apresentar. A partir de botao.disabled = false, troque as mensagens e o evento pela parte correspondente deste arquivo:

import { obterAtendimento } from "./atendimento.js";
import type { Atendimento } from "./atendimento.js";

const nome = document.querySelector("#nome-negocio");
const situacao = document.querySelector("#mensagem-status");
const tempo = document.querySelector("#mensagem-tempo");
const botao = document.querySelector("#atualizar-atendimento");
const aviso = document.querySelector("#aviso-consulta");

if (!(nome instanceof HTMLElement) || !(situacao instanceof HTMLElement) ||
    !(tempo instanceof HTMLElement) || !(botao instanceof HTMLButtonElement) ||
    !(aviso instanceof HTMLElement)) {
  throw new Error("Confira os elementos do balcão no HTML.");
}

const apresentar = (atendimento: Atendimento) => {
  nome.textContent = atendimento.nomeNegocio;
  situacao.textContent = atendimento.mensagemStatus;
  tempo.textContent = atendimento.mensagemTempo;
};

botao.disabled = false;
botao.textContent = "Atualizar atendimento";
aviso.textContent = "Informação recebida ao abrir a página. Você pode consultar novamente.";

botao.addEventListener("click", async () => {
  if (botao.disabled) return;
  const devolverFoco = document.activeElement === botao;
  botao.disabled = true;
  situacao.textContent = "";
  tempo.textContent = "";
  aviso.textContent = "Consultando o atendimento…";
  try {
    const atendimento = await obterAtendimento();
    apresentar(atendimento);
    aviso.textContent = "Atendimento consultado agora.";
  } catch (erro) {
    situacao.textContent = "";
    tempo.textContent = "";
    aviso.textContent = "Não foi possível consultar. Tente novamente.";
    console.error(erro);
  } finally {
    botao.disabled = false;
    if (devolverFoco && document.activeElement === document.body) {
      botao.focus({ preventScroll: true });
    }
  }
});

Salve, execute npm run build em cliente-balcao e recarregue o balcão no servidor PHP. O build deve passar. Você verá a informação que o PHP preparou ao abrir a página e o novo botão habilitado. Ainda não fazemos consulta automática: ela acontece quando você pede.

Agora deixe a página aberta

Com o balcão aberto, volte o prazo PHP de 47 para 30 e salve. Não faça build nem recarregue o balcão. Clique em “Atualizar atendimento”. O prazo deve mudar de 47 para 30, acompanhado de “Atendimento consultado agora.”.

Faça também o caminho contrário: a cozinha passou a informar 47; altere o PHP, salve e clique novamente. O cabeçalho, os links e o restante do documento permanecem. Só os textos do atendimento foram atualizados.

Para enxergar o pedido, abra as ferramentas do navegador com F12, escolha Rede / Network, limpe a lista e clique no botão. Se o navegador agrupar por tipo, escolha Fetch/XHR. Abra a requisição atendimento.php: confira o método GET, o status 200 e a resposta com nomeNegocio, mensagemStatus e mensagemTempo. Não deve surgir um novo carregamento do documento balcao.php por causa do clique.

No PHP, mude pedidosAbertos para false, salve e consulte. A orientação de encerramento aparece sem inventar minutos. Reponha true e 30 ao terminar. Consulte novamente para conferir a recuperação e deixar a referência preparada para a próxima aula.

Se o texto não mudou, investigue a origem: abriu localhost:8000/balcao.php? O terminal PHP continua ativo? O build terminou sem erros depois da alteração dos .ts? Recarregou uma vez para carregar esse JavaScript novo? A resposta vista na Rede corresponde ao PHP que você editou?

Uma alteração no PHP exige salvar e fazer uma nova consulta. Uma alteração no TypeScript exige salvar, gerar o JavaScript e recarregar para carregar esse código novo. Não precisamos reinstalar as dependências a cada tentativa.

Demonstre o caminho inteiro

Com a página aberta, altere o prazo no PHP e mostre sua atualização pelo botão. Localize o JSON na Rede e explique a ordem: buscar, conferir, apresentar. Aponte o await nos dois arquivos e justifique por que a Promise não pode ser entregue diretamente à apresentação.

Teste também com Tab e Enter: você consegue chegar ao botão, consultar e continuar navegando? Confira o link “Voltar ao site”. Guarde uma anotação sobre a diferença entre alterar PHP e alterar TypeScript.

Conferir os arquivos ao fim da Aula 5

A referência termina com pedidos abertos e 30 minutos. Compare em outra pasta: npm ci e npm run build em cliente-balcao; PHP na raiz, com o comando da Aula 1. Não substitua sua solução nem leve node_modules de uma pasta para outra.

E quando a resposta não chega?

O balcão já consulta a cozinha pelo servidor. Se a resposta falhar, o botão volta a permitir uma tentativa. Falta decidir por quanto tempo esperar e experimentar respostas que não merecem ser apresentadas. É a próxima necessidade do atendimento.
