A equipe informa o prazo

Web III — Em desenvolvimento.

A entrada funciona, mas Marina ainda não consegue informar o novo prazo. Vamos acrescentar o formulário de atendimento à área já protegida, sem criar outra tela de login ou outro banco.

Há duas formas da informação em circulação. O visitante recebe três mensagens prontas. A equipe edita nomeNegocio, pedidosAbertos e tempoEstimado. Não vamos tentar transformar a frase “Tempo estimado…” de volta em um número.

Leia a configuração que já está salva

Ao confirmar a sessão, lerConfiguracao busca os dados atuais. config guarda essa configuração; o campo de prazo fica em um estado de texto porque um input entrega texto e também precisa representar vazio.

Conferir cliente-balcao/src/componentes/Operador.tsx

Caminho a partir da raiz da aplicação. Abra o arquivo no VS Code e compare com a explicação desta etapa.

import { useEffect, useState } from "react";
import type { Configuracao, Produto, Sessao } from "../servicos/api.js";
import { gravarConfiguracao, lerConfiguracao, mudarSessao } from "../servicos/api.js";


interface Props { sessao: Sessao; aoMudarSessao: (s: Sessao) => void; produtos: Produto[]; aoRecarregarProdutos: (preservar?: boolean) => Promise<void> }

export function Operador({ sessao, aoMudarSessao, produtos, aoRecarregarProdutos }: Props) {
  const [usuario, setUsuario] = useState("");
  const [senha, setSenha] = useState("");
  const [config, setConfig] = useState<Configuracao | null>(null);
  const [prazo, setPrazo] = useState("");
  const [aviso, setAviso] = useState("");
  const [ocupado, setOcupado] = useState(false);
  useEffect(() => {
    let ativo = true;
    if (!sessao.autenticado) { setConfig(null); return; }
    void lerConfiguracao().then(d => {
      if (ativo) { setConfig(d); setPrazo(d.tempoEstimado === null ? "" : String(d.tempoEstimado)); }
    }).catch(() => { if (ativo) setAviso("Não foi possível consultar a configuração. Atualize sua sessão."); });
    return () => { ativo = false; };
  }, [sessao.autenticado]);

  async function entrar(evento: React.FormEvent) {
    evento.preventDefault(); setOcupado(true);
    try {
      const atual = await mudarSessao(sessao, { acao: "entrar", usuario, senha });
      setSenha(""); aoMudarSessao(atual); setAviso("Sessão confirmada pelo servidor.");
      await aoRecarregarProdutos();
    } catch (e) { setAviso(e instanceof Error ? e.message : "Falha no acesso."); }
    finally { setOcupado(false); }
  }
  async function salvar(evento: React.FormEvent) {
    evento.preventDefault(); if (!config) return; setOcupado(true);
    try {
      if (prazo !== "" && !/^(0|[1-9][0-9]{0,2})$/.test(prazo)) throw new Error("Informe minutos inteiros ou deixe vazio.");
      const minutos = prazo === "" ? null : Number(prazo);
      if (minutos !== null && minutos > 240) throw new Error("O limite combinado neste formulário é 240 minutos.");
      await gravarConfiguracao(sessao, { ...config, tempoEstimado: minutos });
      setAviso("Aviso salvo no servidor. Consulte o balcão para conferir.");
    } catch (e) { setAviso(e instanceof Error ? e.message : "Não foi possível salvar."); }
    finally { setOcupado(false); }
  }
  async function sair() {
    setOcupado(true);
    try {
      aoMudarSessao(await mudarSessao(sessao, { acao: "sair" }));
      setConfig(null); setAviso("Você saiu da área de edição.");
      await aoRecarregarProdutos();
    } catch { setAviso("Não foi possível sair. Tente novamente."); }
    finally { setOcupado(false); }
  }
  return <section><h2>Área do operador</h2>
    {!sessao.autenticado ? <form onSubmit={e => void entrar(e)}>
      <p><label htmlFor="usuario">Usuário local</label><input id="usuario" value={usuario} autoComplete="username" required onChange={e => setUsuario(e.target.value)} /></p>
      <p><label htmlFor="senha">Senha</label><input id="senha" type="password" value={senha} autoComplete="current-password" required onChange={e => setSenha(e.target.value)} /></p>
      <button disabled={ocupado || !sessao.csrfToken}>Entrar</button>
    </form> : <>
      <button disabled={ocupado} onClick={() => void sair()}>Sair da edição</button>
      {config && <form onSubmit={e => void salvar(e)}>
        <p><label htmlFor="nome-cafe">Nome do Café</label><input id="nome-cafe" value={config.nomeNegocio} maxLength={100} required onChange={e => setConfig({ ...config, nomeNegocio: e.target.value })} /></p>
        <p><label htmlFor="pedidos">Situação dos pedidos</label><select id="pedidos" value={config.pedidosAbertos ? "aberto" : "encerrado"} onChange={e => setConfig({ ...config, pedidosAbertos: e.target.value === "aberto" })}><option value="aberto">Abertos</option><option value="encerrado">Encerrados</option></select></p>
        <p><label htmlFor="prazo">Minutos para retirada</label><input id="prazo" type="number" min="0" max="240" step="1" value={prazo} onChange={e => setPrazo(e.target.value)} aria-describedby="ajuda-prazo" /><span id="ajuda-prazo">Vazio significa que a equipe ainda não informou a estimativa.</span></p>
        <button disabled={ocupado}>Salvar aviso</button>
      </form>}
    </>}
    <p role="status">{aviso}</p>
  </section>;
}

O formulário é controlado pelos estados. Em setConfig({ ...config, nomeNegocio: ... }), o espalhamento preserva os outros campos e muda apenas o nome. Não criamos um objeto incompleto que perderia a situação dos pedidos.

Vazio não significa zero

Faça o build, entre e apague os minutos. Salve e consulte o atendimento público: a equipe ainda não informou prazo. Agora escreva zero, salve e consulte novamente. São condições diferentes, por isso a conversão acontece de forma explícita antes do envio.

A verificação local recusa texto inadequado e valores acima do limite do exercício. O servidor repete a validação, pois o visitante pode enviar uma requisição sem usar esse formulário. Tipo TypeScript e atributo min ajudam no navegador; não substituem a regra do PHP.

A mensagem “salvo” aparece depois de o serviço confirmar a escrita. Ela não deve aparecer só porque a pessoa apertou o botão. O cliente do Café ainda precisa fazer uma nova consulta para receber o aviso atualizado.

Teste a recusa sem perder o dado anterior

Informe um valor inválido e confirme que o valor salvo não mudou. Teste pedidos encerrados com prazo preenchido: o aviso de encerramento precisa prevalecer. Saia da edição e tente voltar ao formulário. A consulta pública deve continuar funcionando mesmo sem acesso privado.

Se a sessão ficar indisponível durante a edição, a aplicação informa que não confirmou a operação. O texto digitado não se transforma em dado válido por estar visível no formulário. Volte a entrar e consulte a configuração para conferir o estado real.

A confirmação corresponde ao banco?

Registre alteração aceita, entrada recusada, zero, prazo ausente e encerramento. Mostre a mudança em outra aba de visitante. A próxima tarefa terá outro cuidado: permitir revisar uma descrição do catálogo sem publicá-la antes da decisão da equipe.
