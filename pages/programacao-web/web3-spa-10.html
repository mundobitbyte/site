Outra pasta também precisa funcionar

Web III — Em desenvolvimento.

Na sua máquina a consulta e a edição funcionaram. Uma colega recebeu os arquivos, porém, e encontrou uma lista vazia. Precisamos descobrir se faltou preparar o banco, instalar dependências, fazer o build ou corrigir algum comportamento da interface.

Uma captura de tela não responde a essas perguntas. Vamos reunir testes que observam decisões importantes e repetir a preparação em uma pasta limpa.

Preparar os arquivos desta etapa

Baixar a referência da etapa 10. Ela contém a aplicação ao final desta etapa; não é uma nova tarefa nem uma substituição automática da sua solução.

Continue na sua pasta de trabalho que concluiu a etapa 9 deste percurso. A raiz é o lugar onde aparecem public e cliente-balcao. Não crie uma pasta cafe-aurora-web3 dentro dessa raiz.

  1. Salve os arquivos e pare o servidor antes de copiar dados. Preserve uma cópia da pasta atual.

  3. Compare os caminhos listados abaixo com sua pasta de trabalho. Acrescente os arquivos de apoio que ainda não existem. Para um arquivo já existente, compare a alteração antes de aplicá-la: não apague uma mudança sua sem entender a diferença. Os arquivos discutidos na aula são os que vamos construir e compreender.

Preserve dados, credenciais locais, .env e as dependências já instaladas. Uma pasta ausente no ZIP não é uma instrução para apagar sua cópia. A aula informa quando executar Composer, npm, migration ou build; copiar arquivos não executa esses preparos.

Automatize perguntas que já fizemos

Vitest executa testes do projeto. Testing Library ajuda a observar a interface pelos elementos que a pessoa utiliza. O ambiente jsdom representa o documento para esses testes; não substitui um navegador real nem comprova responsividade.

Conferir cliente-balcao/src/regras.test.ts

Caminho a partir da raiz da aplicação. Abra o arquivo no VS Code e compare com a explicação desta etapa.

import { expect, test } from "vitest";
import { conferirDescricao, filtrarProdutos } from "./regras.js";
import type { Produto } from "./servicos/api.js";

test("buscar combina nome e categoria sem alterar o cardápio recebido", () => {
  const produtos = [{id:"cafe",nome:"Café coado",categoria:"bebida"},{id:"pao",nome:"Pão",categoria:"comida"}] as Produto[];
  expect(filtrarProdutos(produtos," CAFÉ ","bebida").map(p=>p.id)).toEqual(["cafe"]);
  expect(filtrarProdutos(produtos,"CAFÉ","comida")).toEqual([]);
  expect(produtos).toHaveLength(2);
});
test("uma descrição curta ou longa demais não vira publicação", () => {
  expect(()=>conferirDescricao("curta")).toThrow();
  expect(()=>conferirDescricao("x".repeat(401))).toThrow();
  expect(conferirDescricao("  Café preparado com cuidado.  ")).toBe("Café preparado com cuidado.");
});

import { afterEach, beforeEach, expect, test, vi } from "vitest";
import { cleanup, fireEvent, render, screen, waitFor } from "@testing-library/react";
const mocks=vi.hoisted(()=>({obter:vi.fn()}));
vi.mock("./atendimento.js",()=>({obterAtendimento:mocks.obter}));
vi.mock("./servicos/api.js",()=>({consultarSessao:vi.fn(async()=>({autenticado:false,csrfToken:"ficticio"})),lerProdutos:vi.fn(async()=>[])}));
import { App } from "./App.js";
beforeEach(()=>{history.replaceState(null,"","/#atendimento");mocks.obter.mockReset();});
afterEach(cleanup);

test("uma consulta em andamento não aceita um segundo pedido e pode ser repetida após falha", async()=>{
  let falhar!: (erro:Error)=>void;
  mocks.obter.mockImplementationOnce(()=>new Promise((_r,reject)=>{falhar=reject;}));
  render(<App/>);
  const botao=screen.getByRole("button",{name:"Atualizar atendimento"});
  fireEvent.click(botao);fireEvent.click(botao);
  expect(mocks.obter).toHaveBeenCalledTimes(1);
  expect((botao as HTMLButtonElement).disabled).toBe(true);
  falhar(new Error("Sem conexão"));
  await screen.findByText("Não foi possível consultar. Tente novamente.");
  mocks.obter.mockResolvedValueOnce({nomeNegocio:"Café Aurora",mensagemStatus:"Pedidos abertos.",mensagemTempo:"Tempo estimado: 47 minutos."});
  fireEvent.click(botao);
  await screen.findByText("Tempo estimado: 47 minutos.");
  expect((botao as HTMLButtonElement).disabled).toBe(false);
});

test("trocar de área usa o hash sem reconstruir o documento e atualiza o título focável", async()=>{
  render(<App/>);
  location.hash="cardapio";window.dispatchEvent(new HashChangeEvent("hashchange"));
  await waitFor(()=>expect(screen.getByRole("heading",{level:1}).textContent).toContain("Cardápio"));
  expect(document.activeElement).toBe(screen.getByRole("heading",{level:1}));
  expect(screen.getByRole("link",{name:"Cardápio"}).getAttribute("aria-current")).toBe("page");
});
Conferir cliente-balcao/src/componentes/EditorProduto.test.tsx

Caminho a partir da raiz da aplicação. Abra o arquivo no VS Code e compare com a explicação desta etapa.

import { afterEach, expect, test, vi } from "vitest";
import { cleanup, fireEvent, render, screen } from "@testing-library/react";
const mocks=vi.hoisted(()=>({gravar:vi.fn(async()=>{})}));
vi.mock("../servicos/api.js",()=>({gravarProduto:mocks.gravar}));
import { EditorProduto } from "./EditorProduto.js";
import type { Produto } from "../servicos/api.js";
afterEach(()=>{cleanup();mocks.gravar.mockClear();});
test("rascunho exige confirmação separada e continua editável depois da atualização da lista",async()=>{
  const produto:Produto={id:"cafe",nome:"Café",categoria:"bebida",precoCentavos:800,imagem:"cafe.webp",alt:"Xícara de café",descricao:"Descrição pública anterior.",disponivel:true,rascunho:null};
  const sessao={autenticado:true,csrfToken:"ficticio"};
  const atualizar=vi.fn(async()=>{});
  const ui=render(<EditorProduto produto={produto} sessao={sessao} aoSalvar={atualizar}/>);
  const publicar=screen.getByRole("button",{name:"Publicar rascunho salvo"}) as HTMLButtonElement;
  expect(publicar.disabled).toBe(true);
  fireEvent.change(screen.getByRole("textbox",{name:"Descrição"}),{target:{value:"Descrição revisada pela equipe."}});
  fireEvent.click(screen.getByRole("button",{name:"Salvar rascunho"}));
  await screen.findByText("Rascunho salvo. O visitante ainda vê a descrição anterior.");
  expect(mocks.gravar).toHaveBeenLastCalledWith(sessao,"cafe","Descrição revisada pela equipe.","rascunho");
  ui.rerender(<EditorProduto produto={{...produto,rascunho:"Descrição revisada pela equipe."}} sessao={sessao} aoSalvar={atualizar}/>);
  expect(publicar.disabled).toBe(false);
  fireEvent.click(publicar);
  await screen.findByText("Descrição publicada após confirmação.");
  expect(mocks.gravar).toHaveBeenLastCalledWith(sessao,"cafe","Descrição revisada pela equipe.","publicar");
});

Os cinco testes conferem filtro combinado sem perda da lista, limites da descrição, uma consulta em andamento com falha e recuperação, navegação/foco e confirmação separada de publicação. As respostas controladas permitem observar essas decisões sem depender de uma rede externa.

Em cliente-balcao, execute npm test. Leia cada falha antes de alterar o código. Uma resposta simulada em um teste não demonstra que o PHP real gravou no banco; essa parte precisa ser conferida na integração da aplicação.

Prepare uma cópia que não dependa da sua primeira pasta

Extraia a referência em uma pasta nova. Na raiz, execute php src/inicializar-banco.php, php src/inicializar-atendimento.php e php src/inicializar-cardapio.php, um por vez. Depois crie a identidade fictícia com php src/criar-administrador.php. Instale com npm ci, faça npm run build e inicie o PHP na raiz da nova cópia. Confira qual terminal está atendendo a porta 8000 para não testar a pasta antiga sem perceber.

Consulte, filtre, entre, altere o prazo, salve um rascunho e publique. Use uma janela sem sessão para conferir os dados públicos. Teste também resposta inválida e indisponibilidade; restaure os serviços e demonstre recuperação.

Volte à experiência da pessoa

Use os links com teclado, confira o foco após a navegação e leia as orientações sem depender de cor. Reduza a largura da janela e aumente o texto. As imagens precisam manter alternativas e os campos precisam de rótulos. Registre o navegador e a largura utilizados.

Abra a página inicial e o formulário de mensagens do projeto anterior. A evolução do balcão não autoriza perder esses caminhos. Não inclua senhas, banco pessoal, dependências instaladas ou JavaScript antigo apenas para esconder um build ausente.

Você consegue reproduzir e explicar?

Entregue fonte, preparo e evidências, separando testes executados dos não executados. Explique por que um estado local, um rascunho salvo e uma descrição publicada são coisas diferentes. Seu percurso React termina aqui; siga para a entrega comum, sem precisar desenvolver os outros dois caminhos.
