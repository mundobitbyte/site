Web III · Interface com React

O componente consulta o atendimento

Web III — Em desenvolvimento.

Abrir a orientação muda apenas a tela. Para saber se os pedidos continuam abertos, precisamos perguntar ao servidor. Vamos recolocar no balcão React a consulta que você já construiu no Capítulo 2.

O arquivo atendimento.ts continua com a função de consulta, o prazo máximo de espera e a conferência de unknown. Reutilizá-lo preserva uma regra importante: a interface não apresenta como atendimento uma resposta incompleta.

Três estados que o visitante percebe

Precisamos representar os dados confirmados, se há uma consulta em andamento e a orientação de retorno. Quando a consulta começa, retiramos o aviso anterior; quando termina com sucesso, mostramos a nova resposta; quando falha, explicamos como tentar novamente.

Conferir cliente-balcao/src/App.tsx

Caminho a partir da raiz da aplicação. Abra o arquivo no VS Code e compare com a explicação desta etapa.

import {useState,useRef} from "react";
import {obterAtendimento} from "./atendimento.js";
import type {Atendimento as Dados} from "./atendimento.js";
import {Atendimento} from "./componentes/Atendimento.js";
export function App(){
 const [dados,setDados]=useState<Dados|null>(null);
 const [consultando,setConsultando]=useState(false);
 const [aviso,setAviso]=useState("Consulte para confirmar o atendimento.");
 const consultaAtiva=useRef(false);
  async function consultar() {
    if (consultaAtiva.current) return;
    const foco = document.activeElement;
    consultaAtiva.current = true; setConsultando(true); setDados(null); setAviso("Consultando o atendimento…");
    try { setDados(await obterAtendimento()); setAviso("Atendimento consultado agora."); }
    catch { setAviso("Não foi possível consultar. Tente novamente."); }
    finally {
      consultaAtiva.current = false; setConsultando(false);
      requestAnimationFrame(() => { if (foco instanceof HTMLButtonElement && document.activeElement === document.body) foco.focus({ preventScroll: true }); });
    }
  }

 return <><h1>Café Aurora · Balcão</h1><Atendimento dados={dados} consultando={consultando} aviso={aviso} aoConsultar={()=>void consultar()}/></>;
}

Dados | null admite ausência de atendimento confirmado. A interface TypeScript Atendimento foi importada com o apelido Dados porque agora também existe um componente chamado Atendimento. O primeiro descreve dados; o segundo apresenta a interface.

useRef guarda uma referência entre apresentações sem ser, por si, uma informação mostrada. Usamos consultaAtiva.current para impedir outro pedido enquanto o primeiro está em andamento. Já consultando controla o estado visual do botão.

Conferir cliente-balcao/src/componentes/Atendimento.tsx

Caminho a partir da raiz da aplicação. Abra o arquivo no VS Code e compare com a explicação desta etapa.

import type { Atendimento as Dados } from "../atendimento.js";

interface Props { dados: Dados | null; consultando: boolean; aviso: string; aoConsultar: () => void }

export function Atendimento({ dados, consultando, aviso, aoConsultar }: Props) {
  return <section aria-labelledby="titulo-atendimento">
    <h2 id="titulo-atendimento">Atendimento no balcão</h2>
    {dados && <><h3>{dados.nomeNegocio}</h3><p>{dados.mensagemStatus}</p><p>{dados.mensagemTempo}</p></>}
    <button type="button" disabled={consultando} onClick={aoConsultar}>Atualizar atendimento</button>
    <p role="status">{aviso}</p>
  </section>;
}

O componente recebe os dados e a ação de consultar por props. Ele não precisa conhecer o endereço da API. disabled informa a espera; role="status" identifica o retorno para tecnologias assistivas. Observe como dados, ação e apresentação se relacionam sem misturar seus papéis.

Repita uma experiência que você já conhece

Faça o build e consulte o balcão. Mude o prazo no PHP de referência e consulte novamente, sem recarregar o documento. Depois teste pedidos encerrados e prazo ausente. O contrato continua com nomeNegocio, mensagemStatus e mensagemTempo; não substituímos esses campos pelos valores brutos da configuração.

Use uma das respostas inválidas ensinadas no Capítulo 2 e confira se a mensagem antiga desaparece, o erro é comunicado e o botão volta a funcionar. Restaure a API válida e consulte outra vez. Não precisamos estudar novamente toda a aula de Promise ou fetch: estamos reaproveitando o que ela permitiu construir.

A mudança de interface preservou o comportamento?

Mostre consulta, espera, recusa de resposta inválida e recuperação. Compare com a experiência anterior em JavaScript/TypeScript: mudou a organização da tela; a responsabilidade de conferir a resposta permaneceu. Agora podemos consumir outra informação do Café: a lista de produtos.
