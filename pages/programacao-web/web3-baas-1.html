Web III · Serviços com Firebase

A mesma informação em outro serviço

Web III — Em desenvolvimento.

O balcão sabe consultar, mas a equipe ainda depende de editar o PHP para mudar o aviso. Neste percurso, vamos investigar outra possibilidade: usar serviços que oferecem dados, identidade e operações de servidor, começando em um ambiente local de exercício.

BaaS significa backend como serviço. Isso não faz o backend desaparecer: parte da infraestrutura e das operações passa a ser oferecida por uma plataforma. Firebase reúne diferentes serviços; vamos acrescentá-los por necessidade, sem pedir cartão ou contratar um plano para começar.

Preparar os arquivos desta etapa

Baixar a referência da etapa 1. Ela contém a aplicação ao final desta etapa; não é uma nova tarefa nem uma substituição automática da sua solução.

Se você já tinha uma bancada em uso na referência anterior, confira a orientação abaixo antes de encerrar os emuladores. Primeiro guardamos a sessão; depois atualizamos os arquivos.

Já começou com uma referência que não tinha o comando retomar?

Se npm run retomar informar “Missing script”, não recomece o Café. Essa cópia ainda usa os comandos da referência anterior. Antes de fechar os emuladores antigos, abra outro terminal na mesma raiz, com as ferramentas locais já instaladas, e guarde a sessão:

npx firebase emulators:export ./dados-emuladores --project demo-cafe-aurora-web3

Aguarde a conclusão e confira dados-emuladores/firebase-export-metadata.json. Se já houver uma exportação, confira qual cópia quer preservar antes de confirmar sua substituição. Então encerre o terminal antigo com Ctrl+C.

Compare o package.json e o .gitignore do download desta etapa com os seus. Incorpore os scripts emuladores e retomar e a exclusão de dados-emuladores, preservando as demais configurações. Agora execute npm run retomar e confira o atendimento antes de continuar.

Se os emuladores já estavam fechados e não existe exportação, essa sessão não pode ser recuperada por trocar um comando. O início e o preparo da primeira etapa recriam apenas os dados iniciais; uma imagem ou descrição não exportada terá de ser refeita. Sua aplicação e seus arquivos-fonte continuam preservados.

Extraia em uma pasta nova, por exemplo cafe-aurora-servicos, e abra no VS Code a pasta interna cafe-aurora-web3. Ela já reaproveita as imagens e o cardápio do Café. Sua aplicação PHP anterior fica preservada em outra pasta.

Prepare uma bancada para os serviços

Preserve seu Café PHP anterior. Extraia a referência desta etapa em uma pasta nova para os serviços. Ela reaproveita HTML, CSS, imagens e produtos do mesmo Café; você não vai reconstruir essas páginas à mão. As mensagens do Web II continuam na aplicação PHP preservada, não em uma hospedagem estática que prometa executar PHP.

Use Node 22 e Java 21 neste percurso. Confira node --version, npm --version e java -version antes de continuar. O TypeScript Essencial utilizou Node 24; aqui a escolha de Node 22 corresponde ao runtime das Functions que acrescentaremos mais adiante. Se o laboratório não tiver essa combinação, prepare-a com o professor antes da aula. Não tente corrigir incompatibilidade com --force.

Como preparar essa combinação no Windows sem substituir o Node do projeto anterior?

O Java é usado pelos emuladores; você não vai programar em Java nesta atividade. Podemos usar ferramentas extraídas de arquivos ZIP e selecioná-las somente nos terminais desta bancada.

  1. No site oficial do Node.js, escolha a linha 22 e o arquivo ZIP para a arquitetura do computador. A referência validada é 22.23.4. Em Windows x64, use o pacote win-x64.
  2. No site do Eclipse Temurin, escolha JDK 21, Windows e a arquitetura correspondente, em formato ZIP.
  3. Crie ferramentas dentro da sua pasta de usuário. Extraia e organize as pastas para que existam %USERPROFILE%\ferramentas\node22\node.exe e %USERPROFILE%\ferramentas\java21\bin\java.exe. O nome original da pasta extraída pode ser mais longo; ajuste a pasta, sem mover apenas o executável para fora de seus demais arquivos.
  4. No VS Code, abra um terminal com perfil Prompt de Comando / Command Prompt. O comando abaixo usa a sintaxe desse terminal, não a do PowerShell.
set "PATH=%USERPROFILE%\ferramentas\node22;%USERPROFILE%\ferramentas\java21\bin;%PATH%"
node --version
npm --version
java -version
where node
where java

PATH é a lista de lugares em que o terminal procura programas. O comando coloca as ferramentas desta bancada na frente somente nessa janela. As primeiras localizações mostradas por where precisam corresponder às pastas que você preparou. Se estiverem diferentes, confira a extração antes de instalar dependências.

Repita o comando set em cada segundo terminal usado para preparar dados ou Functions. Deixe o primeiro livre para manter os emuladores em execução. Ao fechar esses terminais, a seleção temporária termina; o ambiente anterior do VS Code não foi substituído. No laboratório já preparado, use os caminhos informados pelo professor.

A suíte de emuladores executa versões locais dos serviços. Na raiz da nova pasta, use npm ci. Em cliente-balcao, use npm ci e npm run build. Depois volte à raiz e execute npm run emuladores. Deixe esse terminal aberto; a primeira execução pode precisar baixar componentes.

Uma consulta ao serviço de dados

Em outro terminal na raiz, execute npm run preparar. O preparo inclui um atendimento fictício e identidades de exercício, sem sobrescrever o aviso já existente. Ele está limitado aos endereços locais e ao projeto demo-cafe-aurora-web3; não administra um projeto de nuvem.

Abra http://localhost:5000 e consulte o atendimento. A interface dos emuladores fica em http://localhost:4000. Não usamos a porta 8000 do PHP para esta nova consulta.

Conferir cliente-balcao/src/servico.ts

Caminho a partir da raiz da aplicação. Abra o arquivo no VS Code e compare com a explicação desta etapa.

import {initializeApp} from "firebase/app";
import {getFirestore,connectFirestoreEmulator} from "firebase/firestore";
import {modo,configuracao} from "./ambiente.js";
if(modo==="local" && !["localhost","127.0.0.1"].includes(location.hostname))throw new Error("Abra pelo endereço do emulador local.");
export const app=initializeApp(configuracao);
export const banco=getFirestore(app);
if(modo==="local")connectFirestoreEmulator(banco,"127.0.0.1",8080);

O SDK, conjunto de bibliotecas do serviço, é conectado explicitamente ao emulador Firestore. O Firestore organiza dados em coleções e documentos. Nosso endereço lógico é a coleção atendimento, documento atual.

Conferir cliente-balcao/src/dados.ts

Caminho a partir da raiz da aplicação. Abra o arquivo no VS Code e compare com a explicação desta etapa.

import { doc, getDocFromServer, onSnapshot, updateDoc } from "firebase/firestore";
import { banco } from "./servico.js";
import { conferirConfiguracao, prepararMensagens } from "./atendimento.js";
import type { Atendimento, Configuracao } from "./atendimento.js";

const referencia = doc(banco, "atendimento", "atual");
export async function obterAtendimento(): Promise<Atendimento> {
  const foto = await getDocFromServer(referencia);
  if (foto.metadata.hasPendingWrites) throw new Error("Aguardando confirmação do serviço.");
  if (!foto.exists()) throw new Error("Prepare o atendimento do exercício.");
  return prepararMensagens(conferirConfiguracao(foto.data()));
}

export async function alterarAtendimento(dados: Configuracao): Promise<void> {
  await updateDoc(referencia, { ...conferirConfiguracao(dados) });
}

O documento guarda os valores brutos conhecidos: nome, situação e minutos. O código confere esses valores e prepara as três mensagens para a apresentação. Não tenta extrair um número da frase do prazo.

Guarde a bancada para continuar depois

Você não precisa refazer os dados a cada aula. O comando npm run emuladores desta referência inicia uma bancada e prepara a exportação ao encerrar. No terminal dos emuladores, pressione Ctrl+C uma vez e aguarde a conclusão. Deve surgir dados-emuladores/firebase-export-metadata.json na raiz, junto dos dados exportados de Auth e Firestore. Essa pasta guarda a sessão do exercício; ela não está no download.

Na próxima abertura, na mesma raiz, use:

npm run retomar

Esse comando importa a pasta guardada e volta a exportar quando você encerrar corretamente. Consulte o atendimento e confira que o valor anterior permaneceu. A partir da etapa da imagem, a exportação também poderá preservar Storage. O nome dos serviços não muda a cada retomada; o que importa é manter a pasta e conferir o encerramento.

Se a pasta não existe porque o processo foi fechado à força ou você está em uma cópia nova, comece com npm run emuladores e execute npm run preparar no segundo terminal. Isso recupera os dados iniciais conhecidos, não uma alteração que não chegou a ser exportada. Não publique dados-emuladores: ela pode conter identidades e arquivos do exercício. A referência inclui essa exclusão no .gitignore.

Você sabe de onde veio o aviso?

Mostre o documento no emulador e a consulta nas duas páginas. Encerre o emulador corretamente e observe a falha; use npm run retomar para recuperar a sessão. Reiniciar não equivale a persistir dados em nuvem. A consulta funciona sem conta de visitante; a próxima necessidade é reconhecer a equipe que poderá alterar.
