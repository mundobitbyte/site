Web III — Em desenvolvimento.

O objeto reuniu as regras do aviso. Porém, ao abrir a aplicação, ainda precisamos procurar arquivos para descobrir quem recebe uma consulta e quem monta a página. Isso fica mais difícil quando o Café ganha uma área de edição.

Vamos organizar uma única parte primeiro: a consulta do atendimento. O balcão continuará sendo o mesmo consumidor de JSON, as imagens e o CSS continuarão sendo os do Café e as mensagens do Web II permanecerão preservadas. A conquista desta etapa será enxergar a página funcionando através de um caminho organizado.

Prepare o ambiente sem substituir seu projeto

Preserve uma cópia da pasta e do banco antes de experimentar. No Windows, usaremos o terminal do Laragon para disponibilizar o PHP ao VS Code. O servidor que abrirá a aplicação nesta aula será iniciado por um comando; não é preciso instalar XAMPP ou WAMP junto. Confira php -v, php --ini, php -m e composer --version. O kit usa PHP 8.5, Laravel 13 e extensões PDO SQLite, mbstring, XML/DOM e OpenSSL. SOAP será necessário em uma etapa posterior.

Laragon organiza o ambiente local. Na política consultada em 28/10/2026, há uso não comercial sem licença paga, com lembrete de licença e sem atualização automática. A prática não exige comprar uma licença. Use uma instalação da escola ou a modalidade permitida para o exercício. Composer instala bibliotecas PHP e suas dependências. Laravel é um framework: oferece uma estrutura para receber requisições, aplicar regras e devolver respostas. VS Code continua sendo o editor. Nenhuma dessas ferramentas elimina a necessidade de compreender o PHP.

Baixe os arquivos desta etapa pelo link ao final. Compare os arquivos com sua pasta anterior: src, public/css, public/img e dados pertencem ao mesmo Café. As pastas novas app, bootstrap, config, resources e routes, além de artisan e dos arquivos Composer, formam a estrutura de apoio fornecida. Não é necessário redigitar as configurações do framework.

Na cópia de trabalho, acrescente essa estrutura e aplique os arquivos apresentados abaixo. Não substitua dados nem suas credenciais por uma pasta vazia do download. Pelo explorador do VS Code, copie .env.example para .env somente se ainda não existir. .env guarda a configuração local e não vai para o Git nem para o download da turma.

composer install --no-interaction --no-plugins
php artisan key:generate

Execute na raiz, onde estão composer.json e artisan. install segue o composer.lock; update mudaria versões. key:generate prepara a chave da aplicação. Não gere outra chave a cada aula. Esta etapa usa sessões e cache em arquivos locais; ainda não precisa criar uma nova tabela.

Uma requisição, três responsabilidades

Ao visitar /atendimento, uma rota escolhe o código que atenderá o endereço. Um controller coordena a consulta. Uma view monta o HTML. Nossa classe continua preparando as mensagens. Essa separação conduz ao padrão MVC: Model representa os dados e regras; View apresenta; Controller coordena a requisição.

Conferir routes/web.php

Caminho a partir da raiz da aplicação. Abra o arquivo no VS Code e compare com a explicação desta etapa.

<?php
use Illuminate\Support\Facades\Route;
Route::get('/',fn()=>view('inicio-legado'));
Route::get('/atendimento',[\App\Http\Controllers\AtendimentoController::class,'mostrar']);
Route::get('/api/atendimento',[\App\Http\Controllers\AtendimentoController::class,'publico']);
Route::get('/api/atendimento.php',[\App\Http\Controllers\AtendimentoController::class,'publico']);
Conferir app/Http/Controllers/AtendimentoController.php

Caminho a partir da raiz da aplicação. Abra o arquivo no VS Code e compare com a explicação desta etapa.

<?php
namespace App\Http\Controllers;
class AtendimentoController {
 public function mostrar(){require_once base_path('src/atendimento.php');return view('atendimento',['dados'=>obterAtendimento()]);}
 public function publico(){require_once base_path('src/atendimento.php');return response()->json(obterAtendimento())->header('Cache-Control','no-store');}
}
Conferir resources/views/atendimento.blade.php

Caminho a partir da raiz da aplicação. Abra o arquivo no VS Code e compare com a explicação desta etapa.

@extends('layout')
@section('titulo','Atendimento')
@section('conteudo')
<h1>{{ $dados['nomeNegocio'] }}</h1><p>{{ $dados['mensagemStatus'] }}</p><p>{{ $dados['mensagemTempo'] }}</p>
@endsection

Na view, @extends reaproveita o layout e @section preenche uma parte dele. {{ $dados['nomeNegocio'] }} imprime o nome com escape de HTML. Blade é o sistema de templates do Laravel; evita duplicar cabeçalho e rodapé em cada tela.

O ponto de entrada também muda: public/index.php inicia o Laravel. A antiga página inicial está preservada em resources/views/inicio-legado.blade.php. O download inclui essa adaptação; “legado” significa o que já existia, não algo que precisamos descartar.

Abra pelo servidor certo

Encerre o servidor PHP anterior com Ctrl+C antes de usar novamente a porta 8000. Na raiz, execute:

php artisan serve --host=localhost --port=8000

Abra http://localhost:8000/atendimento, depois /api/atendimento e /balcao.php. A rota /api/atendimento.php também foi mantida: assim o TypeScript existente continua consultando o mesmo endereço. Se extraiu uma cópia nova, faça o build de cliente-balcao antes de testar o balcão.

Para conhecer o apoio de geração de arquivos, execute php artisan help make:controller. O comando php artisan make:controller AtendimentoController gera o esqueleto quando o arquivo ainda não existe; não o execute para substituir nosso controller pronto. Esse apoio à criação é chamado de scaffolding. O código gerado precisa receber as regras reais da aplicação.

O que deve continuar igual?

A página inicial abre, a nova página mostra o aviso e o balcão recebe os mesmos três campos. Use php artisan route:list para localizar os endereços que você abriu. Se aparecer erro de extensão ou versão, resolva o ambiente antes de alterar regras do Café. Agora que os caminhos estão organizados, falta permitir que o prazo sobreviva sem ficar escrito na criação do objeto.
