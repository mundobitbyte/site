Módulo 5 · IA e Programação

Você herdou um programa que funciona. Agora precisa fazê-lo evoluir sem perder o controle.

O laboratório de informática da escola empresta notebooks, kits Arduino e câmeras para aulas e projetos. Um aluno começou um pequeno programa em Python para registrar os empréstimos, mas deixou o curso antes de terminar. O código funciona para um caso simples — e agora ficou com você.

Durante este módulo, o mesmo projeto receberá novos pedidos, apresentará erros, precisará guardar dados, ganhará testes e será preparado para outra pessoa continuar. A IA participará de todas essas etapas, mas com uma regra: ela ajuda a investigar e modificar; você continua responsável por compreender, decidir e comprovar.

Regra central

Se você não consegue explicar o que mudou, por que mudou e como comprovou que funciona, a tarefa ainda não terminou — mesmo que o código tenha sido escrito pela IA.

Antes de começar — este módulo não ensina Python do zero

Você não precisa ser especialista, mas precisa reconhecer o básico para que a IA não vire um atalho que esconda aquilo que você ainda não aprendeu.

  • Variáveis e entrada/saída com input e print.
  • Decisões com if, elif e else.
  • Funções simples com parâmetros e return.
  • Listas ou dicionários em situações básicas.
  • Executar um programa e localizar uma mensagem de erro.

Se isso ainda estiver novo demais

Volte primeiro para Programação de Computadores. Aqui vamos aprender a trabalhar com IA durante o desenvolvimento, não substituir os fundamentos da linguagem.

1. Segunda-feira — o projeto chega às suas mãos

O professor entrega um arquivo chamado app.py. Antes de pedir “melhore esse código”, você precisa descobrir o que já existe e o que realmente funciona.

    "CAM01": {"nome": "Câmera 01", "disponivel": True},
    "ARD01": {"nome": "Kit Arduino 01", "disponivel": True}
}


def emprestar(codigo):
    codigo = codigo.strip().upper()
    item = equipamentos.get(codigo)

    if item is None:
        return "Equipamento não encontrado."

    if not item["disponivel"]:
        return "Equipamento indisponível."

    item["disponivel"] = False
    return f'{item["nome"]} emprestado com sucesso.'


codigo = input("Código do equipamento: ")

9. Verifique a API antes de confiar em um nome convincente

LEIA — exemplo proposital de sugestão errada da IA

Imagine que a IA sugira Path.makedirs() para criar a pasta. Não coloque isso no projeto. O nome parece plausível, mas esse método não existe em pathlib.Path.

PROMPT PARA A IA — exija verificabilidade

Você sugeriu Path.makedirs(). Antes de alterar meu código, indique a classe e o método exatos que está assumindo, os parâmetros relevantes e o que devo confirmar na documentação oficial do Python. Se o método sugerido não existir, corrija a orientação sem inventar outro.

Para este caso, o método correto é Path.mkdir(). Antes de salvar, podemos criar a pasta com ARQUIVO_DADOS.parent.mkdir(parents=True, exist_ok=True).

Checkpoint 2 — persistência funcionando

import json
from pathlib import Path

ARQUIVO_DADOS = Path("dados/equipamentos.json")


def criar_dados_iniciais():
    return {
        "NB01": {
            "nome": "Notebook 01",
            "disponivel": True,
            "emprestado_para": None
        },
        "CAM01": {
            "nome": "Câmera 01",
            "disponivel": True,
            "emprestado_para": None
        },
        "ARD01": {
            "nome": "Kit Arduino 01",
            "disponivel": True,
            "emprestado_para": None
        }
    }


def carregar_dados():
    if not ARQUIVO_DADOS.exists():
        return criar_dados_iniciais()

    with ARQUIVO_DADOS.open("r", encoding="utf-8") as arquivo:
        return json.load(arquivo)


def salvar_dados(dados):
    ARQUIVO_DADOS.parent.mkdir(parents=True, exist_ok=True)

    with ARQUIVO_DADOS.open("w", encoding="utf-8") as arquivo:
        json.dump(dados, arquivo, ensure_ascii=False, indent=2)


equipamentos = carregar_dados()


def emprestar(codigo, aluno):
    codigo = codigo.strip().upper()
    item = equipamentos.get(codigo)

    if item is None:
        return "Equipamento não encontrado."
    if not item["disponivel"]:
        return "Equipamento indisponível."

    item["disponivel"] = False
    item["emprestado_para"] = aluno
    return f'{item["nome"]} emprestado para {aluno}.'


def devolver(codigo):
    codigo = codigo.strip().upper()
    item = equipamentos.get(codigo)

    if item is None:
        return "Equipamento não encontrado."
    if item["disponivel"]:
        return "Este equipamento já está disponível."

    item["disponivel"] = True
    item["emprestado_para"] = None
    return f'{item["nome"]} devolvido com sucesso.'


acao = input("Digite E para emprestar ou D para devolver: ").strip().upper()
codigo = input("Código do equipamento: ")

if acao == "E":
    aluno = input("Nome do aluno: ")

elif acao == "D":
    resultado = devolver(codigo)
else:
    resultado = "Opção inválida."

if acao in ("E", "D"):
    salvar_dados(equipamentos)

Checkpoint 3 — projeto preparado para testes

Seu emprestimos.py já é o mostrado na etapa anterior. O app.py deve ficar responsável pela interação e pela persistência:

import json
from pathlib import Path

from emprestimos import criar_dados_iniciais, emprestar, devolver

ARQUIVO_DADOS = Path("dados/equipamentos.json")


def carregar_dados():
    if not ARQUIVO_DADOS.exists():
        return criar_dados_iniciais()

    with ARQUIVO_DADOS.open("r", encoding="utf-8") as arquivo:
        return json.load(arquivo)


def salvar_dados(dados):
    ARQUIVO_DADOS.parent.mkdir(parents=True, exist_ok=True)

    with ARQUIVO_DADOS.open("w", encoding="utf-8") as arquivo:
        json.dump(dados, arquivo, ensure_ascii=False, indent=2)


dados = carregar_dados()
acao = input("Digite E para emprestar ou D para devolver: ").strip().upper()
codigo = input("Código do equipamento: ")

if acao == "E":
    aluno = input("Nome do aluno: ")
    resultado = emprestar(dados, codigo, aluno)
elif acao == "D":
    resultado = devolver(dados, codigo)
else:
    resultado = "Opção inválida."

if acao in ("E", "D"):
    salvar_dados(dados)

print(resultado)

PARE E CONFIRA

Neste ponto: emprestimos.py contém regras; app.py contém interface e persistência; test_emprestimos.py protege comportamentos já aprovados. Execute os testes mais uma vez antes de seguir.

12. “Na minha máquina funciona” — ambiente também faz parte do projeto

LEIA — situação simulada

Você não precisa trocar de computador para continuar a aula. Imagine que um colega copie a pasta e, ao executar os testes, receba:

ModuleNotFoundError: No module named 'pytest'

A regra de empréstimo não ficou errada. O novo ambiente ainda não possui a dependência usada para executar os testes.

PROMPT PARA A IA — diagnostique o ambiente

Os testes rodam em outro computador, mas neste laboratório Python 3.12 informa ModuleNotFoundError: No module named 'pytest'. Antes de mandar instalar qualquer coisa, explique o que preciso verificar sobre interpretador selecionado, ambiente virtual, instalação do pacote e registro de dependências do projeto.

FAÇA AGORA — registre a dependência

Como você criou um ambiente virtual controlado para este projeto, gere o arquivo:

python -m pip freeze > requirements.txt

PARE E CONFIRA

Abra requirements.txt e confirme que o pytest e suas dependências aparecem. O objetivo é tornar o ambiente reproduzível, não apenas “funcionar na sua máquina”.

13. O projeto agora contém dados de pessoas — nem todo contexto deve ir para a IA

LEIA — nenhuma alteração de código nesta etapa

Os testes da turma começam a usar nomes reais e alguém pensa em enviar o equipamentos.json inteiro para pedir ajuda. A IA não precisa de identidades reais para compreender a regra.

Evite

"emprestado_para": "Nome completo do aluno real"

Prefira

"emprestado_para": "ALUNO_TESTE_01"
  • Use dados fictícios ou anonimizados nos exemplos enviados à IA.
  • Compartilhe apenas os arquivos e trechos necessários para o problema.
  • Se futuramente houver API, nunca envie chaves, tokens ou arquivo .env com valores reais.
  • Se um segredo real for exposto, trate-o como comprometido e siga o procedimento de revogação do serviço.

PARE E CONFIRA

Antes de anexar um arquivo a uma IA, pergunte: “ela realmente precisa destes dados para resolver este problema?”

14. Revise o projeto antes de outra pessoa continuar

FAÇA AGORA — prepare somente o contexto necessário

Use o estado do Checkpoint 3. Envie à IA emprestimos.py, app.py e test_emprestimos.py. Não envie o JSON real se ele contiver nomes.

PROMPT PARA A IA — revisar sem editar

Revise este projeto sem editar ainda. Organize os achados em: - CORREÇÃO: comportamento que pode estar errado; - LEGIBILIDADE: algo que dificulta entender; - DUPLICAÇÃO: lógica repetida que aumenta risco de inconsistência; - TRATAMENTO DE ERROS: falhas que hoje não têm resposta adequada; - TESTABILIDADE: pontos difíceis de isolar ou testar. Para cada achado, cite o arquivo e o trecho. Não proponha mudanças apenas cosméticas.

FAÇA AGORA

Escolha uma única melhoria que tenha justificativa concreta. Faça uma alteração pequena e execute novamente todos os testes existentes.

PARE E CONFIRA

Se um comportamento mudou sem intenção, não foi apenas refatoração. Reverta ou investigue antes de continuar.

15. Uma IA com acesso ao repositório pode agir — e por isso exige mais controle

Até aqui você poderia copiar trechos para um chatbot. Agora imagine um agente conectado ao projeto, capaz de localizar arquivos, editá-los e executar testes.

LEIA — dois termos

Branch é uma linha separada de trabalho: permite experimentar uma mudança sem alterar diretamente a versão principal.

Diff é a comparação que mostra exatamente o que foi adicionado, removido ou alterado. Para aprofundar, consulte Git/GitHub.

Novo pedido do laboratório

Além de emprestar e devolver, o sistema deve permitir reservar um equipamento disponível para uma aula futura. A reserva não pode marcar o equipamento como emprestado e deve poder ser cancelada.

FAÇA AGORA — antes de autorizar qualquer edição

  1. Crie ou selecione uma branch separada.
  2. Peça apenas o plano.
  3. Revise os arquivos que o agente pretende alterar.
  4. Só depois autorize implementação.
  5. Leia o diff e execute testes antigos e novos.

PROMPT PARA O AGENTE

Antes de editar, analise o projeto e liste quais arquivos precisam mudar para implementar reserva e cancelamento de reserva. Explique por quê. Não altere nada ainda. Depois da minha aprovação, faça somente as mudanças necessárias. Preserve empréstimo, devolução e persistência existentes. Acrescente testes para as novas regras e execute também os testes antigos. Ao final, mostre resumo do diff, testes executados, riscos restantes e qualquer decisão de requisito que ainda precise de resposta humana.

PARE E CONFIRA

Não aceite “concluído” como evidência. A evidência é: escopo compreendido, diff revisado e testes executados.

16. Laboratório final — implemente a reserva sem terceirizar a decisão

Agora você assume o fluxo completo. Cada etapa produz algo que precisa ser entendido antes da próxima.

Etapa A — escreva as regras antes da IA

FAÇA AGORA: escreva com suas palavras quando uma reserva pode ser criada, o que acontece se o equipamento já estiver emprestado ou reservado e como uma reserva é cancelada. Pare aqui antes da Etapa B.

Etapa B — peça perguntas sobre lacunas

Estas são minhas regras de reserva. Antes de propor código, identifique no máximo cinco decisões que ainda estejam ambíguas e que possam alterar a implementação. Não invente respostas para elas.

PARE E CONFIRA: responda você mesmo às ambiguidades relevantes. A IA não decide a regra do laboratório.

Etapa C — transforme regras em testes

FAÇA AGORA: registre pelo menos reservar disponível, impedir segunda reserva, impedir reserva de emprestado, cancelar reserva e comprovar que empréstimo/devolução continuam funcionando.

Etapa D — planeje a alteração

Com base apenas nas regras aprovadas e no projeto atual, liste arquivos e funções que precisam mudar. Preserve o restante. Não escreva código ainda.

PARE E CONFIRA: cada arquivo listado precisa ter uma justificativa ligada a uma regra.

Etapa E — implemente pouco e revise o diff

FAÇA AGORA: autorize a implementação apenas depois de entender o plano. Compare antes/depois e procure requisito novo que ninguém pediu.

Etapa F — execute os testes e investigue qualquer falha

FAÇA AGORA: rode os testes antigos e novos. Se houver falha, primeiro descubra qual regra, teste ou implementação está errada. Não peça simplesmente para “fazer passar”.

Etapa G — explique sem a IA

FAÇA AGORA: feche a conversa e responda: quais arquivos mudaram, qual estado representa uma reserva, como ela é cancelada e quais testes comprovam que as regras antigas continuam válidas?

Critério de conclusão

Você não terminou quando a ferramenta escreveu o código. Terminou quando consegue defender a mudança com requisitos, diff, testes e explicação própria.

Escolha um programa pequeno que você realmente consiga executar — em Python, JavaScript, Java, VisuAlg ou outra linguagem estudada. Não copie o projeto do laboratório; transfira o método.

  1. Explique o comportamento atual sem IA.
