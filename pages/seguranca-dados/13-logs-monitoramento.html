O problema aconteceu de madrugada. Quem viu?

Sistemas podem registrar eventos enquanto ninguém está olhando. Esses registros ajudam a reconstruir o que ocorreu.

Logs, logging, monitoramento e alerta

Log é um registro de evento. Logging é o processo de gerar esses registros. Monitoramento acompanha o ambiente; um alerta chama atenção quando determinada condição merece ação.

Horários coerentes são essenciais para relacionar eventos de máquinas diferentes. Por isso, sincronização de tempo e proteção dos próprios logs também importam.

Prática orientada — observar consultas no MySQL

Use somente um MySQL de laboratório

O general query log pode registrar grande volume de informações, incluir conteúdo presente nas consultas e produzir impacto operacional. Não ative esse recurso em um servidor de produção para esta atividade.

Roteiro pronto

Baixar mysql-general-log-lab.sql →

A conta usada no laboratório precisa ter permissão para alterar variáveis globais. Se você não tiver esse ambiente, acompanhe o roteiro como demonstração orientada.

O que cada etapa faz

  1. Confira se o general_log está ligado ou desligado.
  2. Defina temporariamente a saída como tabela, para facilitar a observação didática.
  3. Ative o general_log.
  4. Execute duas consultas de teste conhecidas.
  5. Consulte registros recentes na tabela mysql.general_log.
  6. Relacione horário, usuário, tipo de comando e consulta registrada.
  7. Desative o general query log.
  8. Confirme que ele realmente ficou desligado.

Os comandos do laboratório

SHOW VARIABLES LIKE 'general_log';
SHOW VARIABLES LIKE 'log_output';

SET GLOBAL log_output = 'TABLE';
SET GLOBAL general_log = 'ON';

SELECT NOW();
SELECT 'Mundo bit Byte' AS origem;

SELECT event_time, user_host, command_type, argument
FROM mysql.general_log
ORDER BY event_time DESC
LIMIT 20;

SET GLOBAL general_log = 'OFF';
SHOW VARIABLES LIKE 'general_log';

O que precisa ficar comprovado

As ações executadas durante o laboratório deixam registros que podem ser relacionados ao horário e ao usuário. Ao final, o valor de general_log deve voltar a indicar que o recurso está desligado.

Registrar não basta

Um log que ninguém revisa pode não produzir ação. E um log que pode ser alterado pelo mesmo usuário investigado perde parte de seu valor como evidência.
