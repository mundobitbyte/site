Etapa 11

E se o servidor parar?

Diferencie recuperação de dados de continuidade do serviço.

Temos backup. Mesmo assim, o sistema está parado.

Restaurar dados pode levar tempo. Se o serviço não pode esperar, precisamos discutir disponibilidade e evitar um único componente capaz de interromper tudo.

Ponto único de falha e redundância

Um Single Point of Failure — SPOF, ou ponto único de falha, é um componente cuja indisponibilidade pode interromper o serviço inteiro. Redundância adiciona componentes ou caminhos para reduzir essa dependência.

Replicação

Em banco de dados, uma configuração pode manter um servidor principal e uma réplica. No MySQL, encontramos a relação source/replica. Alterações do source são enviadas à réplica, podendo existir algum atraso de replicação.

source→replicação→replica

Failover é a mudança do serviço para outro componente quando o principal falha. Ele pode ser manual ou automatizado, conforme a arquitetura.

Replicação não é backup

Uma exclusão indevida também pode ser replicada. Backup e replicação atendem necessidades diferentes e podem coexistir.

Prática orientada

Desenhe uma arquitetura mínima com servidor principal, réplica e backup separado. Para cada elemento, escreva qual problema ele tenta reduzir: perda de dados, tempo de indisponibilidade ou ambos.

A configuração completa de replicação fica como laboratório orientado; não é pré-requisito para compreender o módulo sozinho.
