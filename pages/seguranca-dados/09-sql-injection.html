Etapa 9

Quando aquilo que digitamos vira parte de um comando

Entenda por que dados do usuário não devem alterar a estrutura de comandos SQL.

O campo deveria receber um nome. Mas o programa monta um comando com ele.

Na Conecta Serviços, uma busca de clientes recebe texto do usuário. Se esse texto for concatenado diretamente à instrução SQL, dado e comando deixam de estar claramente separados.

SQL e a separação entre comando e dado

SQL — Structured Query Language é usada em bancos relacionais. Uma consulta normal pode ser:

SELECT * FROM clientes WHERE nome = 'Ana';

A estrutura da consulta é uma coisa. Ana é o valor procurado.

Onde nasce a vulnerabilidade

nome = input("Digite o nome: ")
sql = "SELECT * FROM clientes WHERE nome = '" + nome + "'"

O programa mistura parte fixa do comando com texto recebido. Dependendo da entrada, isso pode alterar a estrutura interpretada pelo banco. Essa classe de problema é chamada de SQL Injection, ou injeção de SQL.

Ideia central

Entrada do usuário é dado. Dado não deve ganhar o poder de modificar a estrutura do comando.

Laboratório apenas local e autorizado

Use somente o ambiente didático fornecido para o módulo. Primeiro faça uma busca normal e observe a consulta construída. Depois compare a versão vulnerável com uma consulta parametrizada:

cursor.execute(
    "SELECT * FROM clientes WHERE nome = ?",
    (nome,)
)

A sintaxe do marcador varia conforme linguagem e driver. O princípio é manter a estrutura da consulta separada dos valores.

Prepared statement

Uma prepared statement, ou instrução preparada, mantém a estrutura do comando separada dos valores utilizados. Não é equivalente a simplesmente apagar aspas ou criar uma lista improvisada de “caracteres perigosos”.

A seguir: se os dados forem perdidos, conseguimos recuperá-los?

Mesmo um sistema bem construído pode sofrer falhas, exclusões, defeitos ou ataques. Precisamos pensar em recuperação.
