# Programação de Computadores — Mapa e Auditoria MbB

## Escopo curricular consolidado

Este módulo passa a usar três referências curriculares de programação como auditoria conjunta:

1. **Informática — I.12 Programação de Computadores**: formação conceitual, algoritmo, pseudocódigo, fluxograma, sequência, variáveis, constantes, operadores, entrada/processamento/saída, funções predefinidas, decisão, repetição, ambiente, bibliotecas, programação estruturada, orientada a eventos e orientação a objetos, com desenvolvimento de aplicações.
2. **Desenvolvimento de Sistemas — Técnicas de Programação e Algoritmos**: acrescenta teste de mesa, código-fonte/objeto/executável, conversões, exceções, tabela verdade, recursos de IDE, build/deploy, modularização, vetores/matrizes, depuração detalhada, versionamento, estilo, programação em par e testes unitários.
3. **Desenvolvimento de Sistemas — Programação e Algoritmos (plano mais recente)**: acrescenta/explicita estruturas compostas (matrizes, listas, dicionários, tuplas, conjuntos), classes e objetos, depuração, gerenciamento de pacotes e controle de versão distribuído completo.

A carga horária específica de cada plano **não limita a organização deste material consolidado**. O objetivo é não omitir conteúdos relevantes das disciplinas de programação e permitir ao professor adequar profundidade e ritmo à turma.

## Princípios pedagógicos preservados

- **necessidade → ideia → nome técnico → sintaxe**;
- **Saber → Fazer → Responder** como modelo mental inicial;
- **Entender → Experimentar → Programar → Aplicar**;
- conceitos surgem porque o problema os exige;
- VisuAlg funciona como primeira ponte executável;
- Python faz transferência de conceitos, não reinicia o curso;
- Cantina continua como sistema guiado/integrador;
- Estacionamento continua como problema de transferência;
- explicação simples no primeiro contato **não significa conteúdo superficial**: depois do entendimento inicial, o conceito é aprofundado tecnicamente;
- nenhum conteúdo curricular é forçado artificialmente dentro da Cantina; quando necessário, usa-se um problema próprio e autêntico;
- Git/GitHub continua como módulo especializado do Mundo bit Byte, mas o módulo Programação explica sua necessidade e cobre o mapa conceitual/terminológico exigido pelos planos antes de encaminhar para a prática completa.

## Profundidade — regra nova

Cada conceito importante deve, quando aplicável, passar pelas seguintes camadas:

1. necessidade que faz o conceito aparecer;
2. explicação simples e intuitiva;
3. nome técnico e definição mais precisa;
4. sintaxe/ferramenta;
5. exemplo acompanhado;
6. funcionamento interno ou consequência importante;
7. erros comuns e limites;
8. prática;
9. reaparecimento em problema mais rico;
10. transferência entre VisuAlg/Python ou para ferramenta especializada.

Não é obrigatório exibir artificialmente dez subtítulos em toda aula; é uma régua de auditoria de profundidade.

## Bit e Byte — precisão

- 1 byte = 8 bits.
- 16 bits = 2 bytes; 32 bits = 4 bytes; 64 bits = 8 bytes.
- Não afirmar que `inteiro`, `real`, `lógico` ou outro tipo possui universalmente um tamanho fixo.
- Tamanho e representação dependem de linguagem, implementação, runtime e plataforma.
- Um padrão binário só ganha significado quando interpretado segundo uma representação/codificação.
- Em texto, um caractere não corresponde necessariamente a um byte.

- lista os grupos de operações curriculares;
- diferencia Git de GitHub;
- apresenta README/Markdown;
- reforça uso de CLI para visualizar conceitos;
- encaminha o projeto real ao módulo Git/GitHub já existente.

A prática detalhada permanece centralizada no módulo especializado para evitar duplicação.
